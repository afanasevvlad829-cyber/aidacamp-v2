# Yandex Direct — основы для агентов

> ⚠️ **Для агентов**: правила работы, которые считаются само-собой разумеющимися. Читать ПЕРЕД вопросами к владельцу. Если ответа тут нет — смотри официальную документацию, только потом спрашивай.

Проект: **aidacamp.ru** — детский IT-лагерь в Подмосковье. Продукт — путёвки на смены (сезонность: зима, весна, лето, осень). Ниша: education / children / events.

## 1. Типы кампаний Директа

| Тип (API / UI) | Где показывается | Цель | Когда использовать |
|---|---|---|---|
| **TEXT_CAMPAIGN (Поиск)** | Результаты поиска Яндекса + партнёры поиска | Горячий спрос, люди уже ищут | Ядро семантики: «купить путёвку в лагерь», «детский лагерь подмосковье» |
| **TEXT_CAMPAIGN (РСЯ)** | Сайты-партнёры Рекламной Сети Яндекса + внешние сети | Охват, возврат, тёплый спрос | Широкие ключи, интересы, ретаргет на look-alike |
| **TEXT_CAMPAIGN (Ретаргет / Retargeting)** | РСЯ + главная Яндекса | Догнать тех, кто был на сайте | Брошенные корзины, посетители LP без заявки |
| **DYNAMIC_TEXT_CAMPAIGN (Динамические)** | Поиск | Авто-генерация объявлений по фиду/сайту | Для больших каталогов (у нас — нет) |
| **MCBANNER_CAMPAIGN (Баннер на поиске)** | Справа от выдачи | Охват + брендинг | Дорого, имиджевая история |
| **CPM_BANNER_CAMPAIGN** | Медийная РСЯ | Оплата за показы, не клики | Охват по широким аудиториям |
| **SMART_CAMPAIGN (Мастер кампаний, МК)** | Поиск + РСЯ автоматически | Упрощённый интерфейс, всё на автомате | Быстрый старт, но меньше контроля |
| **UNIFIED_CAMPAIGN (ЕПК — Единая Перформанс-Кампания)** | Поиск + РСЯ + Товарные | Максимум автоматизации + контроль | **Новый формат, постепенно замещает классику** |
| **CPC_VIDEO_CAMPAIGN** | Видео-реклама в сети | Видео-креатив | Нет, если нет роликов |

**Важно**: с 2024–2025 Яндекс форсирует переход на ЕПК (Единую Перформанс-Кампанию). В ЕПК поиск и РСЯ объединены в одной кампании — и там правила для минус-площадок **отличаются от классического Поиска**.

Источник: https://yandex.ru/support/direct/ru/

## 2. Структура

```
Клиент (Account)
└── Кампания (Campaign)      ← бюджет, стратегия, гео, расписание
    └── Группа (AdGroup)     ← ключи/аудитории, таргетинги, ставки
        └── Объявление (Ad)  ← текст, заголовок, картинки, UTM
        └── Ключевые фразы (Keyword) / Аудитории / Ретаргеты
```

**Зона ответственности**:
- **Кампания**: стратегия, бюджет, гео, минус-слова **кампанейского уровня** (CampaignLevelNegativeKeywords), ExcludedSites, минус-площадки, BidModifiers.
- **Группа**: объединяет похожие ключи/объявления; здесь задаются таргетинги (аудитории, ретаргетинги, ключи).
- **Объявление**: текст, быстрые ссылки, уточнения, картинки, видео.
- **Ключ**: фраза + ставка (если стратегия ручная) + статус.

Правило: **в одной группе — однотипные ключи и одно-два объявления для A/B**. Разнотипные ключи дают мусор в статистике.

## 3. Стратегии

| Стратегия (API) | Что делает | Когда использовать | Подводные камни |
|---|---|---|---|
| `HIGHEST_POSITION` (ручные ставки на поиске) | Ты сам ставишь CPC | Опытный специалист, мало конверсий для авто | Устарела, Яндекс пушит автостратегии |
| `WB_MAXIMUM_CLICKS` | Максимум кликов в рамках бюджета | Охватный тест, верх воронки | Даёт много мусора, нет фокуса на CPA |
| `WB_MAXIMUM_CONVERSIONS` (Оплата за клики, цель по конверсиям) | Макс. конверсий в рамках бюджета + targetCPA | Когда конверсий достаточно (10+/нед) | Нужна корректная цель в Метрике |
| `AVERAGE_CPC` | Средняя цена клика | Когда цена клика важнее, чем CPA | Не оптимизирует под конверсии |
| `AVERAGE_CPA` | Средняя цена конверсии | Стабильный поток конверсий | Нужно 10+ конв/нед |
| `PAY_FOR_CONVERSION` (Оплата за конверсии) | **Платишь только за конверсию**, клики бесплатны | Хорошо работает, когда CPA стабильный | См. раздел 6 — главный источник факапов |
| `CP_*` (серия) | Разные вариации оплаты за клик/конверсию с разными приоритетами | По ситуации | См. официальную таблицу |

**Правило**: если конверсий < 10/нед на кампанию — автостратегии по конверсиям **не будут обучаться корректно**. Используй `WB_MAXIMUM_CLICKS` или ручку, накопи данные, потом переключайся.

Источник: https://yandex.ru/support/direct/ru/features/strategies.html

## 4. Пакетные стратегии

**Пакетная стратегия** — когда одна стратегия применяется к **нескольким кампаниям сразу**. Это нужно, чтобы алгоритм учился на суммарных данных (а не по каждой кампании отдельно).

Правила:
- Обучение требует **10+ конверсий в неделю на пакет** (не на кампанию).
- В пакет можно добавлять кампании **совместимых типов** (нельзя миксовать ЕПК и классические поисковые, нельзя миксовать PAY_FOR_CONVERSION с обычными).
- **Бюджет задаётся на пакет**, а не на каждую кампанию отдельно — при неправильной настройке одна кампания может съесть весь бюджет пакета.
- **WSL-кампании (с ручными ставками уровня группы/фразы)** могут игнорироваться бюджетом пакетной стратегии или вести себя нестандартно — реальный кейс, который мы ловили. Если у кампании стоят ставки вручную на уровне фраз, а она в пакете с автостратегией — **эти ставки игнорируются** алгоритмом пакета.
- Нельзя просто так выдернуть кампанию из пакета — обучение сбросится.

**Как не сломать**:
1. Не мешай пакету 2 недели после запуска (только если полный провал).
2. Не меняй цели в Метрике внутри обучения.
3. Не режь бюджет больше чем на 20% за раз.
4. Прежде чем добавить кампанию в пакет — убедись, что её тип и стратегия совместимы.

Источник: https://yandex.ru/support/direct/ru/features/package-strategies.html

## 5. Минус-слова vs Минус-площадки — КРИТИЧЕСКИ ВАЖНО

Это самая частая путаница у агентов. Запоминай:

| | Минус-слова (Negative Keywords) | Минус-площадки (Excluded Sites) |
|---|---|---|
| **Где работают** | Везде: Поиск, РСЯ, Ретаргет, ЕПК | **Только РСЯ и Ретаргет**. В Поиске — **НЕ работают физически** |
| **Что исключают** | Поисковые фразы пользователя | Сайты-площадки РСЯ, где показывается реклама |
| **Где задаются** | Уровень кампании (`CampaignLevelNegativeKeywords`) и уровень группы/фразы | Уровень кампании (`ExcludedSites`) |
| **Лимит** | 4096 символов на кампанию | **~1000 площадок на кампанию** |

### ❓ Почему минус-площадок нет в поисковых кампаниях?

**Потому что поиск — это только выдача Яндекса (yandex.ru) и сайты-партнёры поиска, контролируемые Яндексом.** Там нет «площадок» в том смысле, как в РСЯ. Исключать `yandex.ru` из поисковой кампании бессмысленно — это и есть основной источник.

**Для агентов**: если видишь поисковую кампанию без минус-площадок — **это нормально и так должно быть**. Не спрашивай владельца. Если нужно исключить партнёров поиска — это делается через галочку «Показывать только на Яндексе» в настройках кампании, а не через список минус-площадок.

Источник: https://yandex.ru/support/direct/ru/keywords/negative-keywords.html, https://yandex.ru/support/direct/ru/features/site-exclusion.html

## 6. PAY_FOR_CONVERSION — особенности и капканы

Стратегия оплаты за конверсию — деньги списываются **только когда выполнена целевая конверсия** (заявка, звонок, покупка). Клики бесплатные.

### Требования для обучения
- **Минимум 10 конверсий в неделю** на кампанию (или пакет).
- Цель в Метрике должна быть **корректно настроена** и стрелять стабильно.
- CPA (targetCPA) должен быть **реалистичным** — если поставить 100₽ при реальном CPA 800₽, алгоритм не поедет.

### 💥 Сценарий «заморозки» (реальный инцидент)
Если кампания получает **0 конверсий за 48–72 часа**:
1. Алгоритм считает, что CPA недостижим.
2. Кампания перестаёт показываться вовсе (или показывается крайне мало).
3. Визуально выглядит как «открутка остановилась».

**Как разморозить**:
1. **Повысить targetCPA** на 30–50% (даёт алгоритму «воздух»).
2. Если не помогает — **дублировать кампанию** (новая = новое обучение с нуля, иногда идёт лучше).
3. Проверить, **не сломалась ли цель в Метрике** (реальный кейс: Partytown блокировал загрузку `ym()` → конверсии не доходили → алгоритм решил, что CPA недостижим → кампания встала).
4. Проверить, что в Метрике цель не была переименована / не сменила ID — Директ ссылается по ID.

### Правила гигиены
- Не меняй targetCPA чаще раза в неделю.
- Не меняй цель в процессе обучения.
- Не режь бюджет в обучении.
- Минимальный бюджет для PAY_FOR_CONVERSION обычно = `targetCPA × 10`/неделю.

Источник: https://yandex.ru/support/direct/ru/features/pay-for-conversion.html

## 8. Частые ошибки и реальные инциденты на проекте

### 8.1. Partytown блокировал `ym()` — PAY_FOR_CONVERSION встала
**Что было**: на сайте подключили Partytown (вынос скриптов в worker для ускорения Core Web Vitals). Метрика начала отдавать события, но `ym('reachGoal', …)` частично не доставлялся. Конверсии в Директе упали в 3 раза → PAY_FOR_CONVERSION решил, что CPA недостижим → кампания заморозилась.
**Урок**: при любых манипуляциях с тегом Метрики (GTM, Partytown, CSP) — **сначала тест на стейдже через Вебвизор/Отладчик Метрики**, потом прод.

### 8.2. Пакетная стратегия «съела» WSL-кампанию
**Что было**: добавили кампанию с ручными ставками на уровне фраз в пакет с автостратегией. Ставки игнорировались. Кампания открутила бюджет на фразах, которые давно минусовали на уровне группы.
**Урок**: не мешай WSL-кампании с автоматическими пакетами. Либо всё вручную, либо всё в пакете.

### 8.3. Агент спрашивал «почему в поисковой нет минус-площадок»
**Что было**: агент не знал базы.
**Урок**: см. раздел 5. Минус-площадок в поисковой быть не должно.

### 8.4. Цель в Метрике переименовали — Директ не увидел
**Что было**: переименовали цель, думая, что Директ подхватит по имени. Директ ссылается по **числовому ID**, имя игнорирует. Но если удалить и пересоздать цель — появится новый ID, и Директ потеряет её.
**Урок**: при работе с целями — менять только название, не удалять.

### 8.5. Ретаргет без свежего сегмента
**Что было**: ретаргет-кампания показывалась тем, кто был на сайте год назад. CTR 0.1%, конверсии 0.
**Урок**: сегменты Метрики для ретаргета — «посетители за 30/60/90 дней», не «за всё время».

## 9. Специфика aidacamp.ru

- **Сезонность**: пики спроса за 2–4 мес до смены (март–май для лета, сентябрь–октябрь для осенних, ноябрь для НГ-смен).
- **Гео**: Москва и МО — ядро. ЦФО — дополнительно. Регионы — только если явно есть спрос (родители выбирают лагерь близко).
- **ЦА**: родители 30–55, чаще мамы. Корректировки по полу: женщины +20–30%.
- **Устройства**: mobile доминирует (70%+), но заявки часто идут с desktop. Не режь mobile.
- **Период бронирования**: длинный (смотрят сайт по 3–7 раз перед заявкой) → ретаргет критичен.
- **Конкурентная среда**: много мелких лагерей + федералы. По ВЧ «детский лагерь» — дорого, идти в СЧ/НЧ («IT-лагерь подмосковье», «лагерь с программированием для детей»).
