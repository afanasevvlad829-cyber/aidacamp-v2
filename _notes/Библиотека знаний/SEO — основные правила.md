# SEO — основные правила (Google + Яндекс)

> Библиотека базовых знаний для агентов и маркетологов проекта **aidacamp.ru** (детский IT-лагерь в Подмосковье). Цель файла — чтобы любой, кто садится работать с сайтом, понимал фундамент и не задавал очевидных вопросов.
>
> **📌 Это живой документ.** Любой инсайт из наших аудитов и инцидентов фиксируем в разделе «Best practices из нашего опыта» с датой и ссылкой на контекст. Если встретил неочевидный факт из официальной доки — добавляй в релевантный раздел со ссылкой.

## Что такое SEO и зачем

SEO (Search Engine Optimization) — комплекс работ, который делает сайт видимым в органической (бесплатной) выдаче поисковиков. Для aidacamp это главный источник долгосрочного, «бесплатного» трафика: пока платная реклама требует непрерывных денег, хорошо проиндексированная страница «Компьютерный лагерь в Подмосковье» может годами приводить мам, ищущих смену для ребёнка. SEO работает медленно (первые результаты — 3–6 месяцев), но накапливается и удешевляет каждый следующий лид.

## Два поисковика в России

- **Google** (~40% рынка в России после 2022) + Bing + DuckDuckGo — строго технические сигналы, Core Web Vitals, E-E-A-T, ссылки.
- **Яндекс** (~60%) + Mail.ru + Rambler — сильный поведенческий фактор, локальная выдача (Яндекс.Карты, Бизнес), ИКС, региональность.

Работать надо **параллельно под оба**: один и тот же сайт, один контент, но настройки (sitemap, robots, микроразметка, карточки) отправляются в оба вебмастера. Игнорировать один из них = терять до половины потенциального трафика.

## Три слоя SEO

1. **Технический SEO** — доступность, скорость, индексация, код, сервер.
2. **On-page** — контент, заголовки, микроразметка, внутренние ссылки, UX.
3. **Off-page** — ссылочное, упоминания, PR, отзывы, карты, соцсигналы.

Если сломан технический слой — on-page и off-page бесполезны: поисковик просто не увидит страницу.

## Технический SEO — базовый чек-лист

- **robots.txt** — синтаксис: `User-agent:`, `Disallow:`, `Allow:`, `Sitemap:`, `Clean-param:` (Яндекс-специфично, см. ниже).
- **sitemap.xml** — лимиты: **50 000 URL** и **50 МБ** несжатого файла на один sitemap. Если больше — делим и собираем **sitemap-index**. [Google Docs](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- **canonical-теги** (`<link rel="canonical">`) — решают дубли (пример aidacamp: `/smena-letniy-lager?utm_source=yandex` → canonical на `/smena-letniy-lager`).
- **hreflang** — для многоязычных сайтов. У aidacamp только русский, не актуально.
- **HTTPS** обязательно — без него Google понижает, Chrome пугает замком.
- **Мобильная адаптация** — Google использует **Mobile-First Indexing** (индексирует мобильную версию как основную); Яндекс учитывает адаптивность и наличие мобильной вёрстки.
- **Core Web Vitals** (пороги 75-го процентиля, [web.dev/vitals](https://web.dev/articles/vitals)):
  - **LCP** (Largest Contentful Paint) — **< 2.5 с** (хорошо).
  - **INP** (Interaction to Next Paint) — **< 200 мс** (хорошо). С марта 2024 INP заменил FID как основную метрику интерактивности.
  - **CLS** (Cumulative Layout Shift) — **< 0.1** (хорошо).
- **Структурированные данные** — Schema.org в формате JSON-LD (см. ниже).
- **301 редиректы** — для постоянных переездов страниц. Никогда не 302 для постоянного (302 = временно, не передаёт вес).
- **Отсутствие цепочек редиректов** — `A → B → C` плохо; делаем `A → C` напрямую.

## On-page — ключевые сигналы

- **Title tag** — до **60 символов**, уникальный, содержит главный ключ. Пример: `Компьютерный лагерь в Подмосковье 2026 — АйДаКемп`.
- **Meta description** — до **160 символов** (Google), до ~250 (Яндекс может показывать длиннее). Не дублировать между страницами.
- **H1** — один на страницу, содержит главный ключ.
- **H2–H3** — структура разделов, вложенность логичная.
- **URL** — ЧПУ, короткие, транслитом или латиницей (`/kompyuternyy-lager/`, не `/page?id=7`).
- **Плотность ключей** — не переспамить, ориентир 1–3% на страницу. Лучше писать естественно и покрывать LSI, чем считать проценты.
- **LSI (семантика)** — синонимы и родственные термины: «лагерь», «смена», «программа», «Подмосковье», «дети», «программирование», «каникулы».
- **Внутренние ссылки** — перелинковка между страницами смен, блогом, главной, FAQ.
- **Alt у картинок** — описывает содержимое для поиска по картинкам и доступности.
- **E-E-A-T** (Experience, Expertise, Authoritativeness, Trustworthiness) — Google Quality Rater Guidelines. Для детского лагеря критичны: страница «О нас», фото педагогов с описанием опыта, лицензии, сертификаты, реальные отзывы с именами.

## Микроразметка Schema.org (JSON-LD)

Основные типы для коммерческого сайта:
- **Organization / LocalBusiness** — карточка компании. Для aidacamp — LocalBusiness с адресом и часами работы офиса.
- **BreadcrumbList** — навигационные «хлебные крошки» в выдаче.
- **FAQPage** — FAQ-блоки попадают в расширенный сниппет Google.
- **Product + Offer** — товары/услуги. Можно использовать для описания смены как услуги с ценой.
- **Review + AggregateRating** — отзывы и средняя оценка. Звёздочки в сниппете = +CTR.
- **Event** — мероприятия: смены лагеря с датами заезда и выезда, локацией.
- **VideoObject** — для видеороликов на сайте.

**Рекомендация для aidacamp:** `LocalBusiness` (главная + контакты) + `Event` (каждая смена как отдельное событие с `startDate`, `endDate`, `location`, `offers`) + `Review`/`AggregateRating` (отзывы родителей) + `FAQPage` (частые вопросы о смене). Валидировать через [Rich Results Test](https://search.google.com/test/rich-results) и Яндекс.Вебмастер → Инструменты → Валидатор микроразметки.

Schema.org справочник: [schema.org/docs/full.html](https://schema.org/docs/full.html)

## Off-page

- **Ссылочное** — качество > количества. Смотрим DR (Ahrefs) / ИКС (Яндекс) донора, тематику (детские / родительские / образовательные сайты лучше всего), естественность анкоров (не «купить компьютерный лагерь» 100 раз подряд).
- **Карточки в сервисах:**
  - Яндекс Бизнес (обязательно — влияет на локальное ранжирование в Яндексе)
  - Google Business Profile
  - 2GIS
  - Яндекс Карты (связан с Яндекс Бизнес)
- **Отзывы** — критичны для коммерции. Основные отзовики для aidacamp: **Яндекс Карты, Google Maps, 2GIS, otzovik.com, irecommend.ru**. Просить родителей оставить отзыв после смены = часть воронки.
- **Упоминания бренда без ссылок** — Яндекс учитывает как сигнал (внутренний фактор «bastion» 🤔 — название из индустриальных источников, в официальной доке Яндекса формулировка другая).

## Яндекс-специфика

- **ИКС (Индекс качества сайта)** — публичная метрика Яндекса, примерный аналог PageRank. Показывается в Вебмастере и сниппетах Яндекс.Бизнес. Считается по комплексу факторов: размер аудитории, удовлетворённость пользователей, доверие. Точная формула закрыта 🤔.
- **Яндекс.Вебмастер** ([yandex.ru/support/webmaster](https://yandex.ru/support/webmaster/)) — основной инструмент: отчёты по запросам, индексация, sitemap, Turbo-страницы, региональность, Валидатор микроразметки.
- **Яндекс.Метрика** — формально отдельный продукт, но фактически влияет на ранжирование через поведенческие (отказы, глубина, время на сайте). Для aidacamp установлена, счётчик работает.
- **Регион сайта** — задаётся в Вебмастере (Москва / Московская область для aidacamp). Без указанного региона локальные запросы типа «лагерь в Подмосковье» вообще не ранжируются корректно.
- **Clean-param в robots.txt** — Яндекс-специфичная директива: склеивает дубли с параметрами, говорит роботу «игнорируй этот параметр, это та же страница». [Яндекс Docs](https://yandex.ru/support/webmaster/robot-workings/clean-param.html). Пример:
  ```
  Clean-param: utm_source&utm_medium&utm_campaign&utm_content&utm_term /
  Clean-param: gclid&yclid&ysclid /
  ```
  Яндекс заявляет, что стандартные UTM он склеивает автоматически, но явная директива надёжнее — особенно для `yclid/ysclid/gclid`.
- **Turbo-страницы** — ускоренный мобайл-формат Яндекса (аналог AMP). Для aidacamp 🤔 — не критично, адаптивная вёрстка с хорошим LCP обычно даёт ту же скорость без привязки к формату.
- **Яндекс Бизнес** — карточка для ранжирования по локальным запросам («лагерь рядом со мной», «детский лагерь Химки»).

## Google-специфика

- **Google Search Console (GSC)** ([search.google.com/search-console](https://search.google.com/search-console)) — аналог Вебмастера: отчёт «Покрытие» (Indexed / Discovered / Crawled-not-indexed / Excluded), отчёт «Эффективность» (запросы, CTR, позиции), проверка URL.
- **Mobile-First Indexing** — индексирует мобильную версию как основную. Если на мобильной спрятан блок — для Google его нет.
- **Core Web Vitals** — подтверждённый ранжирующий фактор с 2021 года.
- **Google Business Profile** ([business.google.com](https://business.google.com)) — для локального SEO и Google Maps.
- **Disavow Tool** — отклонение спамных входящих ссылок. Редко нужно; Google сам фильтрует большинство плохих ссылок.

## SXO — Search Experience Optimization

Новая парадигма: Google и Яндекс смотрят не только на on-page, но и на поведение пользователя:
- **CTR в выдаче** — сколько кликнули по твоему сниппету относительно показа.
- **Dwell time** — сколько пробыл на странице после клика.
- **Pogo-sticking** — вернулся ли в выдачу и кликнул следующий результат (плохой сигнал).
- **Bounce rate** — отказы.

Значит **UX, скорость, контент по интенту = часть SEO**. Если мама искала «сколько стоит лагерь», а у нас нет цены на первом экране — она уйдёт, и Яндекс поймёт, что страница не удовлетворяет запрос.

## GEO / AEO (SEO для AI-поиска)

AI-поисковики (Яндекс Нейро, Google AI Overview, ChatGPT, Perplexity, Claude) цитируют источники. Чтобы попадать в AI-ответы:
- Структурированный контент: короткие абзацы, буллеты, таблицы.
- **FAQ-блоки** с чёткими вопросами/ответами.
- Чёткие определения в начале разделов («Компьютерный лагерь — это …»).
- Schema.org разметка (AI-краулеры её читают).
- Citation-friendly: одна мысль = один абзац, легко вырезать.

Для aidacamp перспективно: мамы всё чаще спрашивают Нейро/ChatGPT «посоветуй лагерь для ребёнка 10 лет в Подмосковье». Попасть в цитату = новый канал трафика.

## Семантическое ядро

- **Сбор** — источники ключей:
  - [Wordstat](https://wordstat.yandex.ru) (Яндекс, бесплатно)
  - Google Keyword Planner (через Ads-аккаунт)
  - Serpstat, Ahrefs, SEMrush, DataForSEO (платные, зарубежные)
  - Keys.so, Букварикс, Rush Analytics (российские)
- **Кластеризация по интенту:**
  - **Информационный** — «как выбрать детский лагерь» → блог.
  - **Коммерческий** — «компьютерный лагерь в Подмосковье цена» → посадка на смену.
  - **Транзакционный** — «купить путёвку в IT-лагерь» → форма брони.
  - **Навигационный** — «айдакемп официальный сайт» → главная.
- **Правило: 1 кластер = 1 страница.** Не пытаемся одной страницей закрыть «программирование для детей» и «робототехника для детей» — это разные интенты, нужны две.

## Индексация — частые проблемы

- Страница не в индексе → проверить `site:aidacamp.ru/название-страницы` в Google и Яндексе.
- **GSC** показывает статус: `Indexed` / `Discovered — currently not indexed` / `Crawled — currently not indexed` / `Excluded`.
- **Яндекс.Вебмастер** → «Индексирование» → «Страницы в поиске» / «Исключённые страницы» (с причиной).
- Типичные причины исключения:
  - `noindex` в meta или в HTTP-заголовке `X-Robots-Tag`
  - canonical указывает на другой URL
  - дубли (одна и та же страница по нескольким адресам)
  - низкое качество / тонкий контент (Thin Content)
  - Soft 404 (страница живая, но по сути пустая)
  - блок в `robots.txt`

## Частые ошибки на российских сайтах

- Нет Schema.org вообще или только `Organization` (мало).
- `robots.txt` без `Clean-param` — плодит дубли в индексе Яндекса по UTM/yclid.
- Картинки без alt, без WebP/AVIF (у aidacamp частично есть AVIF — хорошо).
- `H1 = Title` — одно и то же. Title должен быть SEO-формулой с брендом, H1 — человеческим заголовком для посетителя.
- Нет sitemap.xml или он устарел / отдаёт 404.
- Нет региональности в Яндекс.Вебмастере — локальные запросы «проваливаются».
- Мета-описания копируются между страницами (или вообще пустые — Google подставляет случайный кусок текста).
- Нет FAQ-блока на коммерческих страницах — упускаем расширенный сниппет и цитаты в AI.

## Best practices из нашего опыта (aidacamp.ru)

Реальные инциденты и решения. Даты — чтобы понимать, когда факт был проверен эмпирически. Новые инсайты дописываем сверху.

### 🟢 Clean-param решил 11 дубликатов `/it-camp` в Яндекс.Вебмастере (15.04.2026)

**Симптом:** Яндекс.Вебмастер показывал 11 вариаций URL `/it-camp` с разными UTM как дубликаты заголовков.

**Решение:** добавили в `public/robots.txt`:
```
Clean-param: utm_source&utm_medium&utm_campaign&utm_content&utm_term&utm_h1&utm_sub&utm_offer&utm_device&utm_pos&utm_region&yclid&ybaip&sbclid&region_name&perf_run&gclid&fbclid /
```
Через 2–3 апдейта индекса дубли склеились.

**Правило:** на любом сайте с большим объёмом рекламного трафика (Директ, VK Ads, email) **без Clean-param нельзя** — Яндекс плодит дубли и делит вес между UTM-версиями.

### 🟡 Sitemap в Яндекс.Вебмастере нельзя удалить, если его источник = `ROBOTS_TXT` (20.04.2026)

**Симптом:** после того, как мы убрали `sitemap-index.xml` из `robots.txt`, Яндекс.Вебмастер продолжает показывать этот sitemap в списке. Через API удалить невозможно, через UI — тоже (кнопка корзины недоступна).

**Причина:** API-эндпоинт `/user-added-sitemaps` удаляет только sitemap'ы, добавленные пользователем. Если Яндекс нашёл sitemap через `robots.txt` → source = `ROBOTS_TXT` → удалить нельзя никак (ни API, ни UI).

**Решение:** ждать автоматического переобхода `robots.txt`. Обычно 1–7 дней, иногда до 2 недель. Пока `urls_count=0` и `errors_count=0` — ничего не ломает.

**Правило:** если нужно «починить» sitemap — не удалять, а **изменить содержимое по тому же URL** (или вернуть 404). Yandex переобойдёт robots.txt и переосмыслит список sitemap'ов.

### 🟡 `sitemap-index.xml` от `@astrojs/sitemap` отдаёт 404 (15.04.2026)

**Симптом:** Вебмастер ругался на sitemap — URL `sitemap-index.xml` в `robots.txt`, а файл отсутствует.

**Причина:** у нас build post-processor удаляет `sitemap-index.xml` и переименовывает `sitemap-0.xml → sitemap.xml`. Директива в robots осталась старой.

**Решение:** в `robots.txt` оставили только:
```
Sitemap: https://aidacamp.ru/sitemap.xml
```

**Правило:** после любых правок sitemap-плагина — проверить что в `robots.txt` указан реально существующий файл, а не тот, что сгенерировал дефолт Astro/Next.

### 🟡 Webmaster 404 на редиректах — нормально, но нервирует (15.04.2026)

**Симптом:** Яндекс.Вебмастер помечал 5 URL (старые ссылки проекта) как 404, хотя все они **корректно отдают 301** на живые страницы.

**Причина:** Webmaster хранит исторические состояния, пока не переиндексирует редирект.

**Решение:** ничего не делать, ждать переиндексации. Либо в Вебмастере → «Переобход страниц» → запустить вручную.

**Правило:** перед тем как реагировать на 404 в Webmaster, проверить фактический ответ сервера: `curl -I https://aidacamp.ru/старый-url`. Если 301 — ок.

### 🟡 Якорь-редирект требует `return 301`, не `rewrite` (15.04.2026)

**Симптом:** правило nginx `rewrite ^/founders/?$ /#team permanent;` не работало — якорь `#team` отбрасывался.

**Причина:** директива `rewrite` не может отдать фрагмент `#...` — он не передаётся по HTTP, только через `Location:` в 301-ответе браузеру.

**Решение:** заменили на:
```nginx
location = /founders { return 301 /#team; }
```

**Правило:** для редиректов с якорем — `return 301 /path#anchor;` через `location =`. `rewrite` работает только для URL без фрагмента.

### 🟢 `legal.html` → `/legal/` — nginx rewrite (15.04.2026)

**Решение:** старые ссылки на `.html` редиректим в SEO-дружественный `/legal/`:
```nginx
rewrite ^/legal\.html$ /legal/ permanent;
```

**Правило:** при переезде с `.html`-файлов на чистые URL — обязательно 301-редиректы, иначе теряем ссылочный вес.

### 🟢 Фото преподавателей с именами = E-E-A-T для детского лагеря

**Контекст:** в Google Quality Rater Guidelines для YMYL-тематик (дети, здоровье, деньги) E-E-A-T — ранжирующий фактор. Для детского лагеря аудитория **мам** требует доверия.

**Практика:**
- На странице «Команда» (`/#team`) — фото педагогов с именами, опытом, достижениями.
- Блок «Отзывы» с ссылкой на Яндекс.Карты (подтверждает, что отзывы реальные).
- Лицензия Минобра — упоминать в тексте + ссылка на скан.

**Урок:** E-E-A-T — это не только про контент, а про **факты, которые можно проверить** (имена, лицензии, карты, отзывы).

### 🟡 RSY books генерирует отказной трафик, портит поведенческие (15.04.2026)

**Симптом:** RSY-группа `books` → 695 визитов, **scroll depth 5–6%** в Clarity, bounce ~85%. Это портит поведенческие сигналы всей страницы в Яндексе.

**Причина:** таргетинг по читателям книг по IT не совпадает с интентом «купить лагерь для ребёнка». Люди кликают из любопытства, быстро закрывают.

**Решение (в работе):** либо отключить группу books, либо вести на блог (информационный интент), а не на коммерческую посадку.

**Правило:** если РСЯ-группа даёт высокий объём + низкую глубину → это **риск**, а не «много дешёвых лидов». Яндекс учтёт в ранжировании.

### 🟢 Clarity как SEO-инструмент

**Практика:** Microsoft Clarity показывает реальное поведение — где читают, где скроллят, где кликают в мёртвую зону (`dead clicks`), где злятся (`rage clicks`). Это **прямые SXO-сигналы**:

- `rage clicks` на не-кликабельном элементе — нужно сделать кликабельным или убрать сигнал интерактивности.
- `dead clicks` в CTA-зоне — кнопка сломана или не видна.
- Низкий scroll depth — контент выше фолда не цепляет, интент не совпадает с запросом.

**Где смотреть:** у нас ETL в PostgreSQL, команда `./scripts/stats.sh` или MCP `clarity`.
