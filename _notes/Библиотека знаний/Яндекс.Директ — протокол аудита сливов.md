```

  date_from: "YYYY-MM-DD", date_to: "YYYY-MM-DD",

# Корректировки ставок — текущее состояние
curl Direct API: bidmodifiers.get CampaignIds=[ID] Levels=["CAMPAIGN"]
```

## Блок 1 — Площадки РСЯ

### Шаг 1.1. Найти мусорные площадки

**Критерии мусора (все три одновременно):**
- Кликов ≥ 3
- Отказы > 80%
- Конверсий = 0

```sql
SELECT placement, SUM(clicks) clicks, SUM(cost) spent, AVG(bounce_rate) bounce
FROM direct_placements
WHERE clicks > 3
GROUP BY placement
HAVING AVG(bounce_rate) > 80 AND SUM(conversions) = 0
ORDER BY spent DESC
```

**Красные флаги независимо от конверсий:**
- `com.*` мобильные игры с CTR > 20% — случайные клики
- `vpn.*`, `*.vpn` — VPN-приложения, не целевая аудитория
- `dsp-ironsource.*`, `dsp-unityads.*` — DSP-биржи с нулевой конверсией
- ГДЗ-сайты (`gdz.ru`, `reshak.ru` и др.) — аудитория школьников, не родителей

### Шаг 1.2. Проверить дорогие одиночные конверсии

Площадки с 1 конверсией и CPA > целевого × 1.5 — нестабильно, алгоритм переоценивает.

**Смотреть за неделю, не за день** — день слишком маленькая выборка.

### Шаг 1.3. Добавить в исключения

```bash
# Через прямой API (токен в ~/.codex/mcp-state/yandex-direct-metrica-mcp/.env)
TOKEN="..."
curl -X POST https://api.direct.yandex.com/json/v5/campaigns \
  -H "Authorization: Bearer $TOKEN" -H "Client-Login: kv145" \
  -d '{"method":"update","params":{"Campaigns":[{"Id": CAMPAIGN_ID,
    "ExcludedSites":{"Items":["site1.ru","com.app2","..."]}]}]}'
```

**Важно:** ExcludedSites — полный список (не дополнение). Каждый раз передавать ВСЕ исключённые площадки включая старые.

### Периодичность

- Первые 2 недели после запуска: каждые 3 дня
- После стабилизации: раз в неделю

## Блок 2 — Демография и возраст

### Шаг 2.1. Получить срез по возрасту × полу

Через `direct_reports` с полями Age, Gender, Cost, Conversions, CostPerConversion.

### Шаг 2.2. Оценить каждый сегмент

| Сегмент | Что делать |
|---|---|
| CPA < цели × 0.7 | +10..+30% корректировка |
| CPA > цели × 1.5 | -30..-50% или отключить |
| 0 конверсий при расходе > 500₽ | отключить (-100%) |
| Явно нецелевой (дети 0-17) | -100% безусловно |

### Шаг 2.3. Применить корректировки

```bash
# Удалить старую корректировку
curl bidmodifiers.delete SelectionCriteria.Ids=[ID]

# Создать новую
curl bidmodifiers.add params.BidModifiers=[{
  "CampaignId": ...,
  "DemographicsAdjustments": [
    {"Gender": "GENDER_FEMALE", "Age": "AGE_35_44", "BidModifier": 130},
    {"Gender": "GENDER_MALE", "Age": "AGE_35_44", "BidModifier": 110}
  ]
}]
```

**Формат BidModifier:** 100 = без изменений, 130 = +30%, 50 = -50%, 0 = -100%.

## Блок 3 — Поисковые запросы (кампания Поиск)

### Шаг 3.1. Найти мусорные запросы

```sql
SELECT query, SUM(clicks) clicks, SUM(cost) spent, AVG(bounce_rate) bounce
FROM direct_search_queries
WHERE clicks > 2 AND conversions = 0
GROUP BY query
HAVING AVG(bounce_rate) > 70
ORDER BY spent DESC
```

### Шаг 3.2. Типовые мусорные маркеры

- `бесплатно`, `скачать`, `своими руками` — нецелевой
- `отзывы сотрудников`, `вакансии` — ищут работу, не лагерь
- `что такое`, `как работает` — информационный, не коммерческий
- Конкуренты по названию (если не ретаргет)

### Шаг 3.3. Добавить в минус-слова

Через `direct_negative_keywords` или в настройках кампании.

## Блок 4 — После сброса обучения

**Симптом:** алгоритм PAY_FOR_CONVERSION резко снижает расход (0₽ или -90%).

**Причина:** любое изменение в кампании (корректировки, минус-слова, бюджет).

**Протокол:**
1. Не трогать ничего 5–7 дней — дать переобучиться
2. Не паниковать от высоких CPA в первые 3 дня
3. Смотреть тренд, не отдельный день
4. Ориентир восстановления: расход вернулся к 50%+ от докризисного уровня

**Правило 3x:** если CPA > целевого × 3 на площадке за 7+ дней → исключать.
