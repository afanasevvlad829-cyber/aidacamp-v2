## Стратегия и запуск кампаний

### Матрица выбора формата — 5 вопросов на старте
1. Товар или услуга?
2. Есть сформированный спрос или нет?
3. Локальный бизнес или без привязки к гео?
4. Уровень конкуренции в нише?
5. B2B или B2C?

| Вход | Формат |
|---|---|
| Товар, большой ассортимент, фикс. цена на позицию | Товарные кампании (динамика на поиске, смарт-баннеры в РСЯ, товарная галерея) — фид, не ручная семантика |
| Услуга, 10–20 позиций | Классика: поиск + РСЯ, без товарных форматов |
| Услуга, но нужна товарная галерея | «Упаковать» услугу как SKU — присвоить фикс. цену, сделать фид |
| Спрос сформирован | Поиск (горячий трафик) + медийно-контекстный баннер (МКБ) |
| Спроса нет, известен портрет ЦА | РСЯ с LAL / по интересам |
| Спроса нет вообще | РСЯ «решение проблемы» (ключи про боль, не про продукт) или «атака на конкурентов» (ключи-бренды конкурентов + жёсткий УТП — без него просто сливаете бюджет на чужой бренд-трафик) |
| Локальный бизнес | 3 раздельные кампании, не смешивать в одной РК: Яндекс.Бизнес (отдельная подписка, не часть Директа) + список организаций в поиске (режим эксперта / ЕПК) + Яндекс.Карты |

**Практически:** ЕПК (единая перформанс-кампания) — объединяет товарное объявление, Карты, список организаций, РСЯ, поиск и товарную галерею; на уровне объявления выбирается текстово-графический / графический / товарный формат / страницы каталога.

### Воронка спроса — приоритет каналов

| Уровень | Канал | Условие запуска |
|---|---|---|
| Уже знают нас | Ретаргетинг | Аудитория на сайте от 100 посетителей/мес (минимум для теста), 500–1000/мес — объём для устойчивого результата |
| Есть спрос | Поиск + МКБ | Сформированный интент, целевые запросы |
| Есть признаки покупателя, спроса нет | РСЯ + LAL (на купивших/оставивших заявку) + интересы | Известен портрет ЦА |
| Создание спроса | Видео / медийка | Есть бюджет на охват с нуля |

🤔 Гео-таргетинг через сегмент в Яндекс.Аудиториях (круг/полигон) по опыту одного из практиков курса работает нестабильно — тестировать в каждом проекте, не закладывать заранее в план.

### Алгоритм тестового запуска и диагностики
1. Тест 1–2 недели — собрать первичные показы/клики/заявки.
2. Проблема → спуск по воронке от большего к меньшему: **кампания → группа → объявление**. Не отключать кампанию целиком, если внутри есть рабочая группа/объявление.
3. Работает хорошо → масштабировать: удачный текст — тиражировать в другие группы, удачную кампанию — расширять (МКБ, ретаргетинг).
4. Гипотеза не сработала → следующая гипотеза, не зацикливаться на одной идее.

**Кейс (грузоперевозки):** гипотеза «ключи с парами городов >1000 км друг от друга» — 10 конверсий по 3000 ₽, 0 сделок. Пивот: убрали города из семантики (минус-словами), оставили отраслевые запросы («контейнерные перевозки») — конверсии в 3 раза дешевле, пошли реальные сделки. Вывод: угадать рабочую гипотезу заранее нельзя, только тест + разбор по воронке.

### Гео-таргетинг для локального бизнеса

| Способ | Где | Параметры |
|---|---|---|
| Сегмент в Яндекс.Аудиториях | Библиотека → Аудитории → геолокация | Круг (радиус 500 м – 10 км) или полигон; поведение: живёт / работает / регулярно бывает / был N дней за период |
| Настройка группы объявлений | «Указать регион на карте» на уровне группы | Радиус 500 м – 20 км; старт — 10 км, дальше калибровать по готовности ЦА ехать |
| Корректировка ставки по гео-сегменту | Уровень кампании, условие из Аудиторий | Максимум **+1200%** (технический потолок системы). Пример: базовая ставка 30 коп. × 13 = 3,60 ₽ — часто мало для нормальной частоты показов; поднимать базовую ставку (например до 10 ₽) и калибровать эмпирически |

**Практически:** для локального бизнеса не растягивать таргетинг на весь город — сужать до районов/станций метро, где реально находится ЦА.

### Пороги готовности целей к оптимизации

- Минимум **8 достижений цели в неделю**, идеал — **10/неделю** — иначе алгоритму не на чем обучаться (актуально и для авто-стратегий, и для запуска оплаты за конверсию).
- Цели делятся на **макро** (заявка, звонок, покупка) и **микро** (клик по телефону/email, копирование номера, сообщение в чат). Квиз — пограничный случай: горячая аудитория → можно считать макро, иначе — микро.
- Не хватает объёма по макроцели → подниматься по воронке к цели с бóльшим охватом (например «Все формы» вместо «CRM: заказ создан»).
- **Проверка качества суррогатной (микро)цели** перед тем как оптимизировать по ней (Метрика, отчёт «Директ, сводка»):
  1. Сегмент «визиты, в которых» → фильтр по достижению макроцели.
  2. Второй фильтр внутри сегмента → доля визитов, где достигнута цель-кандидат.
  3. Фильтрация **«по людям» точнее, чем «по визитам»** — использовать её.
  - Пример: «Все формы» конвертировались в «CRM: заказ создан» в 60% случаев при достаточном объёме — годится для оптимизации; «Клик по номеру телефона» и «Звонок» показывали похожую % корреляции, но недостаточный объём — не годятся, даже если их рекомендует сам Директ.
- Обязательно сверять срабатывание цели через Дебаггер Метрики или GTM перед стартом кампании.

### Прогноз бюджета и лидов

| Инструмент | Когда использовать | Особенности |
|---|---|---|
| **KeyCollector** (статистика Директа через прокси-аккаунты + Wordstat через XML River) | Есть готовое чистое СЯ | Точнее по конкретным ключам; при больших объёмах неудобно — делить на части |
| **«Прогноз бюджета» Директа** (Инструменты → Прогноз бюджета) | Нет собранного СЯ (медиаплан с нуля) | Ввод базисов/масок, не готовых ключей; сразу даёт 3 уровня трафика — 100% / 85% / 62% ≈ 1-е / 2–3-е / 4–5-е места; лимит символов на ввод — делить список и суммировать вручную; минус-слова не заливать — виснет или ошибка |

**Формула прогноза лидов:** клики × % конверсии сайта = заявки; бюджет / заявки = цена заявки.
- Диапазон конверсии по умолчанию: **1–5%** (обычный сайт), в квизах и нишах с высокой вовлечённостью — выше (до 10%).
- Если кампания уже крутится — не гадать диапазон, а подставлять реальную конверсию из Метрики (составная цель, объединяющая заявки+звонки, срез за 90 дней).

**Поправочные коэффициенты** (все прогнозы относятся к 1-му месту / 100% трафика — верхняя граница, не гарантия результата):
- Прогноз по базисам/маскам (неочищенное СЯ) — итоговые конверсии и бюджет делить на **3**. 🤔 Эмпирический коэффициент одного из практиков курса (по наблюдению: ~1/3 ключей мусор, ~1/3 не мусор, но не по бизнесу, ~1/3 целевые) — не задокументирован Яндексом, проверять на своих нишах.
- Прогноз KeyCollector и встроенный «Прогноз бюджета» по одинаковым чистым ключам расходятся примерно **в 1,3 раза** (KeyCollector обычно выше) — использовать оба как перекрёстную проверку, а не как точное число.

**Чистка СЯ:**
- Проверка коммерциализации ключей (Arsenkin) — порог **< 30%** = подозрительный ключ, разбирать вручную.
- Фильтр «мусора» в KeyCollector: база (частота) > 1000 при частоте «в кавычках» = 0 — сигнал недочищенной фразы.
- Фиксация порядка слов в минус-фразе: `!для грузоперевозки` — восклицательный знак перед словосочетанием отсекает конкретный порядок слов, а не отдельные слова.

```
Пример (перевозки контейнеров, KeyCollector, 100% трафика):
клики/мес ≈ 456, бюджет/мес ≈ 84 000 ₽
конверсия 1%  → 5 заявок,  CPA ≈ 18 465 ₽
конверсия 5%  → 23 заявки, CPA ≈ 3 193 ₽
```

### Стратегии запуска по типам бизнеса

🤔 Раскладка по 7 типам бизнеса и по месяцам — личная система одного из авторов курса на основе практики («откручены сотни миллионов рублей»), не официальная методология Яндекса. Рабочая, но не догма.

| Тип бизнеса | Месяц 1 | Месяц 2+ | KPI-ориентир |
|---|---|---|---|
| **B2B** (грузоперевозки, брокеридж) | Ретаргетинг в РСЯ (от 100 посетителей/мес) | Поиск: сначала брендовый запрос (проверить через Wordstat с оператором «ИЛИ»), затем небрендовый; со 2-го мес — РСЯ (мин. 4 группы: по ключам, LAL, интересы+сайты конкурентов, расширение) + Мастер-кампании | Лид 2000–5000 ₽; доля неподтверждённых заявок не выше 30% — иначе отключать источник |
| **Интернет-магазин** | Товарная галерея на поиске (нужны цена+фото — клик в 2–3 раза дешевле обычного поиска) + смарт-баннеры / офферный ретаргетинг | Мес.2: классич. ретаргетинг, текстово-графич. поиск, динамич. объявления по фиду. Мес.3: смарт-баннеры на LAL, единая товарная кампания, РСЯ, Мастер-кампании | Корзина 500–2000 ₽; конверсия корзина→покупка от 20% (иначе проблема на сайте, не в рекламе); тест РСЯ/МК — не более 20% бюджета аккаунта |
| **Офлайн/локальный** (стоматологии, салоны) | Яндекс.Бизнес + список организаций в поиске + Карты (через ЕПК, режим эксперта) | Поиск с гео-настройками (см. выше) | Крео: интерьер, коллектив |
| **Недвижимость** | Сразу: поиск + ретаргетинг + МКБ + графика (без поэтапного разделения) | Со 2-го мес: видео с гео-таргетингом по району | МКБ почти обязателен в нише; аналогично хорошо работает в медицине |
| **Онлайн-школы** | Чек до 5000 ₽ → сразу РСЯ с оплатой за конверсии + обязательный ретаргетинг по сегментам интересов (строить в Метрике через «Просмотры URL» на каждое направление); чек ~30 000 ₽ → пробовать поиск | LAL по сегментам, Мастер-кампании со 2-го мес; видео/медийка — только когда РСЯ и МК уже выжаты | Модерация режет тексты про деньги/заработок в текстовых объявлениях — то же самое часто проходит в баннерах |
| **Приложения** | Все форматы с оптимизацией на установку | Оптимизация на первое событие (сразу или через ~2 нед), затем на оплату | Установка 50–500 ₽; подписка окупается за 50–200% от разовой цены за счёт LTV |

**Практически (МКБ):** без номера телефона в дизайне баннера часть звонков теряется — указывать обязательно.

### Декомпозиция до уровня продаж

Обратный расчёт бюджета от цели клиента в клиентах:

```
лиды         = целевые_клиенты × 100 / %конверсия_в_сделку
клики        = лиды / SR1                 (SR1 = конверсия клик→заявка, из Метрики)
бюджет       = клики × средняя_CPC
цена_клиента = бюджет / целевые_клиенты

Проверка через юнит-экономику:
оборот  = средний_чек × целевые_клиенты
доход   = оборот × %маржи
чистыми = доход − бюджет − стоимость_услуг_специалиста
```

**Пример:** 20 клиентов, конверсия в сделку 30% → 67 лидов; SR1 1% → 6700 кликов; CPC 100 ₽ → бюджет 670 000 ₽; цена клиента 33 500 ₽. Чек 150 000 ₽ → оборот 3 000 000 ₽, маржа 30% → доход 900 000 ₽; минус реклама (670 000 ₽) и услуги специалиста (40 000 ₽) → чистыми ≈ 190 000 ₽ — реклама окупается.

**Практически:** брать не любую попавшуюся CPC (у отдельной группы может быть 138 ₽), а средневзвешенную по аккаунту/нужным ключам — иначе прогноз бюджета исказится.

### Мастер кампаний

Гибрид поиск+РСЯ в рамках **одной группы объявлений** (не полноценная кампания с несколькими группами). При наличии карточек товаров с ценниками — автоматически переключается в товарную кампанию, даже если вручную выбран режим «Конверсии, трафик».

| Параметр | Значение |
|---|---|
| Ключевые фразы | Максимум **200** на кампанию — оставлять самые частотные |
| Заголовок / текст | 56 / 81 символ; Директ комбинирует 5 заголовков × 3 текста × до 5 картинок |
| Быстрые ссылки | Название до 30 симв., описание до 81; нужно 8 шт. (показываются 4 или 8) |
| Видео | До 60 сек, mp4, ≤100 МБ, 360p–4K |
| Чекбокс «продвижение из Яндекс.Бизнеса» | Только для локального бизнеса — запускает сразу 4 формата (РСЯ, поиск, список организаций, Карты) в одной кампании; для нелокального бизнеса лишний расход |
| UTM-метки | Вставлять по одной строке — блоком целиком система не распознаёт разметку |

**Категории авто-таргетинга — исключать по умолчанию:** альтернативные запросы, сопутствующие запросы, запросы с упоминанием конкурентов, широкие запросы. Оставлять только «целевые запросы» (не отключается принципиально) — расширение охвата означает больше нецелевого расхода.

**Стратегия оплаты:**
- **Без ограничений** — обязательна при первом запуске / нет накопленной статистики.
- **Фиксированная цена / среднее за неделю** — только при ≥10 конверсий/неделю по другим кампаниям. 🤔 По опыту практика курса, у фиксированной цены «ограниченный срок жизни» — через 3–4 дня (максимум неделю) показы и клики резко падают. Официальная документация Яндекса такого поведения не описывает — проверять на своих кампаниях.
- Недельный бюджет — не ниже **10 000 ₽/неделю** практически в любой нише: лид редко стоит дешевле 1000 ₽, для обучения нужно ~10 лидов/неделю.
- «Директ Помогает» (авто-применение рекомендаций Яндекса) — не включать на старте, отдаёт кампанию под неконтролируемые правки.

**Поиск конкурентов для таргетинга по доменам:** Arsenkin → «Выгрузка топ-10 сайтов» по ключам региона → вручную отсеять маркетплейсы/агрегаторы/непрофильные широкие компании → добавлять именно как **домен** (аудитория, похожая на посетителей сайта), не как поисковый запрос — иначе таргетинг уйдёт на буквальный запрос с названием сайта.

### Диагностика Мастера кампаний

У Мастера кампаний по умолчанию нет кнопки «Статистика» в списке — обходной путь: открыть статистику любой другой активной кампании (например РСЯ) → выбрать нужный Мастер по полному названию в выпадающем списке кампаний, либо (если не находится) скопировать номер кампании и подставить его в URL статистики РСЯ-кампании вручную.

**Что смотреть:**
- Срез по типу площадки («Название кампании» содержит «МК» → срез «тип площадки») — в норме **90%+ кликов и показов уходит в РСЯ**, не на поиск. Это системная особенность формата, не аномалия конкретного проекта.
- Если РСЯ-часть даёт конверсии, а поиск — нет: это **не означает**, что отдельная поисковая кампания будет слабой — внутри Мастера все 200 ключей свалены в одну группу без разбивки по смыслу, в отличие от полноценного поиска с группировкой по контексту. При ограниченном бюджете — сначала масштабировать то, что уже работает (обычно РСЯ), поиск тестировать отдельно позже.
- Срез «по площадкам» — искать домены с расходом без конверсий, вручную запрещать показы (галочками) — единственный доступный способ оптимизации плейсментов внутри Мастера.
- Срез «по номеру объявления» — искать лучшую комбинацию заголовок+текст+картинка по CPA/конверсии, отключать проигравшие варианты.

## Исследование: спрос, семантика, конкуренты, SEO

### Базисы и маски — сбор ядра «в ширину»

Базис / маска / маркерный запрос — минимальный набор слов (обычно 2–3, реже 1 или 4), описывающий продукт. Порядок работы: сначала собрать все базисы **в ширину** (структура сайта, разные услуги), затем каждый базис прорабатывать **в глубину** (все вложенные хвосты через Wordstat / K-коллектор).

**Методика сбора базисов через структуру сайтов конкурентов:**
1. Вбить самый частотный запрос тематики в Яндекс, пролистать блок рекламы до SEO-выдачи.
2. **Не открывать агрегаторы** (Ozon, Wildberries, Zoon и т.п.) — они в топе за счёт трафика, а не проработанной структуры, чистых базисов там нет.
3. Открыть 2–3 первых коммерческих сайта, выписать формулировки базисов из меню/разделов (SEO-специалисты конкурента уже сделали эту работу).
4. Разбивать сложные запросы на несколько отдельных базисов там, где Яндекс различает написание: «бетон M100 B7,5» → «бетон M100», «бетон M 100», «бетон B7», «бетон 100»/«бетон марки 100».
5. Согласовать список базисов с клиентом — не все формально релевантные запросы подходят под его продукт.

| Инструмент | Что даёт | Цена |
|---|---|---|
| SEO-выдача Яндекса (вручную) | Основной способ добычи базисов | бесплатно |
| MegaIndex.ru, «Поиск конкурентов» | По одному прокачанному домену находит похожие сайты, сортировка по «показам конкурента» | бесплатно, рекомендован в первую очередь |
| Key.so (сбор конкурентов) | Глубже MegaIndex: объявления, органика, ключи в топ-1/5/10/50 | от 5300 ₽/мес; бесплатный тариф — только 10 сайтов |
| Букварикс | По базису отдаёт тысячи вложенных ключей + синонимы, выгрузка | ~800–1000 ₽ разово |
| Google Картинки, сниппеты выдачи | Доп. атрибуты товара, «чтение между строк» | бесплатно |

Ограничение Wordstat: по одной маске отдаёт максимум **41 страницу × 50 = ~2100 ключей** — собирать по широкому слову («бетон», «грузоперевозки») бессмысленно, часть хвостов теряется.

### Операторы Wordstat

| Оператор | Действие | Когда применять |
|---|---|---|
| `+` | Фиксирует стоп-слово (предлог/союз/местоимение) | Фиксировать всегда, если без него меняется интент фразы |
| `-` | Исключает слово | Формирование списка минус-слов |
| `!` | Фиксирует словоформу | Только после проверки в Wordstat, что другая словоформа действительно нерелевантна |
| `""` | Частота точной фразы без хвостов | На дорогих ВЧ-ключах — не переплачивать за широкий трафик |
| `[]` | Фиксирует порядок слов внутри фразы | Билеты, направления доставки («Москва-Сочи» ≠ «Сочи-Москва») |
| `\|` (ИЛИ) | Комбинаторное «перемножение» групп слов | Быстрая оценка суммарного спроса по синонимам, не финальный сбор |
| `#` | Автоподстановка ключа в заголовок/текст объявления | 🤔 автор использует крайне редко |

**Что Яндекс различает / не различает** (важно для решения — минусовать словоформу или нет):
- Существительные: различает написание (слитно/раздельно, транслит) и род; **не** различает число без `!`.
- Глаголы: различает вид (делать/сделать) и причастия/деепричастия; **не** различает время/лицо без `!` (купил/купить/куплю — одно и то же).
- Прилагательные: различает полную форму («хорошая» ≠ «красивая» кухня); **не** различает краткую форму/наречие («хорошо» = «хорошие»).
- Не различает регистр, порядок слов, дефис.
- Различает сленг (стиралка/стиральная машина), автоматически поправляет транслит/раскладку.

### KeyCollector — сбор и чистка

**Зависимости:** антикапча (Rucaptcha, пополнение 10–20 ₽/мес), XMLRiver (~20 ₽/1000 ключей, пополнение 100 ₽ ≈ 5000 запросов), «прогретые» аккаунты Яндекс.Директ для сбора реальной статистики (~405 ₽/мес за пакет на 5 потоков). Лицензия KeyCollector — разовая, ~2200 ₽, привязана к ПК.

```
Парсинг → Собрать фразы Яндекс.Wordstat через XMLRiver
  Страниц: 45 (не 41 — за счёт метода обхода даёт больше, чем UI Wordstat)
  Частота: от 1 до ∞
  Обязательно включить: «Пропускать фразы, которые уже есть в любой группе»
  → Распределить по группам (каждый базис = отдельная папка)
```

**Строгий порядок обработки (нарушение усложняет работу): сначала минус-слова, потом группировка.**

1. Выделить все группы → Shift/F3 («мультигруппа»).
2. Главная → «Анализ групп» → «по отдельным словам» → Начать анализ — фразы раскладываются на уникальные слова с частотой встречаемости словоформ.
3. Сортировать по убыванию количества вхождений, проходить сверху вниз: «Отправить слово в минус-слова» → обязательно нажать «Добавить» (иначе не сохранится).
4. Информационные слова с двойным смыслом («размер») минусовать точечно через `!словоформа`, а не слово целиком — иначе теряются коммерческие хвосты («кровать размером 40 на 40»).
5. Проверка: Минус-слова → «Показать найденные фразы» — убедиться, что минус-слово не выбивает целевые фразы; если выбивает — сузить через `!`.
6. Только теперь — повторный «Анализ групп», фильтр «Количество» → «Больше чем 1», группировка кластеров вручную по одному за раз (слова пересекаются между смысловыми группами — скопом переносить нельзя).

**Готовые шаблоны минус-слов** (переиспользуемые заготовки): вопросительные слова, «бесплатно»/«даром», «самостоятельно», информационные (форум/чат/фото), агрегаторы, «б/у».

**Идеальная кластеризация = синхронизация с продуктовой линейкой клиента**, а не только с совпадением URL в выдаче (пример: группировка по реальным проектам домов/направлениям грузоперевозок). Правило: **одна семантическая группа = одно объявление**, ключи группы — в заголовок и текст; в идеале под группу — отдельная посадочная, минимум — отдельный заголовок на общей странице.

**Поиск неявных дублей:** режим «точный» → при необходимости «углублённый» (🤔 «быстрый» даёт ошибки, у автора углублённый тоже ложно предлагал объединить «с маятником» и «без маятника»). Критерий: если у похожих фраз разная базовая частота — это разные ключи для Яндекса, не объединять.

### Кластеризация запросов: Арсенкин vs KeyAssort

| | Арсенкин | KeyAssort |
|---|---|---|
| Цена | Basic 850 ₽/мес (28000 лимитов), Mini 110 ₽/мес (2500); промокод `EXTEND7` | разовая покупка ~40$ (~3700 ₽ на 2024 г.), привязка к ПК, через XMLRiver |
| Метод группировки | Hard (по URL из топ-10, не по главным страницам) — для бизнес-тематик всегда Hard, Soft — для инфоресурсов | сила по SERP аналог Hard |
| Проверка коммерциализации | Есть | Нет — нужен Арсенкин отдельно |
| Доп. функции | Генератор ключей (продающие приставки: купить/заказать/по индивидуальному размеру) | «Миграция запросов» (перегруппировка при более сильной связи 3–4 URL), исключение агрегаторов и сервисов Яндекса из выдачи, свой стоп-лист URL |

**Степень группировки:** начинать с 2 (быстрый поиск мусора, качество низкое), при плохом результате повышать до 3–4 (точная группировка под объявления). Выше 4 — смысла нет; если и на 4 «бардак» — признак неоднозначной тематики.

**Настройка Арсенкина под рекламу на поиске:**
- Регион: если город клиента <100 тыс. населения — брать региональную столицу.
- Глубина проверки — топ-10.
- Проверять интент группы можно в режиме инкогнито ИЛИ через сам Арсенкин (он работает «инкогнито» по умолчанию, история запросов не искажает выдачу) — достаточно одного ключа из группы, не всей группы.

**Минус-слова из кластеризации** ставить на уровне **группы объявлений**, не кампании — в Директе ключевое слово приоритетнее минус-слова: если «кухни Италии» в минус-словах, но есть широкий ключ «итальянская кухня заказать», показ всё равно будет.

### Проверка коммерциализации

Арсенкин: закинуть список ключей → сервис проверяет топ-10 SEO-выдачи по каждому → % коммерческих сайтов среди них.

| Порог | Действие |
|---|---|
| ≥ 30% | Брать ключ для рекламы на поиске |
| 20–30% | Можно брать, если ниша узкая и мало ключей (снижать порог до 25%) |
| < 20% | Не брать для поиска, минусовать |

Применимо только к **поиску** — для РСЯ ключи не так критичны, там таргетинг на аудиторию, а не на интент запроса.
Слова «лучше», «рейтинг», «топ» — сигнал информационности, минусовать. Указание города в запросе резко повышает коммерческий интент (🤔 пример из курса: «услуги электрика» ~30% → «услуги электрика Москва» 70–90%).

Альтернатива без Арсенкина — оператор `|` с коммерческими приставками («купить», «заказать», «недорого») — 🤔 автор прямо называет метод менее точным, рекомендует Арсенкин.

### Расширение семантики через сайт сильного конкурента

1. Найти сайт, хорошо ранжирующийся по нужному базису.
2. Спарсить весь сайт: SiteAnalyzer (бесплатно, лимит ~10 000 страниц) или ScreamingFrog SEO Spider (платный, без лимита).
3. Оставить только HTML-страницы, взять столбцы title/description/H1/H2.
4. «Текст по столбцам» в Excel → залить слова в Key Collector → «Анализ групп по отдельным словам» → найти упущенные базисы.
5. Те же title/description — готовые заготовки для заголовков и текстов собственных объявлений.

### SEO-выдача как индикатор интента

Смотреть **не на рекламный блок** (он оплачен), а на органический топ-10 — Яндекс ранжирует по накопленному поведению пользователей, это прямой сигнал их намерения. Пример: по «кухни Италии» весь топ-10 — про еду, ни одного сайта про мебель → рекламодатели под мебель сливают бюджет. Если в топе видео (YouTube/Дзен) — аудитория хочет видеоформат ответа.

Двухфильтровая система отбора ключей под рекламу на поиске:
1. Кластеризация по SEO топ-10 (Арсенкин/KeyAssort) → отсев нецелевых групп.
2. Проверка коммерциализации → отсев информационных запросов.

### Анализ спроса

**Ёмкость рынка в деньгах**
```
Ёмкость рынка (₽) = число показов по ключу за месяц (Wordstat → «Топ запросов») × средний чек
```
Опционально: делить на число конкурентов → ориентировочный потолок выручки на игрока.

**Сезонность**
1. Wordstat → «История запросов» за 2 года, выгрузка XLS, убрать столбец «доля от всех запросов».
2. Отметить аномальные месяцы отдельно по каждому году.
3. В итоговую сезонность заносить только месяцы, **совпавшие в обоих годах** (пересечение, не объединение).
4. Усиленный запуск рекламы — **за 2 недели до начала роста**. В спад — либо полная остановка, либо «поддерживающий» бюджет, чтобы не обнулять заявки.

**Регионы (индекс интереса / Affinity Index)**
- Wordstat → «Регионы», смотреть **отдельно** разрез регионов и разрез городов (смешивать нельзя — подмешиваются страны/округа).
- Индекс 100% = средний интерес по РФ, 420% = в 4 раза чаще, чем в среднем.
- 🤔 Фильтр-эвристика автора: отсекать регионы с числом запросов < 100 при сортировке по индексу — иначе «выстреливает» регион с индексом 1000% и 1 запросом в месяц.
- Результат — основа для корректировок ставок по регионам.

**Устройства (десктоп/мобайл)**
Wordstat → «Топ запросов» с фильтром по устройствам.
- 🤔 Авторское правило: сильный перекос (пример 58/42) → делать отдельную мобильную версию сайта; ~50/50 → достаточно адаптива.
- Проверка адаптив vs мобильная версия: Chrome DevTools (F12) → эмуляция устройства, смотреть меняется ли раскладка блоков.

**Сформированность спроса (длина хвоста)**
1. Базовый ключ в кавычках → частота двухсловника. Последовательно добавлять слова (дублируя слова базиса) до 10-словника.
2. Доля каждой длины = частота этой длины / общая частота без кавычек × 100%. Остаток до 100% = спрос 11+ слов.
3. 🤔 Ориентир: основная доля (60–80%) на 4–7-словниках → спрос сформирован (нужна цена, условия), на 1–2-словниках → не сформирован (нужно «разжёвывать» на лендинге). Порог индивидуален по нише.
4. **Жёсткое ограничение Директа: ключевая фраза максимум 7 слов.** Хвосты от 8 слов — только через Букварикс (фильтр «слов от 8»), используются для SEO/контента/Google Ads.

**Анализ по свойствам (Key Collector → «Анализ групп по отдельным словам», колонка «Сумма» = базовая частота)**
- Раскладывает всю собранную семантику на уникальные слова с долей от общего спроса → основа для позиционирования и приоритизации ассортимента.
- Пример метода: доли по словам «каркасный»/«модульный»/«под ключ»/«терраса»/«ипотека» → 3 варианта позиционирования продукта.
- Даже микро-доля (0,2–0,4%) может стать УТП, если у конкурентов это свойство не отражено на сайте.
- Ассортиментная матрица: топ-20 запросов внутри каждой категории товара — что закупать/публиковать в первую очередь; альтернатива — фокус только на топ-10 самых рентабельных позиций.
- Смежный спрос («точка роста»): расширяться на него — **только после полной проработки прямого спроса** и при наличии доп. бюджета. Монетизация: посадочные страницы сравнения («товар А vs товар Б») или блог со статьёй под каждый смежный продукт.

Инструменты по возрастанию стоимости/глубины:

| 5 | SpyMetrics | бесплатно (есть платные тарифы) | Все каналы трафика конкурента: источники, гео, соцсети, баннеры/РСЯ доля |

**MegaIndex → таргетинг «Интересы и привычки»:** загрузить до 30 доменов конкурентов. 🤔 Яндекс официально заявляет таргетинг «на похожую» аудиторию, а не напрямую на аудиторию конкурентов, но по опыту автора при загрузке ровно до 30 доменов показ идёт максимально прицельно на близкую к конкурентам аудиторию.

**Keys.so vs SpyWords:** оба дают исторические данные (в отличие от XMLRiver — real-time). Выбор по гео клиента: если город входит в список из 7 у SpyWords — брать его (дешевле), иначе проверять покрытие в Keys.so. 🤔 «Прогноз бюджета» в Keys.so сильно врёт — расхождение с фактом может быть в 10–20 раз в любую сторону, использовать только для грубой оценки масштаба, не для планирования.

Длительное время объявления в открутке (по данным Keys.so) — косвенный сигнал, что креатив хорошо работает.

### Анализ сайтов конкурентов — шаблон

Столбцы таблицы (адаптировать под нишу — добавлять специфичные, например «каталог блюд» для доставки еды):

```
Сайт | Заголовок/текст объявления (из XMLRiver-выгрузки) |
Соответствие обещания из объявления посадочной странице (да/нет) |
Цены по типам товара/услуги | Промо-акции (предложение с ограничением по времени) |
Позиционирование | УТП | Недостатки сайта | Точки роста |
Оценка сайта (0–10) | Оценка рекламы (0–10)
```

**Первая и главная проверка** — соответствие обещания в объявлении посадочной странице (пример: объявление про «аренду супер-яхты», а отдельного лендинга под неё нет — фиксировать как минус конкурента).

Вывод по пулу конкурентов: «что есть у всех» = обязательный минимум для сайта клиента; «чего нет ни у кого» = потенциальная точка дифференциации.

**Технический лимит Директа:** видео-дополнение — ролик до 1 минуты.

**Сведение УТП конкурентов с болями ЦА** (два независимых источника данных сводятся в одну таблицу):

```
УТП (из объявлений конкурентов) → какую боль/страх/потребность ЦА закрывает
(из отдельного анализа аудитории) → важность 0–10
```
Примеры: гарантия 2–5 лет → страх недолговечности; бесплатный выезд специалиста → страх переплатить неизвестному подрядчику; оплата поэтапно → страх оплаты за плохой результат.

**Призыв к действию:** предпочтительны мягкие CTA — задача объявления получить переход, а не продать сразу.

**Приоритет шаблонов по автору:** комплексный (сайт+реклама вместе) — основной, использовать сразу; детальный шаблон под доработку сайта — позже, когда накоплены данные Метрики/вебвизора; короткий шаблон по объявлениям — для быстрой прикидки.

### Числовые пороги — сводная таблица (авторские эвристики 🤔, не документация Яндекса)

| Порог | Значение |
|---|---|
| Длина ключа для Директа | максимум 7 слов (жёсткое техническое ограничение) |

## Маркетинг и анализ целевой аудитории

### ABC-анализ (приоритизация товаров)

Источник данных — Яндекс.Метрика → «Электронная коммерция» (расширенная) → отчёт «Заказанные товары». Требует настройки расширенной эком-цепочки (CMS + CRM + Метрика). Отчёт агрегирует продажи по **всем** источникам трафика (SEO, прямые заходы, соцсети), не только по Директу — ABC даёт срез по всему бизнесу.

**Методика:**
1. Выгрузка за период ≥ год, в Excel; удалить строки «Итого»/«Среднее» и столбец «кол-во посетителей купивших товар».
2. Автосуммой посчитать общее кол-во проданных единиц и общую сумму продаж.
3. Доля товара (шт.) = кол-во товара / сумма всех товаров; доля оборота (₽) = стоимость товара / сумма всей стоимости.
4. Отсортировать по убыванию, посчитать накопительный % отдельно по осям «штуки» и «оборот».
5. Присвоить категорию по накопительному %:

| Накопительный % | Категория |
|---|---|
| < 80% | A |
| 81–95% | B |
| > 95% | C |

🤔 Пороги 80%/95% — авторские, не отраслевой стандарт с точностью до цифры; на практике подбираются под ассортимент.

Категория считается отдельно по «штукам» и по «обороту» → 9 комбинаций (AA…CC).

**Трактовка комбинаций:**

| Комбинация | Смысл | Действие в рекламе |
|---|---|---|
| AA | товары-звёзды | приоритет №1 в Директе, максимальный бюджет |
| AB/BA | сильный по одному критерию | стандартная поддержка, мониторинг |
| AC | низкая маржа, высокий оборот | не давать продажам упасть, следить за ценами конкурентов |
| BB | устойчивые середняки | рекламу не трогать |
| BC | низкая маржа, средний оборот | усиливать УТП в объявлениях/на лендинге |
| CA | эксклюзив/новинка, высокая маржа | точечный таргетинг, малый бюджет |
| CB | небольшой оборот, средняя маржа | акции, изменение выкладки/оффера |
| CC | аутсайдеры | **не рекламировать в Директе** — заведомо убыточные вложения |

### RFM-анализ (приоритизация клиентов/сегментов)

В отличие от ABC (товары) — сегментирует клиентов/отрасли. Источник данных — **CRM**, не Метрика: дата покупки, клиент/организация, сумма заказов, отрасль.

**Методика:** по каждому клиенту считаются 3 сырых показателя → каждому присваивается балл 1–5:
- **R (Recency)** — дней с последней покупки
- **F (Frequency)** — количество покупок
- **M (Monetary)** — сумма заказов

Итог R+F+M = от 2 до 10.

| Сумма баллов | Сегмент | Действие |
|---|---|---|
| ≥ 5 | приоритетные клиенты | максимальная лояльность, бонусы, персональные предложения |
| 2–4 | вторая приоритетная группа | поддерживающая коммуникация |
| низкие баллы | новые клиенты | не разочаровать, показать конкурентные преимущества |

Тот же расчёт можно агрегировать по отраслям вместо клиентов (B2B).

**Применение в Директе:**
- Приоритетная отрасль/сегмент → её интересы и ключевые слова в семантику; домены сайтов-конкурентов этой отрасли — в блок «интересы и привычки».
- Отдельные сегменты ретаргетинга и отдельные объявления под разные отраслевые сегменты (не одно объявление на всех).
- «Подвисшим» клиентам (низкий R) — напоминание через ретаргетинг + email.

ABC и RFM вместе задают приоритеты бюджета: какие товары и какие сегменты ЦА продвигать в первую очередь.

### Сбор данных о ЦА

Пять источников (не документация Яндекса, авторская методика):

1. Форумы, отзовики, комментарии в соцсетях
2. Прослушка входящих звонков
3. Обзвон существующих клиентов
4. Прямые сообщения потенциальным клиентам в соцсетях
5. Отчёты Яндекс.Метрики («Аудитория»)

**Работа с отзывами:**
1. Запрос «[товар] отзывы + регион» в Яндексе → irecommend, otzovik.com, Яндекс/Google Карты.
2. Приоритет — **отрицательным** отзывам: положительные часто заказные (SERM/ORM), негативные подделать сложнее. На otzovik.com — фильтр по звёздам/негативу.
3. Свести в таблицу и категоризировать жалобы, посчитать долю каждой категории.
4. Категория с максимальной долей жалоб → акцент на лендинге (гарантии, УТП против этой боли) и в тексте объявления.

Шаблон таблицы отзывов: пол, дата, адрес компании, боли, потребности, критерии выбора, преимущества компании, комментарии, площадка, вывод.

Дополнительно: опрос неконвертировавшихся (не дозвонился / не устроила цена / занят) даёт материал для доработки скрипта продаж; согласие лояльных клиентов на публикацию отзыва — материал для SERM.

**Яндекс.Метрика → «Аудитория»:**

| Отчёт | Что даёт |
|---|---|
| Пол + группировка «Возраст» + фильтр по цели | конверсионный пол/возраст (сверять % конверсии с абсолютным числом целей — низкий объём искажает %) |
| География | доля конверсий по регионам/городам |
| Долгосрочные интересы | сегменты через аффинити-индекс |

**Аффинити-индекс:**
- 100 = нейтральная аудитория («средняя температура по больнице»).
- 503 = эта аудитория примерно в 5 раз чаще совершает целевое действие, чем средняя.
- В UI нельзя отсортировать по индексу — выгружать в Excel.
- Смотреть 3 уровня вложенности интереса — уровень 2–3 обычно даёт более специфичный (и более высокий) индекс, чем уровень 1.
- 🤔 Порог значимости, который использует автор: **индекс от 200+**, и обязательно фильтровать по кол-ву достижений цели **> 3–4** — иначе высокий индекс на 1 конверсии нерелевантен (ложный сигнал).
- Практика: интересы с высоким индексом часто пересекаются с краткосрочными интересами в интерфейсе Директа — готовый список для таргетинга.

### CustDev (глубинные интервью)

Метод проверки гипотез продукта через проблемные интервью с реальными/потенциальными клиентами. Опрашивать в первую очередь тех, кто **уже купил** — не случайных людей. Минимум ~10 вопросов на интервью, интервью ~30 минут.

Если своей базы для интервью нет — платные респонденты в телеграм-каналах «Коридорка CustDev», «CustDev-чат UX Boost» (порядка 500 ₽ за подборку под нужный профиль); сбор ответов — Google Forms.

**Скрипт проблемного интервью:**
```
1. Как вы сейчас решаете свою потребность?
2. Каким продуктом пользуетесь сейчас, довольны ли?
3. Когда планируете купить?
4. Как поймёте, что продукт оправдал ожидания?
5. В каком случае оставили бы отзыв о компании?
6. Какими ещё способами могли бы решить потребность?
7. Что потеряете, если продавец не решит вашу потребность?
8. Какие действия продавца вызывают неудобство/неприятие?
9. Какие трудности возникают при выборе/покупке?
10. Расскажите про сложный опыт покупки аналогичного продукта.
11. Что хотели сказать/сделать, когда продавец не понял запрос? А когда понял и предложил хороший вариант?
```

Результат CustDev — не только доработка продукта, но и прямой вход в настройки Директа (интересы, площадки, медиапотребление ЦА) и в тексты объявлений.

### 4P / 4C — рамка перед запуском рекламы

| 4P (продукт, 1960-е) | 4C (потребитель, 1990-е) |
|---|---|
| **Product** — ассортимент/продуктовая матрица | **Consumer** — нужды и ценности клиента во главе угла |
| **Price** — цена + акции + программы лояльности | **Cost** — воспринимаемая ценность vs цена: если ценность выше цены в восприятии клиента, продукт продаёт себя сам |
| **Place** — канал продажи (онлайн/офлайн) + люди-продавцы (скрипты, контроль доходимости заявок до менеджеров) | **Convenience** — удобство покупки/оплаты/доставки |
| **Promotion** — выбор канала продвижения (Директ подходит не всем нишам — иногда нужен ВК или другой канал) | **Communication** — tone of voice, допустимые формулировки |

**Правило перед настройкой Директа:** технически идеальная кампания не спасёт при слабом продукте, неконкурентной цене или нерелевантном лендинге. Сначала — анализ рынка/конкурентов (их ключевые слова, форматы рекламы, цены), потом настройка.

### Бриф и погружение в бизнес клиента

Заполняется вместе с клиентом на созвоне (screencast), не в одиночку. Блоки:

| Блок | Ключевые поля |
|---|---|
| Общее | города работы, адрес, время работы, приоритетные направления/товары |
| Портрет клиента | B2B/B2C, розница/опт, кто точно клиент / кто точно НЕ клиент |
| Конкуренты | 3–10 названий — пригодится в настройке рекламы |
| Продукт | преимущества/недостатки vs конкуренты, УТП, кейсы, акции, ценовая категория |
| Маркетинг/продажи | CRM есть/нет, каналы привлечения и их эффективность, средний чек, **LTV**, сезонность, частота покупки, срок принятия решения, путь клиента |
| Аналитика | общий бюджет на продвижение, IP-телефония, **коллтрекинг** (динамический — привязка звонка к конкретному ключевому слову/креативу), сквозная аналитика до продаж, **ROI** (окупаемость бизнеса) vs **ROMI** (окупаемость именно рекламы) |
| Контекстная реклама | опыт рекламы раньше, текущий **CAC** (стоимость реального клиента), **CPL** (стоимость квалифицированного лида), конверсия сайта, бюджет/мес, гео, «сленговое» название продукта (важно для семантики — «стиралка», не только «стиральная машина») |

**Дополнительные источники (кроме брифа):**
- продуктовая матрица от клиента с указанием, что продаётся активнее;
- скрипты продаж (в т.ч. отдельно скрипт обработки входящего звонка с рекламы: контакт → квалификация → выявление потребности → презентация → отработка возражений → закрытие);
- прослушка 30–50 звонков (если есть запись) — частые проблемы/возражения;
- если записи нет — обзвон ~50 клиентов клиента под легендой «оценка обратной связи» (по согласованному с клиентом скрипту);
- интервью с менеджерами по продажам, готовый FAQ;
- Вордстат для анализа спроса и популярных характеристик продукта;
- анализ сайтов конкурентов;
- «тайный покупатель» — фрилансер обходит конкурентов клиента с проблемными вопросами, либо обзвон конкурентов напрямую.

**Правило:** всё, что клиент рассказал в брифе/интервью, но чего нет на лендинге — сигнал дорабатывать лендинг, а не только настройки Директа.

### Сегментация ЦА

Виды: по продукту, по клиенту, по цене заказа, по географии. Сегментировать — только там, где различие ЦА реально выражено (пример: заказчики бассейна за 300–500 тыс. ₽ и за 1–1.5 млн ₽ — разный портрет).

**Чаще всего — сегментация по продукту** (почти в каждом бизнесе есть продуктовая матрица). Таблица по каждому продукту:

```
- название продукта (+ синонимы/жаргон, важно для семантики)
- срок принятия решения о покупке
- частота покупки
- сезонность
- средний чек
- приоритетность/маржинальность (шкала 1–10)
- на кого нацелена услуга (сегмент B2B/B2C)
- факторы покупки (отсрочка платежа, цена, сроки), что останавливает
- целевое действие на сайте (должно требовать минимум усилий от пользователя,
  напр. онлайн-расчёт стоимости — проще, чем звонок)
- соотношение звонков к заявкам
```

**Кейсы-паттерны сегментации:**
- *По жизненной ситуации/возрасту* (риэлторское агентство): у каждого сегмента свой ЛПР и **ЛВПР** (лицо, влияющее на принятие решения) — напр. в молодой семье решение принимает женщина (ЛПР), мужчина влияет (ЛВПР); и свои критерии выбора → своё позиционирование и канал.
- *По услуге, не по возрасту* (банкетный зал): свадьбы / банкеты / юбилеи / корпоративы / обеды навынос — у каждой услуги своя ЦА и причины покупки.
- *Новый сегмент из запроса клиентов* (фитнес-центр): продуктовая линейка родилась из прозвона текущих клиентов, а не «сверху».
- *По возрастной группе и цели* (детский центр): раннее развитие / подготовка к школе / английский / доп. специалисты — у каждой своя ЦА и критерии выбора.

**Итог сегментации используется для:**
1. упаковки каждого продукта на лендинге/в оффере;
2. текстов объявлений в Директе (отдельное объявление под сегмент, не одно на всех);
3. сбора семантического ядра отдельно под каждый сегмент.

### Сквозной принцип модуля

Рабочая цепочка: **бриф → CustDev/интервью → анализ отзывов → RFM/ABC → сегментация ЦА → семантика и объявления в Директе → доработка лендинга.** Каждый этап физически меняет настройки следующего — это не разрозненные методики, а последовательный процесс перед и во время настройки рекламы.

## Лендинги и конверсия

### Структура первого экрана

Первый экран решает три задачи: показать позиционирование, дать доступ к пути клиента через меню, закрыть главную боль дескриптором.

**Дескриптор** — первый заголовок сайта, формула: услуга + выгода + гео/срок. Примеры: «Установим ГБО на авто от 3 часов в Ставрополе», «Экономьте на бензине от 80 тыс ₽/год».

**Где размещать продукт:** не выше 3-го экрана — кроме двух случаев:
- бизнес отталкивается от продукта → продукт сразу на первом месте;
- бизнес отталкивается от проблемы → трёхступенчатая подача: проблема → факт → механизм (пример Volvo: статистика аварийности → «безопаснее на 80%» → технологии).

**Форма заявки:** открытая форма (поля видны сразу) конвертит лучше закрытой (поля скрыты за кнопкой) — у закрытой на шаг больше, человек заранее не знает объём полей. Правило — минимум полей: в форме «заказать звонок» оставлять только телефон, «обязательное» с имени снимать в настройках, имя и бюджет выяснять по ходу диалога.

### Чек-лист блоков конверсионного сайта

| Блок | Задача | Как оформить |
|---|---|---|
| Знакомство с компанией | Снять недоверие к «новому» продавцу | Дублировать в тексте + видео + виртуальный тур |
| Обращение директора | Персонализация | Видео и/или текст |
| Сегментация «для кого мы» | Разные аргументы под разные ЦА | Отдельный подблок на каждый сегмент |
| Кейсы | Соц. доказательство «мы не первый раз» | Формат до-после: задача → потребность → решение → сложности → кто занимался |
| Отзывы | Доверие | Видео > скриншоты из соцсетей (указывать число подписчиков, если блогер) > благодарственные письма с печатью. Текстовый отзыв форматом «простыня А4» — не работает |
| FAQ | Снять возражения на входе | Вопросы брать у отдела продаж — это реальные вопросы клиентов, а не выдуманные |
| Этапность работ | Для услуг с последовательными этапами (кухни, лестницы, двери) | Весь путь от заявки до монтажа |
| Гарантии | Снизить риск решения | Не «гарантируем качество», а конкретное действие на конкретный случай («не подошёл размер → сделаем то-то») |

**Призывы к действию:** не в каждом блоке подряд — через один экран (иначе баннерная слепота на CTA). Формулировка каждый раз разная, действие одно и то же: «получите 2 КП», «опишите задачи — предложим решение», «видеосозвон».

**Дополнительные триггеры доверия** (использовать точечно, не все сразу): продукт в цифрах («1720+ пациентов восстановили зрение»), ограниченный тайминг (работает для чека ~10–20 тыс ₽), онлайн-чат и виджет обратного звонка, авторские фото вместо стоковых, storytelling от первого лица клиента, карты (Я.Карты/2ГИС) с рейтингом, прайс в открытом доступе, калькулятор/конструктор — вовлекает в диалог вместо монолога.

🤔 Норматив «клиент ждёт звонка 10–15 минут, потом уходит к конкуренту» — авторская оценка лектора, не подтверждена исследованием, использовать как ориентир, не как факт.

### UX/UI и подача текста

- UI — визуал (цвет, кнопки), UX — расположение блоков.
- Вёрстка каждого следующего экрана должна визуально отличаться от предыдущего — иначе баннерная слепота.
- Текст не сплошным полотном — 2–4 колонки или «шахматная» раскладка (текст/картинка/кнопка по диагонали).
- Кнопка CTA — заливка цветом (solid), не обводка; цвет контрастный к палитре сайта, а не в тон.

### Квизы

**Квиз** = сайт-опросник. Отличие от квиз-лендинга: квиз занимает только первый экран или всю страницу целиком; квиз-лендинг — многоэкранная структура (2–5 экранов), где квиз лишь один из блоков.

**Обязательные элементы первого экрана квиза:**
1. Обращение на «вы».
2. Заголовок-обещание + время прохождения («Пройдите тест за 2 минуты и узнаете стоимость…»).
3. Явный список выгод от прохождения (КП с вариантами, скидка, сценарий).
4. Пульсирующая CTA-кнопка.

**Нормативы:**
- Максимум 10 вопросов, идеально 4–6 — короче квиз → выше % полного прохождения.
- Средняя конверсия квиза: 1–10% в зависимости от ниши. 🤔 «Раньше было 15–20%» — субъективная оценка лектора, не подтверждённый факт.
- Финальный блок обязан продублировать все выгоды с первого экрана — типичная ошибка их не повторить.
- Страница благодарности — персонализированная под сценарий (расчёт / купон / консультация / каталог), не одна универсальная на все случаи. Текст должен буквально повторять то, что обещали в процессе прохождения — иначе ощущение обмана.

**Формирование вопросов:** сценарий согласовывать с отделом продаж — вопросы должны быть теми, что реально задают клиенты при обращении. После каждого ответа — микромотивация (поп-ап со скидкой).

**Рекомендуемая структура квиз-лендинга:**
1. Оффер с УТП.
2. Портфолио/кейсы.
3. Отзывы.
4. Видео о компании/производстве.
5. Квиз.

Причина, почему квиз-лендинг конвертит лучше «голого» квиза: прогревающие экраны (кейсы, отзывы) уже отрабатывают возражения до момента заполнения — «голый» квиз даёт холодный, не готовый к покупке лид.

**Инструмент:** MarkViz — конструктор без дизайнера/верстальщика, сборка 10–60 минут, тарифы по числу заявок в месяц, готовые шаблоны по нишам, есть бесплатный обучающий курс («курс марквиз» в поиске).

### Как найти квизы конкурентов

1. Google/Яндекс-дорк: `site:2.markviz.me <ключевое слово>` — под другой конструктор подставить его домен.
2. Таблица анализа: запрос → квиз → вопросы → варианты ответов → домен.
3. Пройти 5–10 конкурентных квизов, зафиксировать вопросы/ответы и визуальные приёмы (например индикатор растущей скидки по шагам).
4. Свести самые повторяющиеся вопросы, скомбинировать под свой продукт, согласовать с отделом продаж.

### Позиционирование

**5 вопросов для формирования позиционирования компании:**
1. Чем отличается от остальных?
2. В чём первая (одна из первых) на рынке?
3. Каким предложением её вспоминают клиенты? (метод получения ответа — обзвонить клиентов и спросить, какими словами вспоминают)
4. С кем работаете и с кем точно нет?
5. Что делаете и чего не делаете?

**Тест на наличие позиционирования:** спросить клиентов/сотрудников «чем вы отличаетесь от конкурентов?» — внятный ответ есть → позиционирование есть, нет ответа → позиционирования объективно нет.

**7 рабочих стратегий позиционирования (с примерами):**

| Стратегия | Пример |
|---|---|
| То же самое, но иначе | Тинькофф — банк без офисов |
| Лучший для конкретной ЦА | Точка — банк для предпринимателей |
| Лучший в решении конкретной задачи | Яндекс.Такси — уехать за 5 минут |
| То же самое, но премиум | Азбука Вкуса |
| Без лишнего («не плати за то, что не нужно») | Победа — без питания и багажа в базе |
| Уникальная технология | Skyeng — обучение по Skype |
| По аналогии | Whoosh — «как Uber, но для самокатов» |

Ключевой тезис: позиционирование — всегда сознательный отказ от части аудитории (японский ресторан не продаёт пиццу).

### УТП

**4 шага для вывода УТП через конкурентов:**
1. Определить продукт и важные для клиента характеристики через отзывы, комментарии, сайты конкурентов, аналитику.
2. Отобрать 5–10 характеристик, ранжировать по важности.
3. Сравнить себя с 3–5 конкурентами по этим критериям.
4. Где сильнее конкурентов — то и есть УТП.

**8 формул УТП** (с примером «дизайнерские детские кроватки»):
1. Рациональный аргумент, чаще заходит мужчинам: измеримые факты — «прослужит 10+ лет», «48 000 продано, 2000 отзывов».
2. Рассрочка без переплат — «решение за 5 минут по фото паспорта».
3. Рациональный + эмоциональный, чаще заходит женщинам — «20 цветов, подберите под интерьер», апелляция к образу жизни.
4. Короткий факт-крючок — «своё производство, 6 моделей».
5. Превосходство/сравнение — «единственная компания в регионе», «гарантия 20 лет — больше нет ни у кого».
6. Узкая характеристика под узкий сегмент — «для ребёнка-аллергика».
7. Дополнительный сервис — «личный менеджер 24/7».
8. На страхе клиента — «текущая кровать небезопасна для ребёнка».

**Формула ценностного предложения:**
```
Мы, компания [название], помогаем клиентам типа [сегмент]
в ситуации [ситуация] решать проблему [проблема]
с помощью [решение] и получать ценность [ценность].
```

Правило переноса на сайт: формулу НЕ размещать одним текстовым блоком-простынёй — каждый элемент (сегмент/ситуация/проблема/решение/ценность) разносится по отдельным экранам сверху вниз.

### Путь клиента (Customer Journey) и структура блоков

Проектируется после того, как определено позиционирование и ЦА — иначе блоки закрывают случайные, а не реальные возражения.

**Методика (пример «кухня на заказ»):**
1. Расписать стадии принятия решения (выбор стиля → выбор цвета → фотопечать → возражение «хочу готовую кухню»).
2. Под каждую стадию — свой контент-блок с УТП.
3. На верхних стадиях воронки — контекстная реклама по ключам уровня осознанности («стиль кухни», «кухня хай-тек») на информационную посадочную страницу с лид-магнитом (каталог стилей), чтобы удержать холодный контакт до готовности купить.
4. Каждое возражение закрывать отдельным контентом (пример: «дорого» → статья «из чего складывается цена»).
5. По статистике отвалов на каждом шаге (Метрика) — приоритизировать, какие блоки дорабатывать в первую очередь.
6. Страницу благодарности использовать как доп. точку контакта — ссылки на другой полезный контент.

Финальная проверка полноты сайта: пройтись по пути клиента и убедиться, что каждая потребность/возражение/страх закрыты конкретным блоком — иначе клиент уходит к конкуренту с более «разжёванным» сайтом.

### Воронка и юнит-экономика рекламы

Термины: **SR1** — конверсия клик → лид, **SR2** — конверсия лид → сделка.

**Пример расчёта (мотоциклы, РСЯ/Авито):** 10 000 показов → 500 кликов (CTR 5%) → 40 заявок (SR1 8%) → 4 сделки (SR2 20%).

**Метод расчёта допустимой стоимости лида и клика:**
1. Взять охват по ключевому запросу в Wordstat с указанием региона (это не число уникальных пользователей, а число показов объявлений с фразой).
2. Учесть ~5 показов на одного пользователя (авторский ориентир; в Директе нет лимита показов на юзера, в отличие от VK).
3. Через CTR получить клики из показов.
4. Через конверсию клик→заявка получить лиды.
5. Через конверсию лид→продажа получить продажи.
6. Зная CAC (допустимую стоимость привлечения клиента) и долю бюджета, которую бизнес готов вложить в рекламу от CAC — считать допустимую стоимость лида и клика.

🤔 Точная формула шага 6 в источнике изложена нечётко (реконструирована лектором на ходу) — при использовании в расчётах для клиента проверять логику заново, не копировать как готовую формулу. Итоговые цифры примера (лид ≤1500 ₽, клик ≤45 ₽ при CAC=30 000 ₽ и реинвестировании 30%) — иллюстрация метода, не универсальный норматив.

Типовой набор идентификаторов: `email`, `phone`, `chat`, `leadform`, `copyphone`, `click_zayavki`.

### Составные цели и порог обучения автостратегий

Если в неделю набирается мало конверсий (пример: 5 заявок + 2 звонка + 2 обращения в чат) — объединять их оператором «ИЛИ» в одну составную цель.

🤔 Автор называет число **10 достижений цели в неделю** как минимум для обучения автостратегии Яндекса — официальная документация Яндекса приводит разные пороги в зависимости от стратегии и периода оптимизации (обычно ориентируются на 10 конверсий за последние 28 дней, а не строго «в неделю»). Использовать цифру автора как ориентир, не как точный SLA — проверять по актуальной документации стратегии перед настройкой.

### GTM: базовые понятия

| Термин | Аналогия | Примеры |
|---|---|---|
| Тег | Ручка | Код Метрики, Pixel VK, колл-трекинг, коды квизов/чатов |
| Триггер | Условие, когда писать ручкой | Клик по всем элементам / только ссылкам, глубина прокрутки, отправка формы, видимость элемента, пользовательское событие |
| Переменная | Цвет пасты | Click Classes, Click ID, Click URL, Click Text, Click Element, Click Target |

**Перед началом работы:** GTM → Переменные → «Настроить» → включить **все** встроенные переменные, включая «Прокрутка и видимость» — иначе часть переменных клика останется недоступной в триггерах.

### Базовый паттерн установки любого тега

1. Скопировать код счётчика/сервиса.
2. GTM → Тег → «Пользовательский HTML» → вставить код.
3. Триггер `All Pages` (если тег должен грузиться на всех страницах).
4. Назвать тег понятно.
5. **Опубликовать версию контейнера** — без этого шага изменения не применяются.
6. Проверка: «Предварительный просмотр» → ввести адрес сайта → на debug-панели смотреть `Container loaded` / `Tag Fired` (не `Tag Not Fired`).
7. Проверить на второй странице сайта — тег должен грузиться и там.

**Повторяющаяся ошибка (дважды продемонстрирована в курсе):** правка тега/триггера без публикации новой версии контейнера → тег «не срабатывает», хотя логика верна. Публикация — обязательный финальный шаг после любого изменения.

### Разведка кликабельных элементов сайта (методика для целей по кнопкам)

1. Создать триггер «Клик — Все элементы» (`AllClicks`).
2. Открыть Preview, кликать по разным элементам сайта.
3. Во вкладке Variables смотреть, какие переменные заполнены: `Click Element`, `Click Classes`, `Click ID`, `Click Target`, `Click Text`, `Click URL`.
4. Приоритет идентификации: `Click ID` → иначе `Click Classes`.
5. Фиксировать находки в таблице: название кнопки → классы/ID/элемент.
6. Создать точечный триггер на основе находки (копия `AllClicks` с условием `Click Classes содержит [класс]`).
7. Цель в Метрике: JavaScript-событие с ID по правилу именования (см. выше).
8. Тег: `reachGoal` с этим ID → привязать к триггеру → опубликовать.

🤔 На платформе Tilda эмпирически выявлена закономерность: кнопки, **открывающие** попап-форму → `Click Classes` содержит `tn-atom`; кнопки **внутри уже открытой** формы (submit) → `Click Classes` содержит `t-submit`/`ts-submit`. Это платформо-специфичный паттерн (не задокументирован официально), переносится между Tilda-проектами, но требует повторной проверки на каждом конкретном сайте — не использовать как универсальное правило для других CMS.

### Готовые триггеры по каналам связи

| Канал | Тип триггера | Условие |
|---|---|---|
| Email | Клик — только ссылки | `Click URL` содержит `mailto` |
| Телефон | Клик — только ссылки | `Click URL` содержит `tel` |
| Мессенджер | Клик — только ссылки | `Click URL` **соответствует регулярному выражению** (готовый regex на домены WhatsApp/Telegram/Viber/Skype) |

Различие в debug-панели: событие называется `Click`, когда триггер настроен на «Все элементы», и `LinkClick` — на «Только ссылки». По факту одно и то же событие клика.

🤔 Копирование email и клик по email в курсе описаны как «одна и та же цель» — по смыслу это разные пользовательские действия (клик открывает почтовый клиент, копирование — Ctrl+C/ПКМ без перехода), и в готовом контейнере (см. ниже) они и правда разведены на разные события. Разводить эти цели в реальной настройке, не объединять по умолчанию.

### Отправка формы — 3 способа, по убыванию надёжности

| № | Способ | Когда применять | Настройка |
|---|---|---|---|
| 1 | Пользовательское событие `SubmitForm` | Tilda и платформы, генерирующие кастомное JS-событие с суффиксом | Триггер «Пользовательское событие» → `SubmitForm` + галочка **«Использовать регулярные выражения»** (суффикс у Tilda — произвольное число, напр. `SubmitForm_7131`) |
| 2 | Триггер «Отправка формы» с фильтром по классу | Нет чистого кастомного события, но у формы уникальный HTML-класс | `Click Classes содержит [класс конкретной формы]` — привязка не ко всем формам сайта, а к нужной |
| 3 | «Видимость элемента» (Element Visibility) | Блок «Спасибо» подгружается через AJAX без смены URL | ID элемента через F12, при отсутствии ID — CSS Selector (Copy selector в devtools). Минимальный % видимости — 50%. **Обязательно включить «Учитывать изменения DOM»** — без этого триггер не увидит динамически появившийся элемент |

### E-commerce разметка (для интернет-магазинов)

Настройка **требует разработчика** — самостоятельно без знания JS не делается. Роль маркетолога — сформировать ТЗ по мануалу Яндекса «Электронная коммерция Яндекс.Метрика».

Обязательные поля товара в `dataLayer`: `id`, `name`, `brand`, `category`, `price`, `quantity`, вариант (напр. цвет).

Типы событий (`actionType`): `impressions` (показ списка), `click` (клик по товару в списке), `detail` (просмотр карточки), `add` (добавление в корзину) и т.д.

Проверка: `?_ym_debug=2` в адресной строке → выполнить действие (добавить в корзину) → в debug-панели должно появиться событие с параметрами товара.

Поверх e-commerce ставить цели: просмотр товара, добавление в корзину, переход к корзине, удаление из корзины, оформление покупки.

### Аудит сайта под цели (методика прохода)

Идти по сайту сверху вниз (хедер → футер), фиксировать в таблице по каждому кликабельному элементу: расположение → действие по клику → **число шагов до конверсии** → тег GTM → ID цели → работает ли фактически → примечания.

Эвристика: чем меньше шагов до целевого действия — тем выше конверсия обычно.

Аудит вскрывает не только пробелы в аналитике, но и технические поломки сайта (неработающие кнопки, отсутствие визуальной обратной связи при копировании номера и т.п.) — фиксировать отдельно от целей.

### Мультитрекинг (колл-трекинг + мейл-трекинг)

**Когда ставить:**
- Колл-трекинг — если ≥30% обращений идут звонками.
- Мейл-трекинг — прежде всего для B2B, где клиенты пишут, а не звонят.

**Расчёт числа подменных номеров:** 1 номер покрывает до 100 посещений/сутки (500 посещений → 5 номеров). Смотреть **среднее**, не пиковое значение (Метрика → Отчёты → «Как часто» → «Посещаемость»).

**Установка через GTM:** тег «Пользовательский HTML» со скриптом сервиса, триггер `All Pages`.

**Синхронизация с Метрикой:** передавать в цели можно общей категорией (все обращения) или раздельно — ставить галочки на все типы сразу, даже если сейчас не используются (легче расширить структуру позже, чем переделывать).

**UTM-условия для канала переадресации (рекомендация автора):** `utm_source=yandex` + `utm_medium=cpc` — второй параметр повышает точность отсечения SEO-трафика от платного.

**Единый журнал лидов** фиксирует: номер, регион, посадочную страницу, источник вплоть до `utm_term` (ключевое слово/автотаргетинг), запись звонка, статус, ручную классификацию (лид/спам) — по сути мини-CRM для сверки с данными Директа.

## Сегментация аудиторий (Метрика + Аудитории)

### Универсальный алгоритм оценки сегмента перед созданием

1. В отчёте (обычно Вебвизор) применить фильтр.
2. Посмотреть общее число визитов по фильтру.
3. Наложить ключевую цель, посчитать % конверсии = визиты с целью / все визиты × 100.
4. Составить сравнительную таблицу по нескольким вариантам фильтра (например, порог активности >2 / >3 / >4).
5. Выбрать сегмент с лучшим балансом объём/конверсия — только после этого сохранить.
6. Дать сегменту прогрузиться в Метрике (Настройки → Сегменты, объём за 7/30 дней).
7. Директ → «Ретаргетинг и аудитории» → «Сегмент Метрики» → привязать к группе (ретаргетинг) либо использовать «Только похожие пользователи» (lookalike).

**Не создавать сегмент без проверки исторической конверсии** — узкий сегмент без данных не даст ни показов, ни выводов.

### Обязательные и типовые сегменты Метрики

| Сегмент | Источник | Применение |
|---|---|---|
| Отказы (обязателен на каждом проекте) | Вебвизор → «Визиты, в которых» → Отказ | Корректировка ставок «Целевая аудитория» **-100%** |
| Активность Вебвизора >2/>3/>4 (шкала до 5) | Вебвизор → столбец «Активность» | Выше активность → выше конверсия, но меньше объём: узкий high-CR сегмент — для прямого ретаргетинга, объединённый через «ИЛИ» — для lookalike в РСЯ |
| Время на сайте < порога | Отчёт «Директ: сводка» (бенчмарк среднего времени по проекту) | Минусовать -100% **только если** проверено 0 целевых конверсий в сегменте |
| Достигшие ключевой цели | Цель CRM/заказ | Исключать -100% из РСЯ, если бизнес одноразовый; НЕ исключать при повторных покупках |
| Номер визита >1 | Вебвизор, сортировка по номеру визита | Создавать, только если основная масса конверсий приходится не на первый визит |
| Пол/возраст | «Аудитория → Сводка → Характеристики» | Порог значимости — от ~100 целевых достижений на сегмент |
| Долгосрочные интересы | Отчёт «Аудитория → Долгосрочные интересы» (точнее среза «Характеристики → Интересы») | Смотреть в первую очередь абсолютное число целевых визитов и конверсию, Affinity Index — вторично |
| Источник трафика (SEO/соцсети/прямые) | «Источники → Сводка» | SEO-трафик считается более «лояльным» — отдельная группа объявлений |
| URL входа / просмотра | «Обзор» → «Просмотр URL» / «Страница входа» | Ретаргетинг на посетителей конкретной статьи/услуги; сигнал для доработки страницы |
| Ecommerce: товар/категория/сумма/брошенная корзина | Отчёт «Электронная коммерция» (требует настроенного фида) | Окно «брошенной корзины» — 2-3 дня, не больше — «нет смысла гоняться за теми, кто не оплатил полгода назад» |

Отказ = визит короче 15 сек. ИЛИ 1 просмотренная страница. Вебвизор хранит данные максимум 2 недели.

### Яндекс.Аудитории: загрузка CRM и lookalike

**Требования к файлу:** CSV, минимум 100 записей, разделитель запятая/перевод строки/табуляция, UTF-8 или Windows-1251, ≤1 ГБ. Обработка сегмента — ориентировочно ~2 часа, может дольше.

**Доступ выдаётся только по Яндекс-логину** (не по произвольному email) — важно, когда Аудитории/Метрика/Директ на разных аккаунтах.

**Lookalike через Аудитории (не через Директ напрямую)** — 4 уровня точности/охвата, растущий объём: ~250 тыс. → 500 тыс. → 750 тыс. → 1–1.5 млн. Две опциональные галочки: сохранить распределение по городам / по устройствам.

```
Практика: создавать сразу все 4 варианта lookalike, называть с явным указанием
параметров, тестировать все — единого правильного варианта не существует.
```

**Ключевое отличие от lookalike в Директе:** через Аудитории объём аудитории на порядок больше (от 250 тыс.), через Директ — может быть пара сотен человек. Что лучше — тестировать per-проект, единого вывода нет.

**Объединение сегментов через «ИЛИ» vs «И»:** объединение нескольких вариантов lookalike через «выполнено хотя бы одно» — расширяет охват (пример: 324 600 человек). Пересечение через «не выполнено ни одного» (фактически узкая уникальная часть) — резко сжимает объём (пример: со 150 тыс. до 150 человек) — для расширения РСЯ использовать «ИЛИ», «И» — только при явном избытке показов.

**Порог обработки** сегмента Метрики → Аудитории: <100 целевых достижений — данных может не хватить.

### Геолокация в Яндекс.Аудиториях

| Тип | Настройка | Применение |
|---|---|---|
| Окружности | Радиус 500 м – 10 км от точки; типы: живёт / работает / регулярно посещает / сейчас находится / был N дней за период | Начинать с широкого радиуса (10 км) — маленький радиус работает хуже |

Можно загружать список точек массово (например, адреса конкурентов) вместо ручного ввода.

## МКБ и кампании на Поиске

### Логика трат бюджета по дням

Недельный бюджет (стратегии «Максимум кликов»/«Максимум конверсий») считается по календарной неделе пн–вс. Если РК стартует не с понедельника, весь бюджет делится на оставшиеся до воскресенья дни → средний дневной расход резко растёт. Пример: 10 000 ₽/нед, старт в пятницу → делится на 3 дня → до 3 333 ₽/день.

**Допустимый разовый перерасход дня:**

| Стратегия | Максимум сверх среднего |
|---|---|
| Ручное управление ставками | +30% от дневного бюджета |
| Автостратегия (недельный бюджет) | до 35% недельного бюджета за один день (обычно пн–вт) |

При смене стратегии перерасход суммируется. Пример: ручная (2000 ₽/день) → автостратегия (10 000 ₽/нед) в день перехода может списаться 2000+30% + 10000×35% = **5800 ₽**. Переход автостратегия→автостратегия считается по старому и новому недельному бюджету (35%+35%).

**Правило:** менять бюджет/стратегию/модель оплаты не чаще раза в неделю — каждая смена обнуляет расчёт и запускает его заново. Бюджет увеличивать плавно, шагами ~30%, не резко в 2–4 раза.

Оплата за конверсию: списание идёт в окне атрибуции **21 календарный день** — траты неравномерны, могут «выстрелить» пачкой за прошлые визиты. При выборе цели для оплаты — доступна только **одна цель**, остальные конверсии (звонки, чат, клик по телефону) становятся для рекламодателя фактически бесплатными.

🚫 Указывать недостижимую цель, чтобы «обмануть» алгоритм — приводит к **бану всего рекламного аккаунта**.

### Что перезапускает обучение автостратегии

Обучение занимает **2 недели**, порог набора — **10 конверсий в неделю** по целевому действию. Полный список триггеров переобучения:

1. Смена стратегии (Макс. конверсий ↔ Макс. кликов).
2. Создание пакетной стратегии на базе обычной 🤔 (по опыту автора работает плохо, но эффект мог измениться — проверять самостоятельно).
3. Смена модели атрибуции.
4. Смена модели оплаты (за клики ↔ за конверсии).
5. **Остановка кампании более чем на 7 дней** — обучение стартует заново, итоговая CPA может измениться в любую сторону.
6. Смена/удаление цели оптимизации.
7. Смена ценности целевых действий.
8. Массовое добавление ключевых слов (десятки–сотни).
9. Массовое переписывание объявлений.
10. Смена ГЕО.
11. Смена расписания показов.
12. Смена состава конкурентов (особенно критично для РСЯ).
13. Подключение новых форматов/площадок в ту же группу (например, товарная галерея или список организаций поверх поисковой кампании).

**Не триггерит рестарт, но стоит мониторить:** бюджет, средний CPC, CPA, ДРР (расходы/доходы × 100%, чем ниже — тем выгоднее).

**Практический вывод:** разные типы размещений (поиск / товарная галерея / список организаций) — в отдельные кампании, не смешивать в одну группу без крайней нужды (нехватка бюджета — единственное оправдание). Клиента предупреждать заранее: пауза пополнения счёта >7 дней = стратегия слетает.

### Ускорение обучения по целям

Три способа быстрее набрать 10 конверсий/неделю:

1. **Несколько целей одного «звена»** с разными назначенными суммами. Звено — набор действий одной глубины: «звонок» = копирование телефона + клик по телефону + звонок; «email» = копирование + клик + отправка; «форма» = клик по кнопке + заполнение полей + отправка. Реальную CPA делить пополам при назначении цены цели; если данных нет — звонок/форма ~1000 ₽, клик по телефону/email ~200–300 ₽ на старте.
2. **Составная цель в Метрике** (Цели → Составная цель, условие ИЛИ) — объединяет микроцели в макроцель. ⚠️ Не работает с автоцелями — только с целями через GTM/инфокатр.
3. **Коллтрекинг (Calltouch)** — в синхронизации с Метрикой можно передавать каналы (звонок, чат, заявка, email, квиз, виджет) раздельно или объединять по «холодности» (например чат+квиз в одну цель, звонок+заявка+email — в другую).

**Правила:**
- Перед объединением целей — проверять корреляцию микро- и макроцели (клик по номеру vs реальный звонок); без коллтрекинга эта проверка невозможна.
- Не смешивать цели **разного** звена (звонок + форма + квиз одновременно) — Директ не понимает приоритет, оптимизируется по цели с бо́льшей статистикой, игнорируя заданные суммы.
- Двигаться от простого к сложному: сначала одна макроцель, при нехватке данных — 2-3 микроцели одного звена.

### Группы, ключевые слова, автотаргетинг

**Группировка:**
- Многостраничный сайт → 1 группа = 1 посадочная/услуга.
- Лендинг/квиз → 1 группа = 1 свойство товара.
- 10–15 ключей на группу (лимит Директа — 200, см. таблицу лимитов ниже).

**Автотаргетинг на поиске:**

| Ветка | Категории | Логика внутри ветки |
|---|---|---|
| Тип запроса | целевые, узкие, широкие, сопутствующие, альтернативные | ИЛИ |
| Бренд | свой бренд, бренд конкурентов, без бренда | ИЛИ |

Между ветками — **И** (минимум одна галочка в каждой обязательна).

- 🚫 Широкие запросы никогда не включать — сильно сливают бюджет.
- Оптимальная связка при хорошо проработанной семантике: **целевые + упоминание своего бренда**.
- Запасной вариант при мусоре по целевым: сопутствующие + бренд → альтернативные + бренд (обычно мало показов).
- «Целевые + без упоминания бренда/брендов конкурентов» — вариант для слабо проработанной семантики, не рекомендуется как основной подход.
- При достаточном бюджете бренд/небренд разносить на **отдельные кампании**; при нехватке — на уровень групп.

**Минус-слова на группу** — использовать точечно (~5% проектов), когда слово нерелевантно именно этой группе (например «трал» минусуется только в группе «тракторы»). Основной объём минусовки — на уровне кампании.

**Перекрёстная минусовка:** Директ автоматически разграничивает пересекающиеся по составу ключевые фразы внутри объявления («перевозка спецтехники по России» vs «...цена» → авто-минус «цена» у первой).

**Проверка бюджета:** инструмент «Прогноз бюджета» в Директе. Заковычивание дорогого широкого ключа снижает требуемый бюджет и общую конкуренцию за него — компромисс: меньше кликов, но выше шанс низкочастотным длинным хвостам показаться при том же бюджете.

**Кластеризация Arsenkin** (Har2/Har3/Har4, чем выше цифра — тем детальнее разбивка) — используется для проверки ручной группировки, с ручной докорректировкой 1-2 неточно разложенных слов.

### Структура объявления на Поиске

| Элемент | Лимит | Практика |
|---|---|---|
| Отображаемая ссылка | 20 симв. | короткое универсальное слово, проверять обрезку на мобильном (видно ~3 буквы) |
| Заголовок 1 | 56 симв. | самые частотные уникальные слова группы (через «Анализ групп» в Директе) |
| Доп. заголовок | 30 симв. | только мобильный поиск; не дублировать смысл заголовка 1 |
| Текст | 81 симв. | — |
| Уточнения | 25 симв./шт | до 132 (десктоп) / 66 (мобайл) суммарно |
| Быстрые ссылки | до 8 шт, 30/60 симв. | используются и как способ занять больше площади в выдаче, не только для переходов |

**Правило минимум 2 объявления на группу:**
1. Больше данных для обучения автотаргетинга.
2. A/B-тест заголовков/текстов.
3. Позволяет распределить ВСЕ уникальные слова группы по двум объявлениям → напрямую снижает цену клика (см. раздел «Аукцион»).

Изображение/видео добавлять даже в кампанию на Поиске — Яндекс иногда подмешивает креатив в поисковую выдачу, плюс объявление обычно переиспользуется в РСЯ. Карусель (до 10 изображений) и кнопка — работают только в РСЯ, но готовятся заранее вместе с поисковым объявлением.

### Аукцион на Поиске. Биддер Elama

**Ключевой эксперимент:** два одинаковых по ключам объявления — с уникальными словами группы в заголовке vs с общим неконкретным заголовком. Результат: проработанное — ставка 416 ₽ / списание 283 ₽; непроработанное — ставка 540 ₽ / списание 349 ₽.

**Вывод: чем больше уникальных ключевых слов группы употреблено в заголовке/тексте — тем ниже требуемая ставка и списываемая цена по всем словам этой группы.**

**Раздельные ставки** доступны только на стратегии «Максимум кликов с ручными ставками»: отдельно на ключевые фразы, отдельно на автотаргетинг. Практика: ключевым фразам — например 700 ₽, автотаргетингу — 30 копеек (минимизирует его влияние, если ключи и так хорошо собраны). На автостратегиях (Макс. кликов/конверсий) ставку на автотаргетинг задать нельзя.

- Прогноз трафика 100% = показ на первой позиции; >100% (например 116%) = расширенные форматы (картинка, 8 быстрых ссылок).
- Прогнозируемый CTR закрепляется в реальный CTR через **28–30 дней** статистики — после этого прогнозные цены стабилизируются.
- Чем выше CTR — тем ниже требуемая ставка и списываемая цена.
- Позицию показов на автостратегиях (там нет прогноза/ставки в интерфейсе) смотреть через Мастер отчётов → срезы «средняя позиция показа», «средний объём трафика», «средняя позиция клика».

**Биддер Elama:**
- Работает **только** с кампаниями на Поиске и **только** со стратегией «Максимум кликов с ручными ставками».
- Готовые шаблоны: «100% трафика», «Максимальный трафик», 2-е/3-е/4-5-е место (85%/75%/65%), «внизу» (15%), фиксированная ставка.
- Логика: «если [ставка для нужного объёма трафика] < [заданный максимум]» → «то [ставка для объёма] + шаг (₽ или %, мин. 0.01)».
- Может ориентироваться на **списываемую цену**, а не только на номинальную ставку — этого нельзя сделать вручную через интерфейс Директа.
- Регистрация и пополнение бюджета через Elama даёт кэшбэк агентству.

🚫 Кросс-гео копирование семантики «в лоб» (например Москва → Петербург без адаптации) — не рекомендуется. Фиксация формы слова/порядка операторами в автоматическом режиме — не рекомендуется, только точечно.

### Минус-слова и минус-фразы

| | Минус-слово | Минус-фраза |
|---|---|---|
| Единица | одно слово | 2+ слова |
| Блокирует показ, если | запрос содержит слово | запрос содержит **все** слова фразы |
| Уровень задания | кампания, группа, ключевое слово | только кампания или группа |

Пример: минус-фраза «плохие отзывы» блокирует «купить кухню плохие отзывы», но НЕ блокирует «купить кухню отзывы» (совпало одно слово из двух).

**Приоритет ключевика:** если все слова минус-условия полностью входят в саму ключевую фразу — минус игнорируется. Проверка — в КейКоллекторе через «показать найденные фразы» по минус-словам.

**Фиксация словоформы** операторами (кавычки, `+`, `!`, `[]`) в минус-фразе не даёт ей игнорироваться в других склонениях/порядке слов. Пример: минус-фраза «купить слона» без фиксации блокирует «купить розового слона», но не блокирует «розовый слон купить».

**Практика:** минус-фразы использовать редко — в большинстве проектов достаточно минус-слов на уровне кампании, минус-слова на группу — точечно (пример: у группы «водоснабжение» минусуется «электричество» и наоборот).

### Лимиты Яндекс.Директа

```
Кампаний на аккаунт:            до 3000 (активных — не более 1000)
Групп в кампании:                до 1000
Объявлений в группе:             до 50
Ключевых фраз в группе:          до 200, до 4096 симв./фраза, не более 7 слов
Минус-фраз/слов на кампанию:     до 20 000 симв. без пробелов, не более 7 слов/фраза
Минус-фраз на группу:            до 4 000 симв. (в 5 раз меньше лимита кампании), до 7 слов/фраза
Мастер кампаний / моб. прил-я:   до 200 фраз на группу
```

**Практический вывод:** при выгрузке ключей из внешних сервисов (Букварикс, Key Collector, Мегаиндекс) обязательно фильтровать по лимиту 7 слов/фраза перед загрузкой в Директ.

### МКБ — медийно-контекстный баннер на Поиске

Медийная реклама с оплатой за клик справа от результатов поиска — единственный такой формат на странице, взаимоисключающий с товарной галереей (либо баннер, либо галерея). Бывший «Баян». Работает и как имиджевый инструмент (развитие бренда, продвижение акции), и как performance-канал — реально даёт звонки, особенно в «звонящих» нишах.

**Технические требования:**

```
Формат:   JPEG / PNG / GIF
Размер файла:  до 120 КБ
Габариты:      240×400 px 🤔 (в источнике встречается и 200×400 — вероятно оговорка; ориентир 240×400)
```

GIF предпочтительнее статики — привлекает больше внимания; 3–4 слайда с наложением работают хорошо на практике.

**Настройка** (режим эксперта → «Заметность в поиске Яндекса. Баннер справа от результатов поиска. Оплата за переходы»):

| Стратегия | Логика | Лимит |
|---|---|---|
| Оптимизация кликов | автоматическая, средняя/макс. цена клика | лимит трат в неделю |
| Ручное управление ставками с оптимизацией | ориентир на показы, виден аукцион как на обычном поиске | лимит бюджета в день |

Пример из практики: средняя цена клика 10 ₽, максимальная 100 ₽, лимит 7000 ₽/неделю. Тестировать можно от 7–20 тыс ₽/неделю — большие бюджеты не требуются.

**Правила:**
- Цель оптимизации — звонок (если на баннере указан телефон) либо переход на сайт (форму с баннера не отправить).
- Копировать минус-слова/фразы из поисковой кампании в баннерную.
- Группировка — по семантике направления, с отдельной посадочной и отдельным баннером под каждую группу.
- Приоритизация объявлений — «лучшее сочетание показателей», а не «наиболее близкие запросу» (баннер не требует 100% релевантности при большом числе ключей в группе).
- Биддер Elama применим только при ручной стратегии.

**Практика:**
- Тестировать минимум 2 разных баннера.
- **Обязательно указывать номер телефона на самом баннере** — большинство конкурентов этого не делает, а это даёт звонки без перехода на сайт; коллтрекинг — чтобы отследить звонки именно с баннера.
- Клик по МКБ часто обходится **дешевле**, чем клик по первой позиции обычной поисковой выдачи, за счёт уникальной неконкурирующей площади на странице.

### Поисковый ретаргетинг

Работает через оператор **И** с ключевыми фразами/автотаргетингом группы: пользователь должен и ввести целевой запрос, и одновременно удовлетворять условию ретаргетинга (например «посетил сайт»). Новому посетителю реклама не покажется, даже если запрос целевой.

Несколько условий ретаргетинга **внутри одной группы условий** работают между собой через **ИЛИ** («посетил сайт» ИЛИ «сегмент CRM»).

**LAL-сценарий:** через Яндекс.Аудитории (audience.yandex.ru) строится look-alike сегмент на базе своей аудитории (например, оставивших заявку) и подключается как условие ретаргетинга вместо/вместе с «посетил сайт».

🤔 Личная оценка автора (явно субъективная, за 9 лет практики): поисковый ретаргетинг использовался «пару раз», результаты слабые. Рекомендация — применять только при очень больших бюджетах (сотни тысяч ₽), когда обычная реклама на поиске уже упёрлась в потолок охвата и требуется дополнительное сужение отдельной кампанией.

## РСЯ, товарка, маркетплейсы, Telegram

### РСЯ — база

Более 50 000 площадок (сайты, приложения, Smart TV), среднесуточная аудитория РСЯ >65 млн, из них >50% не пересекается с поисковой аудиторией Яндекса.

**2 механизма таргетинга:**
- **Поведенческий** — человек искал на поиске → система «догоняет» рекламой на площадках РСЯ.
- **Тематический** — площадка релевантна теме объявления (даже без прямого запроса пользователя) либо просто входит в сеть (нерелевантная площадка тоже может показать рекламу).

### Запуск РСЯ с оплатой за конверсии (сценарий №1, приоритетный)

1. ЕПК → адрес сайта → тип «РСЯ»
2. Место показов: ручная настройка, только РСЯ, поиск выключить
3. Стратегия: **максимум конверсий с оплатой за конверсии** (не за клики — см. предостережение ниже)
4. Счётчик Метрики + цель оптимизации
5. Цена конверсии = недельный бюджет / 10
6. UTM, минус-фразы/доп. таргетинг — опционально

**Порог для старта сразу с оплатой за конверсии:** если по проекту (любой тип кампании) уже накоплено ≥10 достижений цели за 2 недели (≈20 конверсий/2 нед) — запускать РСЯ сразу с оплатой за конверсии, стратегия сходу знает целевой профиль.

**Формула недельного бюджета (сквозная для РСЯ/ретаргетинга/Telegram):**
```
недельный бюджет = целевая цена конверсии × 10
```

**Почему не «максимум кликов» на старте:** без накопленной статистики стратегия льёт показы на нецелевые площадки (игры, фильмы и т.д.).

### 7 типов таргетинга в РСЯ

| Тип | Как работает | Заметки |
|---|---|---|
| Автотаргетинг | Анализ контента сайта/объявления, без категорий (в отличие от поиска — там 5 категорий + 3 подкатегории бренда) | — |
| Ключевые слова | Релевантность площадки не важна, на цену клика не влияет | Группы можно укрупнять шире, чем на поиске |
| Интересы и привычки (Яндекс) | ~595 встроенных интересов, фильтр по ключевому слову | — |
| Интересы — сайты конкурентов | Вручную вписываются домены конкурентов | Чем точнее домены (узкая ниша, не общая категория) — тем точнее аудитория; слепое копирование списка от клиента снижает точность |
| Ретаргетинг по цели / look-alike | Похожие на достигших цель (например «CRM заказ создан») | — |
| Подбор по сегменту Аудиторий | Загруженная база CRM (телефоны) → look-alike | — |
| Комбинированные сегменты | «Похожие на посетителей», объединение нескольких целей через ИЛИ/И | — |

Перед созданием множества узких сегментов — сначала накопить статистику по укрупнённой цели, потом дробить.

### Оплата за клики + снижение доли мусорных площадок (сценарий №3)

**Когда переключаться:** РСЯ с оплатой за конверсии «не разгоняется» — мало показов/кликов через 5–7 дней при адекватном бюджете (бюджет = цена конверсии × 10). Если даже так нет показов — РСЯ, вероятно, не подходит проекту. Если >1000 кликов без единой конверсии — тоже сигнал переключаться.

При переходе — **копировать** кампанию, не переделывать: стратегия должна обучаться с нуля на новых настройках.

**4 способа снизить долю мусорных площадок, по значимости:**

1. **Минус-площадки** (единственный пункт, обязательный на 100%) — готовый накопленный список в «Запрет показов» на старте. Без него ≈90% показов на новых кампаниях с оплатой за клики уходит на нецелевые площадки.
2. **Минус-фразы** — сверяются с контентом площадки. 🤔 Эффект неоднозначен: в одних проектах Яндекс их учитывает, в других — нет, закономерность не выявлена. При оплате за конверсии можно не добавлять; при оплате за клики — рекомендуется на старте.
3. **Фиксация числа слов в кавычках** (оператор на всю фразу) для ключевых слов — не для автотаргетинга. Через интерфейс: группы → «Ставки и фразы» → выделить фразы → «Действия» → «Добавление операторов». Массово удобнее в Директ Коммандере.
4. **Корректировка «смартфоны» −100%** в разделе «Корректировки» — с мобильных чаще всего идут показы в играх/приложениях.

### РСЯ как копия поисковой кампании (сценарий №4, запасной вариант к сценарию №1)

1. Скопировать поисковую кампанию → сменить тип показов на РСЯ
2. Стратегию обязательно сменить на «Максимум конверсий», оплата может быть за клики
3. Ограничение расхода: **по бюджету** (без фиксированной цены конверсии — система может привести лид дешевле поиска) либо **по средней цене конверсии** = цена, что показал поиск
4. Таргетинг — только ключевые слова (единственный тип, в отличие от полного набора в сценарии №1)
5. Обязательные доработки под РСЯ: изображения ко всем объявлениям + смарт-центры, карусель, видео, возрастные ограничения, кнопка, проверка телефона/организации из Яндекс.Бизнеса

**Приоритет 3 сценариев РСЯ:** 1) оплата за конверсии → 2) копия РК с поиска → 3) оплата за клики с фильтрами (минус-площадки обязательны).

🤔 Авторское наблюдение (2024–2025, без привязки к документации): РСЯ у автора работает нестабильно — «как рандом»: в одних проектах цепляется с оплатой за конверсии, в других не даёт показов вообще, даже смена стратегии клик↔конверсия иногда не помогает. Контрастирует с наблюдением по ретаргетингу (см. ниже) — там результат стабильнее.

### Графические объявления в РСЯ

- 11 форматов креативов (3 мелких + 8 крупных); базовый размер грузить **×2 и ×3** (двойное/тройное разрешение).
- Встроенный конструктор: фон + смарт-центр, библиотека фонов, цвет/текст кнопки, лимиты текста (~60 символов основной текст, ~17 кнопка, ~75 доп. текст), возрастные предупреждения (БАДы, оружие, детское питание, финуслуги/ДДУ).
- **Ограничение инструмента:** графические объявления нельзя массово скопировать между группами — только вручную в каждой группе.
- Клик дороже, CPA в среднем выше, чем у текстово-графических. Использовать как точку масштабирования после того, как основная РСЯ уже стабильна и упёрлась в потолок.

### Ретаргетинг

Работает **только** через блок «Ретаргетинг и подбор аудитории» — ключевые слова и автотаргетинг не задействуются как основа (в отличие от обычной РСЯ, где look-alike — один из 7 типов).

**Запуск:** копировать РСЯ-кампанию → назвать «Ретаргетинг» → стратегия по тому же приоритету (сначала оплата за конверсии) → старые группы в архив, новые — под конкретные сегменты → проверить, что группы ушли на модерацию (при ручных манипуляциях может не произойти автоматически).

**10 сценариев ретаргетинга:**

| # | Сценарий | Особенность |
|---|---|---|
| 1 | Посетители сайта | + корректировка «отказы −100%» (визит <15 сек) |
| 2 | Достигшие цели кампании | встроенная авто-цель |
| 3 | Ранее заказавшие (CRM) | таргетинг именно на выбранную цель, не на «похожих»; окно до 540 дней. Для B2B с разовой сделкой эффективность под вопросом |
| 4 | Напоминание о компании | ведёт на главную/каталог/статью |
| 5 | Повторная покупка | для товаров с циклом (корм, вода, подгузники), окно ~30 дней, с акцией |
| 6 | Дожим незавершивших | зашёл в «Контакты»/скопировал телефон, но не позвонил; не завершил форму |
| 7 | По конкретной странице/услуге | сегмент строится через Метрика → Обзор → Просмотр URL → паттерн по разделу услуги |
| 8 | Брошенная корзина | «добавил в корзину» И НЕ «заказ оформлен» И визит <1 мес назад |
| 9 | Апсейл | мотивация на более дорогой товар через сравнение/инфографику |
| 10 | Кросс-селл | смежные товары/услуги; иногда — обмен базами с партнёрским бизнесом |

**Кейс (каркасные дома, чек 3–5 млн ₽):** цель «отправка формы/квиза», цена конверсии 2000 ₽, бюджет 20 000 ₽/нед. Протестировано 9 комбинаций таргетингов (автотаргетинг вкл/выкл × офферный ретаргетинг вкл/выкл × сегмент аудитории).

- Лучшая по CTR связка (автотаргетинг + «достигли цели» + офферный ретаргетинг): CTR 1.1%, CPA 2200 ₽ — не лучший по цене.
- **Простой сегмент «посетители сайта» + автотаргетинг выкл + не-отказы**: конверсия 1.89%, **CPA 1900 ₽** — лучше сложных комбинаций.
- Сравнение с поиском той же кампании: конверсия близкая (0.64% поиск vs 0.7% ретаргетинг), но **CPA с поиска ≈24 700 ₽ против ≈2300 ₽ с ретаргетинга** — разница на порядок.

Вывод: ретаргетинг с оплатой за заявки давал стабильный результат («ничем не сдувается»), в отличие от нестабильной обычной РСЯ. При этом высокий CPA с поиска может окупаться в unit-экономике конкретной ниши — оценивать не только по лидам, но и по реальным сделкам.

### E-commerce: фиды — основа всей товарной рекламы

Фид одновременно источник таргетинга и контента объявления (заголовок/текст/картинка/цена берутся из него).

**Способ добавления:** по ссылке, файлом или вручную. Ручной фид создаётся **только один раз**, потом лишь редактируется — годится для 5–20 SKU. При большом ассортименте — **обязательно YML** (по ссылке или файлом), не «фид по сайту».

| Тип фида | Макс. товаров | Автообновление | Фильтров доступно |
|---|---|---|---|
| Ручной | до 1000 | только вручную | — |
| Фид «по сайту» | до 100 000 | 1–4 недели (риск устаревших цены/наличия) | 5 |
| YML (по ссылке/файлом) | до 500 000 | 1–3 дня (оптимально) | 16 |
| CSV | — | — | больше XML, меньше YML |

Лимит фидов на аккаунт — до 50. ID каталога — до 20 символов.

**Ключевые атрибуты YML:** `id` (должен совпадать с `offer_id` эл. коммерции в Метрике — критично для офферного ретаргетинга), `type`, `available`, `name`, `type_prefix`, `vendor`, `model`, `categoryId`, `url`, `picture` (до 5), `description`, `sales_notes` (акции/условия), `param`, `price`, `oldprice`, `currencyId`, `video url`, `vendorCode`, `store`, `adult`, кастомные `custom_label`/`custom_score` — удобно для маркировки маржинальности по ABC-анализу для последующей фильтрации. Блок `Collection` (после Offers) — для объявлений «страницы каталога».

**Проверка микроразметки:** Яндекс.Вебмастер → «Валидатор микроразметки» (для страниц сайта) — отдельно от «Валидатора XML фидов» (тот про партнёрки Яндекса, не про рекламу). Неверная микроразметка → робот может генерировать объявления с ошибками (например, картинками).

**Плохие фото для фида:** схемы/инструкции, фото другого цвета/варианта товара, крупный план деталей, интерьер без акцента на товар, ракурсы с плохой видимостью товара. Норма — товар полностью виден, желательно на белом фоне.

**Формула заголовка/текста объявления из фида (сквозная для галереи, РСЯ-товарки, поиска):**
```
заголовок = name, либо model (+vendor, если влезает в 56 символов)
текст     = description, при нехватке места — + sales_notes
```

Рекомендация практика: качественный фид выгружается из CMS и дорабатывается вручную специалистом по фидам под ТЗ и требования Яндекса — делегировать, а не собирать вручную при масштабе.

### Товарная галерея на поиске

ЕПК → сайт → формат «Товарная галерея на поиске» → стратегия как для обычного поиска, e-commerce цель, минус-фразы.

**Управление авто-таргетингом (сквозной принцип и для галереи, и для товарных на поиске):**
- Расширить охват → включить «сопутствующие запросы» + «упоминания бренда» вместе с целевыми (работает через ИЛИ)
- Сузить, отдать приоритет заданным ключам → убрать сопутствующие и брендовые, оставить только целевые

Промоакцию можно не заполнять — в галерее показывается только картинка + цена + название, промо туда физически не попадает.

Фильтрация фида — по цене, модели, ID, каталогу, категории, наличию, vendor. Под каждый фильтр/сегмент — отдельная группа объявлений (например, отдельно по вендору).

«Страницы каталога» как формат требуют отдельного блока `Collection` в фиде — без него объявление не создать.

Для интернет-магазина в первую очередь — объявление в товарной галерее (базовый шаг).

### Товарные объявления в РСЯ (офферный ретаргетинг)

ЕПК → РСЯ, ручная настройка → оплата **за клики** (не за конверсии, в отличие от галереи) → минус-площадки можно не использовать, т.к. работает офферный ретаргетинг.

**Ключевая настройка группы:** галочка «Офферный ретаргетинг» — пользователи, ранее смотревшие товары на сайте/в приложении, видят товарное объявление в РСЯ. Из 4 форматов (графические/текстово-графические/товарные/страницы каталога) для этого сценария — предпочтительны **товарные**.

**Жёсткое правило разделения таргетингов внутри РСЯ:**
- офферный ретаргетинг → отдельная группа, без своих сегментов ретаргетинга в ней же
- ретаргетинг по собственным сегментам → отдельная группа
- интересы/привычки → отдельная группа (или подгруппы: интересы Яндекса отдельно от доменов конкурентов, либо объединить через ИЛИ)
- в одной группе комбинируются только автотаргетинг + тематические слова + ключевые слова

Обычные текстово-графические объявления в РСЯ для e-com автор считает малополезными — предпочтительна связка «товарные + таргетинг».

### Товарные объявления на поиске (бывшие динамические)

ЕПК → сайт → «Реклама в поисковой выдаче». Тематические слова можно не добавлять вовсе — работает только автотаргетинг: система сама подбирает запросы по заголовкам/тексту/фиду, без ручного сбора семантики по тысячам SKU. Заголовок/текст берутся из фида → качество фида напрямую определяет качество авто-таргетинга. В отличие от галереи, здесь заполняются уточнения и быстрые ссылки.

Возможна глубокая сегментация фида: по цвету, размеру, цене, скидке, маржинальности (`custom_label`/`custom_score`), наличию — под каждый срез своя группа.

### Товарная кампания (Товарный Мастер кампаний)

Запускается через Мастер кампаний (не через ЕПК) → «Товарная кампания» — упрощённая точка входа, автоматически совмещает галерею + поиск + РСЯ.

- Фид подтягивается автоматически по ссылке на сайт либо выбирается вручную из библиотеки.
- Фильтрация ограничена **3 типами**: категория, производитель, цена (в ЕПК фильтров больше — используйте ЕПК, если нужна гибкая сегментация).
- Каталожные страницы — список URL автоматически или файл-шаблон (5 столбцов: URL, title, категория, description, price, картинки). Практический метод сбора URL — комбинировать фильтры на самом сайте (каждая уникальная комбинация = строка каталога).
- Объявление «про магазин» — 5 заголовков + 3 текста + изображения + видео + быстрые ссылки, как в обычном Мастере кампаний.
- Не дублировать атрибуты в заголовке (если vendor уже входит в модель — не добавлять его отдельно).

### Приоритет форматов для интернет-магазина (единое правило, повторяется в 3 уроках)

```
1. Товарная галерея на поиске
2. РСЯ, товарные объявления + офферный ретаргетинг
3. Ретаргетинг на собственные сегменты
4. Интересы и привычки / ключевые слова
5. Страницы каталога (обычно работают хуже — низкий приоритет)
6. Графические баннеры с разными таргетингами (доп. тест)
```

### Реклама на маркетплейсы (Ozon, Wildberries, Avito, Яндекс.Маркет) через Директ

**4 варианта организации трафика, от простого к предпочтительному:**

| Вариант | Плюсы | Минусы |
|---|---|---|
| Прямой трафик на карточку/магазин | Просто запустить | Полностью «слепая» оптимизация, аудитория теряется безвозвратно (повторная работа с ней невозможна), учёт вручную |
| Мастер кампании «Продажа на Marketplace» | Бесплатно, встроенная оптимизация на продажу (Ozon/Маркет) | Функционал ограничен тем, что даёт Яндекс, лендинг генерируется автоматически, слабо кастомизируется |
| Диплинки сторонних сервисов (напр. MOPS.IO) | Умный роутинг iOS/Android, ercode-маркировка, QR | 🤔 средний вариант по оценке практика («не такая уж прям хорошая история») |
| Собственный лендинг | Полный контроль, Метрика, сохранение аудитории для сегментов/ретаргетинга | Требует ресурсов на разработку |

**Запуск через Мастер кампании «Продажа на Marketplace»:**

1. Ссылка на магазин (несколько товаров) или на конкретный товар.
2. **Критично для Ozon:** нужна ссылка вида `ozon.ru/seller/...`, НЕ `ozon.ru/brand/...`. Найти: карточка товара → блок продавца (не производителя) → правая кнопка → открыть в новой вкладке → скопировать URL. Брендовая ссылка → ошибка, либо переключение на тип кампании «Conversion Traffic» (там доступна реклама бренда). Та же ловушка на Wildberries (интерфейс сначала подсовывает Brands, доходить нужно до Seller).
3. Фильтрация товаров по названию/описанию/цене/скидке, условия «содержит»/«не содержит» — донастраивать методом проб (пример: фильтр «кроссовки» − «кеды» всё равно цеплял кеды через совпадение в описании).
4. Интеграция с Ozon (для цели «максимум покупок»): Ozon → Настройки → API-ключи → Performance API → Client ID + Client Secret → вставить в Директ; Vendor-префикс из Ozon Аналитика → Внешний трафик, метка формата `yandex-cpc-vendor{X}`.
5. Цель кампании: «максимум покупок» (только при интеграции статистики продаж), «максимум целевых действий» (клики/звонки/сообщения) или «максимум кликов». Стратегия — доля от дохода (пример 20%) либо фикс за конверсию — считать от unit-экономики, не произвольно.
6. Микро-цели: «вовлечённый переход» (~30 ₽), «просмотр телефона/мессенджера» (~50 ₽).
7. Опция «принимать заказы по телефону/мессенджеру» требует указанного контакта — без него кампания с целью «максимум целевых действий» не создастся.

**Ограничение по площадкам:** оптимизация «до продажи» доступна только для Ozon и Яндекс.Маркета (через API). Для Wildberries и Avito на момент записи курса — нет, доступен только косвенный сигнал «вовлечённый переход».

**UTM во «Внешнем трафике» продавца** (у Wildberries — с февраля 2025): личный кабинет Seller → «Внешний трафик» → сформировать метку по формату площадки (для WB — начинается с ID продавца + `_utm_search`) → использовать метку и в мастере кампании, и параллельно в обычной РСЯ для расширения охвата с сохранением атрибуции.

Распределение трафика в мастере на маркетплейс — обычно ~90–95% в РСЯ, ~4–10% на поиск. 🤔 Промо-страница мастера кампании не проверяется заранее — становится видна только после запуска/модерации.

### Реклама Telegram через Директ

Два принципиально разных сценария: (А) реклама **сайта** внутри чужих Telegram-каналов через РСЯ, (Б) реклама **своего Telegram-канала**.

#### А. Реклама сайта в Telegram-каналах (место показа РСЯ)

ЕПК (режим эксперта) → место показа «Telegram-каналы» (бета). Объявление выглядит как обычный пост: картинка/видео, заголовок, текст, метка «реклама», ссылка на сайт.

**Требования Яндекса к каналам-площадкам:** ≥2000 подписчиков, канал создан >3 мес назад, публичный, публикации не реже раза в 2 недели, ≥500 просмотров за 48 часов на публикацию, аудитория РФ/Беларусь, контент на русском. Реклама появляется в течение 4 дней после запуска.

**Настройка:**
- Тестовый бюджет: 10 000 ₽/нед, максимальная цена клика для теста — 10 ₽ (рыночный диапазон 5–30 ₽ в зависимости от тематики/гео); минимальная недельная сумма по стратегии — 30 ₽ (легко не заметить в интерфейсе)
- Цель конверсии + цена цели: занижать относительно целевой на старте (например, ставить 1000 ₽ вместо целевых 2000 ₽), бюджет обучения = цена × 10
- Гео каналов — задавать шире (Россия целиком): многие каналы не указывают точный регион
- Тематики каналов — минимум 3, цена клика по тематикам 30–300 ₽

**Подбор тематик через Метрику (метод, не описанный в документации Яндекса):**
1. Метрика → Аудитория → Долгосрочные интересы (новая версия), период — квартал+
2. Смотреть по категориям уровня 1, фильтр по достижению цели/конверсии → выгрузка XLS
3. Повторить для уровня 2 и уровня 4.2
4. Включать тематику, если по ней реально есть конверсии в Метрике — даже нелогичную для ниши (пример: грузоперевозки + «игры»/«еда»/«фитнес» неожиданно давали конверсии)

**Ограничения объявления:** текст до 764 символов (абзацы, эмодзи), заголовок до 56 символов, картинка — вертикальный формат, максимум 1280×1280.

🤔 Каждый лишний шаг воронки (например, переход в канал вместо прямой конверсии) снижает итоговую конверсию — в Telegram кликают охотнее, чем на незнакомый сайт, но это не значит, что дальше будет целевое действие.

#### Б. Реклама собственного Telegram-канала — 3 формата

| Формат | Суть | Место |
|---|---|---|
| Мастер кампании «Продвижение Telegram-канала» | Реклама конкретных постов, оптимизация на вовлечённых читателей | автоматически |
| Обычный Мастер кампании (Конверсии/Трафик) | Ведёт на прелендинг с призывом подписаться | поиск+РСЯ |
| ЕПК, ручная РСЯ (режим эксперта) | Текстово-графические объявления → прелендинг | РСЯ |

**Настройка формата «Продвижение Telegram-канала»:**
1. Ссылка на канал → Директ подтягивает последние посты → вручную отсеять нерелевантные
2. Из оставшихся — редактировать: заменить изображение, переписать заголовок (лимит 56 симв.) и текст, релевантный конкретному посту
3. Обязательно указывать в объявлении, что это именно Telegram-канал
4. Таргетинг — как в обычном Мастере: регион, время показа (пример: МСК 10:00–22:00, будни/выходные, отдельно праздники), пол/возраст вручную, интересы/запросы по тематике канала, «сайты/компании/тема» — домены конкурентов и нишевых сервисов ЦА (пример: для аудитории бизнесменов — СБИС, Контур, nalog.ru)
5. **Устройства:** отключать компьютеры/ноутбуки, оставлять смартфоны (планшеты — по ситуации) — веб-версия Telegram не всегда доступна с десктопа, конверсия хуже
6. Подключить бота @yandexdirectbot администратором канала (`/start` → пригласительная ссылка → добавить ботом-админом) → статистика по каналу прямо в интерфейсе Директа
7. Стратегия оплаты: фикс за вовлечённый переход / средняя цена за неделю (рекомендуется) / без ограничения. Стартовать с минимума (~10 ₽ за переход), повышать при недостатке показов — слишком низкая цена может полностью остановить кампанию

**Кейс (Telegram-канал риелтора, недвижимость Сочи, ~200 000 ₽/мес, 3 формата параллельно):**

| Формат | Результат |

| РСЯ (ручная, ЕПК) | лучший — самая низкая цена подписчика |
| Обычный Мастер кампании | на втором месте |

## Оптимизация и автоматизация

### Правило X2/X3 — универсальный критерий принятия решений

Сквозной принцип для любого среза Мастера отчётов (кампания, группа, объявление, площадка, регион, устройство, пол/возраст, тип соответствия, заголовок/текст):

| Отклонение CPA сегмента от среднего по кампании | Действие |
|---|---|
| В 2 раза хуже среднего | Сигнал, присмотреться |
| В 3 раза хуже среднего | Отключать / минусовать / понижать ставку (почти всегда) |

Решение принимать только с учётом **абсолютного числа конверсий и объёма расхода** — не по 1 конверсии. Если дорогой сегмент даёт большую долю всех конверсий (пример: 60–70% заявок кампании) — не отключать, даже при 2-кратном превышении CPA. Для регионов/устройств/пола-возраста предпочтительна **корректировка ставки**, а не полное отключение, если сегмент даёт хоть какие-то конверсии; жёсткое исключение (минус-регион, отключение площадки) — только при полном отсутствии конверсий.

**Пороги статистической значимости** (ниже — выводы не делать):
- Клики по фразе/площадке: минимум **3** (для 4-фильтрового метода РСЯ — минимум **10**).
- Достижений цели за неделю: минимум **8–10**, чтобы считать неделю пригодной для сравнения/оптимизации.
- Объявление/группа: < 10 конверсий — «недостоверные данные».

### Еженедельный контроль позиций и охвата (Поиск)

Мастер отчётов → группировка «за период» → цель → столбцы: средняя позиция показа, средняя позиция клика, отказы → фильтр площадка = «Поиск».

- Снимать не чаще **1 раза в неделю** — стратегии обучаются в рамках недельного бюджетного цикла, более частые срезы бессмысленны.
- Хотим больше трафика / выше позицию клика → поднимаем недельный бюджет.
- Клик обычно происходит на позицию **выше**, чем средняя позиция показа.

### Чистка поисковых запросов

Ежедневно в первые дни после запуска, далее реже. Отчёт «Поисковые запросы» → срезы: поисковый запрос, условия показа, тип соответствия → фильтр по цели → фильтр «клики > 3».

- Отказы **15–20% — норма**, выше — разбирать вручную.
- Сортировать и смотреть **раздельно**: сначала пословное соответствие, потом семантическое.
- Хорошие нецелевые формулировки → добавить как ключевые фразы (Direct Commander: найти фразу → «Выбрать их группы» → добавить, следить за пробелами, `+слово` фиксирует предлог) → прогнать «Оптимизировать фразы → кросс-минусовка + склейка дублей».
- Нерелевантные слова → в минус-слова кампании. Если минус-слово — часть устойчивого сочетания (гео, название) — минусовать **фразой целиком**, не отдельным словом, иначе отсечёте целевые запросы.
- Ключевая фраза не может содержать **более 7 слов** (техограничение Директа).

**Сравнение семантики и пословного соответствия:** тот же отчёт, фильтр по типу соответствия отдельно, период от 90 дней → сравнить конверсию, CPA, отказы по правилу X2/X3. Отключать семантику целиком, только если она **и дороже в 2–3 раза, и не даёт значимого объёма заявок**. Если объём конверсий сопоставим с пословным — не отключать, чистить точечно минус-словами.

**Принудительный перевод фразы на пословное соответствие** (техника, не официальная функция Директа):

```
1. Direct Commander → «Заменить»: кавычки → пусто (во всех фразах)
2. Дописать в начало каждой фразы: [
3. Дописать в конец: ]
4. Заменить пробел между словами на: ] [
5. Предлоги внутри скобок не работают — заменить [по]/[в]/[с] на +по/+в/+с вручную
6. Проверить ошибки модерации (запрещённые символы внутри скобок)
7. Отправить на модерацию
```

🤔 Сторонний сервис «Работа с модификаторами» автоматизирует простановку скобок, но по опыту лектора путает фразы местами при вставке обратно — ручной способ через Commander надёжнее.

### Чистка площадок РСЯ и ретаргетинга — метод 4 фильтров

Порядок строго такой (чтобы не отключить площадки, которые всё же конвертят):

```
Фильтр 1 — Конверсии (сортировка по убыванию)
  есть конверсии → сравнить CPA с X2/X3
  1-2 конверсии + CPA×2-3 → отключить
  большая доля всех конверсий (напр. 60-70%) → НЕ трогать, даже при удорожании ×2

Фильтр 2 — Расход (только среди площадок БЕЗ конверсий)
  расход ≥ X2 цены цели, конверсий 0 → кандидат на отключение

Фильтр 3 — Отказы (клики > 10)
  порог 20% (до 25% приемлемо) → выше = в минус-площадки

Фильтр 4 — CTR площадки
  до 5% — норма
  5-10% — подозрительно, смотреть вручную
  >10% — почти гарантированно мусор/скликивание
```

Признак мусорных площадок: домены `.com` (часто DSP-паразиты), игровые/детские сайты — 🤔 наблюдение, не универсальное правило, проверять вручную.

Инструмент: Мастер отчётов (срез «Название площадки», для нескольких целей — обязательно через Excel, интерфейс не даёт фильтр по нескольким столбцам сразу) или встроенный отчёт площадок внутри одной кампании РСЯ (чекбоксы «Запретить показы»). Отсеянные площадки → список «Запрещённые площадки» в настройках кампании.

При росте отказов на одном условии показа с большим разбросом поисковых запросов (напр. 78 разных запросов на 1 условие) — сигнал избыточно широкого соответствия, разбирать до конкретных ключевых слов.

### Разбор по срезам Мастера отчётов — полный проход

Последовательность срезов для системного аудита кампании (к каждому — правило X2/X3):

Цель → Кампания → Группа → Объявление → Условие показа (тип соответствия/категория таргетинга) → **Регион таргетинга** (не «регион местонахождения» — таргетинг отражает выбор пользователя в Яндексе, а не физическое расположение) → Устройство/ОС → Пол/возраст → Формат объявления → Заголовок → Текст → Ссылки/страницы → для e-commerce: категория/производитель товара, ДРР, доход, прибыль → Платёжеспособность.

Частные наблюдения по срезам:
- **Тип устройства** — часто малоинформативен; **Тип ОС** информативнее (пример: mobile iOS давало CPA почти вдвое выше среднего → корректировка −30%…−50%, десктоп +10%).
- **Тип инвентаря** (баннеры/приложения/текстовый контент) — корректировок ставок нет, срез практически бесполезен для решений.
- **Формат объявления** — не отключать новый формат (видео/графика) сразу; давать шанс, пока расход не достиг X2 цены цели.
- **Заголовок/текст** — гипотезу-победителя масштабировать через Commander: выделить группы → «Заменить» → применить только к выбранным. При A/B-тесте распределять варианты «через один» по группам (нечётные — A, чётные — B).
- Проверять, что найденная «дорогая» фраза относится к **актуальной, не архивной** кампании — старые фразы «фонят» в отчётах за 90 дней.
- Конверсия в % сама по себе не критерий — важнее итоговая цена конверсии и объём (пример: РСЯ конверсия 0.36% против 17% на Поиске, но CPA сопоставим → РСЯ продолжали).

Массовые действия — через Direct Commander: отключение объявления (с проверкой, что в группе остаётся ≥1 активное объявление), замена ссылки только для отфильтрованной группы/категории, замена конкретной быстрой ссылки по номеру у всех объявлений группы.

### Регламент отчётности

| Периодичность | Что фиксировать |
|---|---|
| **Ежедневно** (особенно первые дни после запуска) | Остаток бюджета клиента, статус кампании, минус-слова (Поиск), минус-площадки (РСЯ, дать неделю на накопление статистики) |
| **Еженедельно** | Показы/клики/расход/отказы/CPC; по каждой цели — достижения, % конверсии, CPA за 2 недели + «есть прогресс / нет»; раздел «что тестировали» |
| **Ежемесячно** | Сводная таблица по проектам месяц-к-месяцу, пояснения терминов для клиента |

- Цель пригодна для оптимизационных выводов при **8–10+ достижениях за неделю**.
- Резкий скачок конверсий в отдельную неделю (напр. 20/нед → 40/нед) — провалиться на уровень «по дням», сверить аномальный день с CRM на предмет фейковых заявок.
- Оценка эффекта доп. форматов (список организаций, Яндекс.Карты) — отчёт «Вид размещения»: срез «Вид размещения» + «Тип площадки», сравнение CPA по X2 с общей ценой цели. Новым форматам (кампания «моложе» месяца) — не делать выводы по одной неделе, давать «второй шанс».
- Идеальная структура при достаточном бюджете — 4 раздельные кампании (Поиск / РСЯ / организации / Карты); при ограниченном бюджете — объединять форматы и рассматривать полное отключение слабых типов кампаний вместо распыления.

### Direct Commander — массовые операции

Структура рабочего окна (личный workflow, не документированная практика Яндекса): 1-й столбец — кампании, 2-й — группы/объявления/фразы/ретаргетинг, 3-й — настройки кампании. После выбора кампаний жать **«Получить все данные»**, а не «Основные данные быстро» — последнее не подтягивает ставки.

**Копирование кампании Поиск → РСЯ:**

```
1. Выбрать поисковую кампанию → Ctrl+C → Ctrl+V → переименовать
2. Регион, временной таргетинг — без изменений
3. Минус-фразы кампании — убрать (расширяет охват в сетях) 🤔 личная эвристика
4. Место показа: снять «поисковая выдача», оставить «РСЯ»; карты — только если бизнес привязан к локации
5. Вставить список минус-площадок → сохранить
6. Выделить все фразы всех групп → «Оптимизировать фразы» → «удалить минус-слова»
   (или «Заменить»: поле «Минус-слова» → искать все значения → заменить на пусто)
```

Прочие массовые операции: замена заголовка/текста/ссылки по выделенным объявлениям через «Заменить»; загрузка/замена изображений (текстово-графические — да, баннерные креативы — только через веб-интерфейс); фильтр «дочерние объекты содержат ошибки» для быстрого поиска проблем; звёздочка-приоритет для кампаний, требующих постоянного внимания.

**Известные ограничения Commander** (системные, не устранённые годами):
- Условия ретаргетинга можно только выбрать из существующих — создать новое нельзя.
- Стратегии называются иначе, чем в веб-интерфейсе, и их на одну больше (Commander: 4 варианта; актуальный интерфейс: максимум кликов / максимум конверсий / ручное управление с оптимизацией) — 🤔 при работе через Commander проверять итоговую стратегию в интерфейсе.
- Уточнения: подсказка Commander показывает лимит 66 символов, по факту актуален **132 символа (десктоп) / 76 (моб.)** — интерфейс инструмента устарел, ориентироваться на реальный лимит.
- После любой массовой загрузки — обязательно перепроверять кампанию в веб-интерфейсе (параметры, минус-фразы, регионы могут не подтянуться).

### Управление кампаниями через Excel

🤔 **Личная позиция лектора**: штатный Excel-механизм Яндекса (Инструменты → «Управление с помощью Excel») ненадёжен — прямая выгрузка/загрузка через веб-интерфейс сама по себе даёт баги (пример: скачанный без изменений файл при обратной загрузке дал ошибку «отсутствуют группы» для реально существующих групп). Загружать такой файл — **только через Direct Commander** («Импорт из буфера/файла»), не напрямую в веб-интерфейс.

Лимиты символов в упрощённом авторском шаблоне: заголовок 1 — 56, заголовок 2 — 30, текст — 81, отображаемая ссылка — 20, быстрая ссылка — до 30 символов, до 8 быстрых ссылок на объявление. Быстрые ссылки/уточнения/адреса рекомендуется заполнять один раз в интерфейсе на одном объявлении и копировать оттуда, а не вести в Excel (в шаблоне нет проверки лимита для этих полей).

**Итоговая рекомендация лектора** (около 1,5–2 лет практики): Excel-подход не использовать вообще, кампании создавать прямо в интерфейсе — одна группа с готовыми объявлениями (минимум 2 объявления в группе для A/B-теста), далее копировать группу и менять только ключевые слова + заголовок/текст, остальные элементы (быстрые ссылки, уточнения) оставлять общими. Технические ошибки синхронизации Excel/Commander/интерфейс, по его опыту, съедают больше времени, чем экономит табличный подход.

**Практически:** без сопроводительного письма и приложенных кейсов отклик теряется — на заказ в 30 000 ₽ уже 10 конкурирующих откликов.

### Партнёрский маркетинг

Кого искать: офлайн-агентства без компетенции в контексте, веб-студии/разработчики сайтов, которые не настраивают рекламу.

Схема оплаты партнёру:
- 50% от суммы первой продажи клиента (пример: чек 30 000 ₽/мес → 15 000 ₽ разово)
- + фиксированная ставка с каждого следующего платежа этого клиента (пример: 5 000 ₽ постоянно)

**Приём для холодного контакта:** не заходить сразу с предложением партнёрства — начать с нейтрального вопроса («Вы делаете сайты?»), чтобы собеседник по инерции принял вас за клиента, и только потом раскрыть суть. Телефоны брать с сайтов агентств/студий, писать напрямую в WhatsApp/Telegram, поддерживать контакт ~раз в месяц.

### SPIN-продажи для больших чеков

Последовательность из 4 типов вопросов, чтобы клиент «сам себе продал» услугу:

1. **Ситуационные** — выяснить текущее положение
2. **Проблемные** — выявить боль («заявки идут нестабильно»)
3. **Извлекающие** — усилить осознание («вы уже обзвонили всех клиентов холодными звонками?»)
4. **Направляющие** — подвести к решению («те, кто сам ищет вас, покупают охотнее?»)

Дальше — предложение теста: узкий бюджет на самые горячие ключи, чтобы клиент увидел качество заявок из Директа своими глазами.

### Структура кейса

**Короткий вариант:** проект и география → цели клиента → предложенное решение и почему → ограничения/трудности → вовлечённость заказчика → результат в цифрах → отзыв (скрин/видео) → срок сотрудничества → стоимость.

**Расширенный вариант:** как было до вас → кто в команде что делал → гипотезы и план → контрфактический сценарий («что если бы не сделали») → окупаемость → дальнейшие планы → кому подойдёт кейс → авторство (имена специалистов).

### Стратегии по этапу карьеры

- **Без кейсов:** бесплатный качественный видео-аудит сайта конкретного лида, отправленный напрямую — демонстрация компетенций без портфолио.
- **Для опытных:** первым тестировать каждый новый инструмент Директа на своих клиентах → оформлять кейс (PDF/PPT) → выступать на конференциях → предлагать кейс самому Яндексу для размещения на его площадках.
- 🤔 Совет «работать только по контрактам от 1 года, с высоким чеком, с крупными/международными клиентами» (цитата стороннего эксперта) — сам автор оговаривает: подходит только состоявшимся агентствам с доступом к тендерам, новичкам не применим.

### Комбинации таргетингов в ЕПК

Жёсткие ограничения платформы по типу размещения — не путать форматы между собой:

| Размещение | Доступные таргетинги | Форматы объявлений |
|---|---|---|
| **Товарная галерея (поиск)** | Только авто-таргетинг **или** тематические слова. Ретаргетинг/подбор аудитории — не отдельно, только в довесок к ним. «Интересы и привычки» недоступны | Товарные |
| **Обычная поисковая выдача** | Авто-таргетинг, тематические слова, поисковый ретаргетинг (тоже только в довесок к авто/ключам) | Текстово-графические, товарные, страницы каталога |
| **РСЯ** | Авто-таргетинг, тематические слова, ретаргетинг/подбор аудитории, интересы и привычки — любые сочетания | Текстово-графические, товарные, страницы каталога, графические |

**Практически:** если в товарной галерее или на поиске выбрать только ретаргетинг без ключей/авто-таргетинга — показов и кликов не будет, таргетинг обязательно нужен «с предлогом».

Для «интересов и привычек» по похожему сайту — указывать не только свой домен, а свой сайт + сайты конкурентов вместе, точность подбора аудитории выше.

**Мастер кампаний** классифицирует сайт как «товарный» по визуальным маркерам (цена, несколько фото, слайдер), даже если это не классический интернет-магазин — стоит проверять, как Яндекс видит сайт, прежде чем настраивать вручную.

Терминологическое соответствие для старых кампаний: динамические объявления = товарное объявление на поиске; смарт-баннеры = товарное объявление в РСЯ — сейчас объединены в ЕПК.

🤔 Гибридный формат ЕПК (поиск + РСЯ + карты одной кнопкой) — автор не рекомендует запускать, без развёрнутого обоснования в источнике.

### Офлайн-конверсии: связка CRM и Метрики

Цель — оптимизировать рекламу не по формальным конверсиям (клик по телефону, отправка формы), а по реально дошедшим до сделки/оплаты лидам.

| Способ | Когда использовать | Сложность |
|---|---|---|
| **Прямая интеграция CRM** (Битрикс24, AmoCRM) | Есть популярная CRM с настроенной воронкой продаж | Низкая — по инструкции Яндекса, без программиста |
| **Google Sheets** | Нет CRM или интеграция недоступна | Средняя — ручное/полуавтоматическое заполнение таблицы |
| **Client ID ↔ User ID через getClientID()** | Нужна максимальная точность, есть разработчик | Высокая — только с программистом |

**Через CRM:** Метрика → «Интеграции» → «Настройки и загрузка данных» → выбрать Битрикс24/AmoCRM → в CRM должна быть настроена воронка (этапы сделки). После подключения автоматически создаются 2 цели: **«CRM заказ создан»** и **«CRM заказ оплачен»**. Для мессенджеров (WhatsApp и др.) — сервис «Command F5» 🤔 (название неточно расшифровано в исходном транскрипте).

**Через Google Sheets:**
```
created_at   | phone          | status       | client_id | email | revenue | cost
2026-07-08   | "79991234567"  | in progress  | ...       | ...   | ...     | ...
```
- Обязательные поля: `created_at` (дата, затем время), телефон в формате `79XXXXXXXXX` (без скобок/дефисов; несколько значений — через запятую в кавычках без пробелов), `status`.
- Статусы: `pay` → цель «CRM заказ оплачен»; `in progress` → цель «CRM заказ создан»; `cancelled`, `spam` — не конвертируются.
- Опционально: `client_id`, `email`, `revenue`, `cost`. Прибыль = **revenue − cost**.
- Таблица — только на первой вкладке (остальные не читаются). Доступ «по ссылке» на email от Яндекса, право **«Читатель»**.
- Директ → Конверсии → Оффлайн-конверсии → указать источник, ссылку, счётчик, статус. Обработка источника — до 2 часов, дальше файл скачивается **раз в сутки** (обновлять ежедневно).

**Точность сопоставления по числу переданных идентификаторов:**

| Идентификаторы | % распознавания базы |
|---|---|
| Только телефон | ~30% |
| Телефон + email | ~40–50% |
| Только client ID | ~50–70% |
| Телефон + email + client ID | ~70–90% 🤔 (в источнике два расходящихся значения — «70%» и «80–90%» — фиксировать диапазоном) |

Client ID — самый весомый идентификатор из трёх.

**Практически:** не оптимизировать ставки по набору мелких целей (клик по телефону, копирование email, чат) — ориентироваться на одну сводную цель «CRM заказ создан», она объединяет все каналы и отсекает спам.

### Защита от фрода и ботов

| Сервис | Механика | Стоимость |
|---|---|---|
| **BotFactor** | Определяет фрод по поведению → передаёт Client ID в Яндекс.Аудитории → авто-корректировка ставок на сегмент | от ~990 ₽/мес + 1 ₽/переход сверх пакета |
| **ClickFraud** | Та же механика | от ~2 900 /мес (валюта в источнике неоднозначна — ₽ или $ 🤔), лимит до 10 000 визитов/мес на входном тарифе |
| **Click.ru (бесплатно)** | JS-код на сайт, оценка по скроллингу и частоте повторных визитов, статус «bot» при вероятности 50–100% (порог настраивается) | Бесплатно при пополнении бюджета Директа через Click.ru |

Все три работают по одной технической схеме: Client ID заподозренного бота → сегмент в Яндекс.Аудиториях → понижение ставки на сегмент в кампании.

**Ограничения:** ни один сервис не даёт 100% защиты, особенно на поиске (конкуренты могут скликивать с подменных IP — сервисы снижают проблему, но не решают полностью). Защита Click.ru — базовая (в первую очередь по скроллингу), не замена платным сервисам при серьёзном фроде.

**Альтернативный приём для РСЯ:** таргетинг на закупленные/спарсенные базы реальной аудитории по нише (пример источника для B2B — Planfix) вместо широкого авто-таргетинга/ключей — снижает попадание в ботовый инвентарь. Дополнительно — обмен базами клиентов с партнёрскими бизнесами, загрузка через Яндекс.Аудитории.
