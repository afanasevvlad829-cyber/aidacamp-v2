## 1. Попадание в ответы ИИ (GEO)

Источник: [«Как попасть в ответы ИИ: работающие методы и мифы»](https://vc.ru/seo/3093567) (24.08.2026).

**Как устроено:** ИИ-системы не ходят по вебу сами — берут кандидатов из готовых поисковых
индексов (в первую очередь Bing), реранкер отбирает фрагменты, из них собирается ответ со
ссылками. Следствия:

- **Без топ-20 в обычной выдаче в ответы ИИ не попасть.** GEO — это прежде всего обычное SEO.
  Но внутри топ-20 реранкер может предпочесть нас «динозаврам» из топ-3, если семантика
  проработана лучше: у ИИ-ответов нет пиетета к возрасту хоста и ссылочной массе.
- **Скорость ответа сервера критична.** ИИ-агент не ждёт как гуглобот: медленный ответ →
  обрыв соединения → код 499 в логах nginx. В Метрике/GSC этого не видно — **смотреть access-логи
  на 499 от ИИ-ботов**.
- **ИИ-агенты не исполняют JS** (кроме части китайских). Наша Astro-статика — готовое преимущество.
- **Реранкеры любят плотные концентрированные фрагменты**: списки, таблицы, FAQ, атомарные
  утверждения. Первый экран / первые ~30% контента страницы решают — дальше модель может не читать.
- **Фрейминг**: соответствие типовому шаблону контента (структура, оформление, медианные
  значения текстовых зон) — один из сильнейших факторов. «Хотите в ответы — не выпендривайтесь».
  Отдельная посадочная под интент весит больше, чем релевантный блок внутри чужой страницы.
- **Машиночитаемость для ИИ ≠ машиночитаемость для роботов**: LLM видят поток токенов, а не теги.
  Нужна логическая прогрессия (проблема → контекст → решение), однозначные местоимения,
  атомарные факты. Вода и витиеватые периоды снижают шансы.
- **Заземление (grounding)**: учитывается то, что подтверждается другими источниками.
  Заявление «лучший лагерь» без внешних подтверждений — статистический шум.

**Что по Петрову НЕ работает для ИИ-видимости** (совпадает с гайдом Google и нашим скиллом):

- `llms.txt` — Ahrefs проверил 137 000 доменов: 97% файлов не получили ни одного запроса за месяц.
- Микроразметка Schema.org **для ИИ** — шум (ИИ извлекает сущности из текста). ⚠️ Для обычного
  поиска (сниппеты, FAQ rich results) микроразметка по-прежнему нужна — не путать, наш FAQPage-страж остаётся.
- Регалии и отзывы как таковые — внутри модели «экспертности» нет, есть плотность фактов и
  логический каркас текста.
- 🤔 Спорное: «структурирование контента и перелинковка не влияют на цитирование в ИИ» —
  влияют хотя бы косвенно через позиции в поиске, сам же и оговаривается.

**Экшны для нас:**
1. ✅ Проверено 31.08.2026: блок-листы (`deny-scrapers.conf`, `bot-block.conf`) ИИ-ботов не задевают,
   robots.txt всех сайтов открыты. Живой трафик за 2 дня: OAI-SearchBot 504, GPTBot 482,
   ClaudeBot 428, bingbot 342, PerplexityBot 215 хитов — все получают 200/301.
2. ✅ 499 от ИИ-агентов — ноль (31.08.2026). Попутно: ~70% «404 от GPTBot» — сканеры уязвимостей
   с поддельными UA ИИ-ботов, долбят голый IP (`/.env`, `/id_rsa`, даже `/config/anthropic.json`).
   При анализе логов ботов — сначала отфильтровать сканерные пути, потом делать выводы.
3. ✅ Починено 31.08.2026: реальный GPTBot просил `/sitemap.xml` по конвенции, а на vlad-a.ru и
   aidacodit.ru карта лежала только на `/sitemap-index.xml` → 404. Добавлен 301
   `/sitemap.xml → /sitemap-index.xml` в nginx обоих сайтов (бэкапы:
   `/etc/nginx/backups/*-20260831-sitemap`). **Правило:** на сайте с sitemap-index держать
   редирект с конвенционного `/sitemap.xml` — боты не читают robots.txt перед каждым визитом.
4. На ключевых лендингах: прямой ответ в первом экране, факты списками/таблицами — уже в скилле,
   усилить требование «первые 30% контента».

## 2. Накрутки ПФ — механика и риски

Источник: [«Накрутки ПФ: нужны ли они вам»](https://vc.ru/seo/2249895) (10.2025);
база: [«Накрутки поведенческих факторов: путь в топ или в бан?»](https://vc.ru/seo/203524) (2021).

**Механика оценки Яндексом:** профиль пользователя векторизуется (регион, пол, возраст,
долгосрочные интересы, паттерны) и сопоставляется с профилем сайта косинусной близостью.
Подозрительный профиль получает метку «бот» (~неделя): его активность не пишется в Метрику,
ему показывают капчу. Ботоводы «нагуливают» профили: сначала сайты без Метрики, потом смежные
тематики из поиска, только потом целевой запрос.

**Когда ПФ-накрутка осмысленна (по Петрову):**
- Сайт душится метками МПК (малополезный контент) из-за отсутствия трафика — трафик нужен любой ценой.
- Сайт в топ-10, но не в топ-5, ниша конкурентная и конкуренты крутят.
- Ниша высокочастотная — ботный трафик остаётся незначительной примесью к живому.

**Когда ПФ-накрутка хоронит сайт:**
- **Низкочастотная ниша**: ботов становится больше живых → Яндекс пересчитывает эталонный
  профиль аудитории сайта (и даже ниши!) на ботов → живая ЦА перестаёт матчиться, продажи падают
  при красивых позициях. ⚠️ Прямо релевантно нам: «детский IT-лагерь» — ниша узкая.
- Накрутчик не знает реальных медианных паттернов ЦА — лишние 5 секунд на сайте уже девиация,
  визит выбрасывается из учёта.
- «Настучанные» топы слетают так же быстро (минус ~год без всякого ручного бана).
  Оценивать динамику только на длинных периодах, не по скриншоту «прыгнули за день».

**Правило для нас:** перед любым решением по ПФ (докупить слоты / остановить) перечитать этот
раздел; для узких ниш (aidacamp) риск смены эталонного профиля аудитории перевешивает.
Связка с нашим опытом: кампания ПФ на codims — мониторить не только позиции, но и конверсию
живого трафика; обвал позиций aidacamp 07.07 — версию «ответка за ПФ-паттерны» держать в списке.

## 3. Тематическая карта и семантический граф

Источники: [«Тематическая карта как база в семантическом SEO»](https://vc.ru/seo/2833739) (03.2026),
[«Векторные вложения»](https://vc.ru/seo/1289590) (2024), [«Кластеризация как база SEO»](https://vc.ru/seo/1822250) (02.2025).

- Семантика ≠ список запросов из Вордстата. Тематическая карта — онтология темы: сущности,
  связи, вспомогательные страницы, **в том числе без поискового спроса** — они нужны, чтобы
  поисковик счёл сайт полноценным источником в теме (тематическая авторитетность).
- Пользователь часто не знает, что спрашивать: чем сложнее тема, тем меньше реальная семантика
  пересекается с запросами. Пробел в онтологии = потерянная конверсия (посетитель уходит гуглить
  незнакомый термин).
- Кластеризация по пересечению выдачи (наш метод через Арсенкина) — лексический подход;
  Петров дополняет кластеризацией на эмбеддингах. Методы совместимы: выдача — про «как сейчас
  ранжирует Яндекс», эмбеддинги — про смысловую полноту.
- Пример-антипаттерн: дорогая услуга, а на сайте нет базовых терминов отрасли (дизайн-проект,
  обмерный план) — сайт неполноценен и для поиска, и для клиента.

**Экшн для нас:** при следующем пересмотре кластеров aidacamp/codims проверить онтологию, а не
только запросы: покрыты ли «бесспросные» узлы (безопасность, медицина, питание, документы для
лагеря; методика обучения для школы).

## 4. Внутренняя перелинковка

Источник: [«Внутренняя перелинковка в SEO: актуальные практики»](https://vc.ru/seo/2059937) (2025).

- Принцип: **веб-граф (фактические ссылки) должен повторять семантический граф (смысловые связи)**.
  Хаотичные «ссылки по случаю» размывают кластеры.
- Кластер = хаб-страница (общая услуга) + вспомогательные узлы (подуслуги, цены, справка),
  плотно слинкованные между собой, даже если лежат в разных разделах сайта.
- Анкоры формируют контекст: релевантный анкор связывает страницы в семантический узел.
- Семантический кластер может включать страницы без запросов (см. раздел 3).

**Экшн для нас:** фаза перелинковки в seo-keyword-grinder — линковать по кластерам
(гео-лендинг ↔ возрастной лендинг ↔ смена ↔ FAQ ↔ цены), а не «каждый с каждым»;
анкор = ключ кластера, не «подробнее».
