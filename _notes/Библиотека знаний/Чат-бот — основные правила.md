# Чат-бот АйДаКемп — правила разработки

## Принцип №1: ТОЛЬКО ФАКТЫ, НИКАКИХ ГАЛЛЮЦИНАЦИЙ

**Симптом:** агент придумывает статистику ("45 мам записали", "4.9★ на Яндекс.Картах")  
**Причина:** LLM генерирует правдоподобные, но выдуманные данные  
**Правило:** любая цифра, факт, цитата — только из исходников ниже  

### Единственные источники правды

| Что | Откуда брать | Файл |
|---|---|---|
| Рейтинг | 5.0★ на Яндекс.Картах | `src/data/contacts.ts` → `STAT_RATING` |
| Количество отзывов | 40+ | `src/components/Reviews.astro` |
| Лет работы | 7 | `src/data/contacts.ts` → `STAT_YEARS` |
| Детей прошло | 1200+ | `src/data/contacts.ts` → `STAT_KIDS` |
| Возвращаются снова | 60% | `src/data/contacts.ts` → `STAT_RETURN` |
| Отзывы (текст) | Дословно, без изменений | `src/data/reviews.ts` |
| Наполненность смен | Реальные occupied/free/total | `src/data/shifts.ts` |
| Цены | Точные суммы | `src/data/shifts.ts` → price |
| Контакты | Точные номера/ссылки | `src/data/contacts.ts` |

### Что ЗАПРЕЩЕНО придумывать
- Любые цифры ("записали X мам", "X% довольны")
- Любые рейтинги кроме тех что в contacts.ts
- Любые отзывы кроме тех что в reviews.ts (даже "похожие по смыслу")
- Имена, истории, детали которых нет в данных

## Принцип №2: ОТЗЫВЫ — ТОЛЬКО ДОСЛОВНО

**Правило:** брать только из `src/data/reviews.ts`, поле `fullText` (полная версия) или `text` (краткая).  
Не перефразировать, не адаптировать, не "улучшать". Именно такой текст.

**Реальные отзывы (краткие версии для блоков):**

- **Сергей Найденов** (2 фев 2026): "Домой приехал загорелый, уставший и почему-то сразу полез смотреть про программирование на ютубе. Я не ожидал такого эффекта честно говоря."
- **виктория** (13 ноя 2024): "Едем уже третий раз, я даже не уточняю подробности — просто бронирую."
- **Natalia Savenkova** (10 ноя 2024): "Приехал домой и сам попросил записать его на кружок."
- **Надежда Ш.** (12 авг 2025): "Объяснял [проект] минут сорок без остановки, с горящими глазами."
- **Кристина** (8 ноя 2024): "Привезла распечатку скриншота [сайта про животных] и повесила на стену в комнате."

## Принцип №3: СРОЧНОСТЬ — ИЗ РЕАЛЬНЫХ ДАННЫХ

Данные наполненности смен берутся из `src/data/shifts.ts`:

```
Смена 1 (30 мая – 8 июн):   23 занято / 35 всего → 12 свободных мест
Смена 2 (10 – 23 июн):      41 занято / 45 всего → 4 свободных места  ← мало
Смена 2.1 (10 – 16 июн):    29 занято / 40 всего → 11 свободных
Смена 2.2 (16 – 23 июн):    37 занято / 45 всего → 8 свободных
Смена 3 (3 – 15 авг):       40 занято / 45 всего → 5 свободных
Смена 4 (17 – 26 авг):      31 занято / 45 всего → 14 свободных
```

**Правило:** "мало мест" показывать только когда free ≤ 5 (Смена 2 и Смена 3 сейчас).

## Принцип №4: БЛОКИ ИСПОЛЬЗУЮТ РЕАЛЬНЫЕ ДАННЫЕ

Каждый блок чата (`blockXxx()` в `ask.astro`) должен использовать только данные из единственных источников правды. Жёстко запрещено:
- Хардкодить выдуманные цифры в JS-функциях блоков
- Передавать выдуманные данные через `block_data` из systemPrompt

**Алгоритм добавления нового блока:**
1. Найти реальный источник данных в `src/data/`
2. Встроить или импортировать эти данные в блок
3. Только потом рисовать UI

---

## Принцип №5: АЛГОРИТМ РАБОТЫ АГЕНТА

**Перед любым ответом:**
1. Открыть `src/data/contacts.ts` — базовые факты
2. Открыть нужный data-файл (reviews.ts / shifts.ts / etc.)
3. Только потом формировать ответ или UI-блок

**Никогда не:**
- Отвечать из памяти о конкретных цифрах
- Придумывать "правдоподобные" данные
- Округлять/приукрашивать реальные числа
