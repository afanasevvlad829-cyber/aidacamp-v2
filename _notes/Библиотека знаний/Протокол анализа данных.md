### 1.2 Microsoft Clarity

#### Поведенческие метрики
| Метрика | Что значит | Порог тревоги |
|---|---|---|
| `scroll_depth` | Максимальная глубина прокрутки за сессию | < 30% на главной |
| `active_time` | Время активного взаимодействия (не AFK) | < 30 сек |
| `total_time` | Полное время на странице | — |
| `dead_clicks` | Клики на элементы без реакции | > 5% сессий |
| `rage_clicks` | 3+ клика в одну точку за 1 сек | > 2% сессий |
| `quickback` | Уход на сайт-источник < 8 сек | > 40% сессий |
| `error_clicks` | Клики вызвавшие JS-ошибку | > 1% сессий |
| `excessive_scrolling` | Хаотичный скролл вверх-вниз | > 10% сессий |
| `cursor_tracking` | % покрытия страницы курсором | — |

#### Сегменты Clarity
- Устройство / ОС / браузер
- Источник (UTM / referrer)
- Страница входа
- Тип пользователя (новый / возвращающийся)
- Пользователи с конверсией vs без
- Сессии с rage/dead clicks (проблемные)
- Сессии с scroll 75%+ (вовлечённые)

#### Записи сессий — приоритетные сегменты
1. **Rage clicks** — куда тыкают в ярости → сломанный элемент или неочевидная кнопка
2. **Dead clicks** — кажется кликабельным, но не является → cursor-pointer без действия
3. **Quickback < 8 сек** — что видят первым, почему сразу уходят
4. **Scroll 90%+ без конверсии** — дочитали всё и не купили → проблема финального CTA
5. **Время 2+ мин** — что читают, где останавливаются → самый интересный контент
6. **Мобильные iOS** — особый паттерн поведения

| Метрика | Порог блокировки |

#### Поисковые запросы — паттерны для чистки
- Bounce > 75% + 0 конверсий → минус-слово

## ЧАСТЬ 3 — АЛГОРИТМ ПОИСКА ЗАВИСИМОСТЕЙ

### 3.1 Принцип трёх уровней

```
Уровень 1 — ЧТО происходит       (цифры, факты, отклонения)
Уровень 2 — ПОЧЕМУ происходит    (причины, паттерны, корреляции)
Уровень 3 — ЧТО ДЕЛАТЬ           (конкретные действия с приоритетом)
```

Поверхностный анализ = только уровень 1. Протокол требует всех трёх.

### 3.2 Метод «Аномалия → Гипотеза → Проверка»

```
Шаг 1: Найди аномалию
        └─ Метрика выбивается из нормы (>2x от среднего)
        └─ Неожиданная зависимость (A растёт, B не растёт)
        └─ Исчезновение паттерна (было, перестало быть)

Шаг 2: Сформулируй гипотезу
        └─ «Возможно, проблема в X потому что Y»
        └─ Всегда помечать 🤔 пока не доказано

Шаг 3: Проверь на данных
        └─ SQL-запрос / срез в Метрике / запись в Clarity
        └─ Минимум 30 наблюдений для вывода

Шаг 4: Зафиксируй результат
        └─ Факт: «iOS mobile, реклама → CVR 2.1% (данные 15.04-30.04, n=287)»
        └─ Вывод → в ЧАСТЬ 5 (решающие деревья)
```

### 3.3 Метод «Декомпозиция воронки»

Для каждого шага воронки ищем: **где самый большой drop-off?**

```
Показ → Клик           drop = 1 - CTR          → проблема объявления
Клик → Вовлечение      drop = bounce_rate       → проблема посадочной
Вовлечение → Скролл75  drop = 1 - scroll75/NB   → проблема контента
Скролл75 → age_select  drop = 1 - age/scroll75  → проблема CTA или оффера
age_select → choose     drop = 1 - choose/age   → проблема цены или формата
choose → контакт       drop = 1 - contact/choose → проблема следующего шага
контакт → лид в CRM    drop = 1 - CRM/contact   → проблема менеджера/бота
лид → оплата           drop = 1 - paid/leads    → проблема продажи
```

Главное правило: **чини самый большой drop-off первым**.

### 3.4 Метод «Сравнение с лучшим сегментом»

1. Найди сегмент с лучшей конверсией (например, organic desktop женщины 35-44)
2. Возьми его параметры как эталон
3. Сравни с каждым другим сегментом по всем метрикам
4. Разница = потенциал улучшения

```sql
-- Пример: сравнение CVR по сегментам относительно лучшего
SELECT
  traffic_source, device,
  COUNT(*) visits,
  ROUND(100.0 * SUM(chose_shift) / COUNT(*), 2) AS cvr,
  ROUND(100.0 * SUM(chose_shift) / COUNT(*) /
    MAX(ROUND(100.0 * SUM(chose_shift) / COUNT(*), 2)) OVER (), 0) AS pct_of_best
FROM metrika_visits_raw
WHERE date >= CURRENT_DATE - 30
GROUP BY traffic_source, device
HAVING COUNT(*) > 30
ORDER BY cvr DESC;
```

### 3.5 Метод «Когортный анализ»

Для понимания цикла принятия решения:

```
Когорта = пользователи, впервые зашедшие в период X
Отслеживать: 
  - Day 0: первый визит (bounce? scroll? микроцель?)
  - Day 1-3: возврат? с какого канала?
  - Day 3-7: второй-третий визит
  - Day 7+: конверсия или уход
```

**Вывод по нашим данным (апрель 2026):**
Типичный путь = 2-3 визита за 3-7 дней, последний перед конверсией = прямой заход (Яндекс.Карты) или брендовый поиск.

## ЧАСТЬ 5 — РЕШАЮЩИЕ ДЕРЕВЬЯ

### 5.1 Дерево: «Высокий bounce»

```
bounce > 65% на рекламном трафике?
  ├─ mobile > desktop bounce?
  │   ├─ ДА → проблема мобильной посадочной (скорость / первый экран)
  │   │       → PageSpeed mobile < 60? → оптимизация загрузки
  │   │       → First screen не соответствует объявлению? → правка контента
  │   └─ НЕТ → проблема не в устройстве
  │
  ├─ РСЯ bounce > Поиск bounce?
  │   ├─ ДА → площадки РСЯ дают нерелевантный трафик
  │   │       → Найти площадки с bounce > 65% → заблокировать
  │   │       → CPC < 8₽? → DSP-мусор → фильтр
  │   └─ НЕТ → проблема в ключевых словах или объявлениях
  │
  ├─ Bounce вырос резко (не постепенно)?
  │   ├─ ДА → внешнее изменение (код сайта, редирект, Partytown?)
  │   │       → Проверить деплои за период
  │   └─ НЕТ → медленная деградация → рост нерелевантного трафика
  │
  └─ Direct bounce > 90%?
      └─ ДА → боты или внутренние проверки → фильтровать IP
```

### 5.2 Дерево: «Мало конверсий»

```
choose_shift < 0.5% визитов?
  │
  ├─ age_select тоже низкий (< 1%)?
  │   └─ ДА → проблема верхней части воронки (аудитория, оффер)
  │           → Проверить: нужна ли другая ЦА?
  │           → Проверить: понятен ли первый экран?
  │
  ├─ age_select норма, но choose низкий?
  │   └─ ДА → проблема в блоке цен / смен
  │           → Пользователи выбирают возраст, но не видят следующий шаг
  │           → Clarity: что делают после age_select?
  │           → Добавить CTA рядом с блоком смен
  │
  ├─ choose норма, но контактов мало?
  │   └─ ДА → проблема в шаге после кнопки (бот / форма)
  │           → Бот не отвечает? Форма сломана?
  │           → Пользователь нажал кнопку — что видит?
  │
  └─ Конверсия хорошая на desktop, плохая на mobile?
      └─ ДА → CTA не виден на мобильном (маленький экран)
              → Нижняя плашка показывается?
              → Кнопка выше сгиба первого экрана?
```

### 5.3 Дерево: «Реклама дорогая»

```
CPA растёт или > порога?
  │
  ├─ CTR упал?
  │   ├─ ДА → выгорание объявлений → обновить креативы
  │   └─ НЕТ → CTR норма, проблема после клика
  │
  ├─ CPC вырос?
  │   ├─ ДА → аукцион стал дороже → проверить конкурентов
  │   │       → Снизить ставку и принять меньше трафика? или поднять?
  │   └─ НЕТ → CPC норма
  │
  ├─ Конверсия с клика упала?
  │   ├─ ДА → проблема посадочной или оффера
  │   └─ НЕТ → конверсия норма → откуда рост CPA?
  │
  └─ Много показов на мусорных площадках?
      └─ ДА → очистить площадки РСЯ (bounce > 65%, CPC < 8₽)
```

## ЧАСТЬ 9 — СПРАВОЧНИК SQL-ЗАПРОСОВ

### Базовые
```sql
-- Качество трафика по источникам за период
SELECT
  traffic_source, device,
  COUNT(*) visits,
  ROUND(AVG(visit_duration)) avg_sec,
  ROUND(100.0 * COUNT(*) FILTER (WHERE bounce) / COUNT(*), 1) bounce_pct,
  ROUND(100.0 * COUNT(*) FILTER (WHERE visit_duration > 120) / COUNT(*), 1) engaged_pct
FROM metrika_visits_raw
WHERE date BETWEEN '2026-04-01' AND '2026-04-30'
  AND traffic_source NOT IN ('internal')
GROUP BY traffic_source, device
HAVING COUNT(*) > 30
ORDER BY engaged_pct DESC;

-- Воронка целей по источникам
SELECT
  traffic_source,
  COUNT(*) visits,
  ROUND(100.0 * SUM(CASE WHEN goals_id::text LIKE '%541048270%' THEN 1 ELSE 0 END) / COUNT(*), 2) age_select_cvr,
  ROUND(100.0 * SUM(CASE WHEN goals_id::text LIKE '%545216463%' THEN 1 ELSE 0 END) / COUNT(*), 2) choose_shift_cvr,
  ROUND(100.0 * SUM(CASE WHEN goals_id::text LIKE '%545216440%' THEN 1 ELSE 0 END) / COUNT(*), 2) phone_cvr
FROM metrika_visits_raw
WHERE date >= CURRENT_DATE - 30
GROUP BY traffic_source
HAVING COUNT(*) > 50
ORDER BY choose_shift_cvr DESC;

-- Топ площадок РСЯ для блокировки
SELECT
  placement,
  SUM(clicks) clicks,
  SUM(cost) cost,
  ROUND(AVG(bounce_rate), 1) bounce,
  SUM(conversions) conv,
  ROUND(SUM(cost) / NULLIF(SUM(clicks), 0), 2) cpc
FROM direct_placements
WHERE date >= CURRENT_DATE - 14
GROUP BY placement
HAVING SUM(clicks) > 5
  AND (AVG(bounce_rate) > 65 OR SUM(cost)/NULLIF(SUM(clicks),0) < 8)
ORDER BY SUM(cost) DESC;
```
