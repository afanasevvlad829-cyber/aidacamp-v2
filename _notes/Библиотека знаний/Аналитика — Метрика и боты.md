# Аналитика: Яндекс.Метрика, PostgreSQL, наши боты

## Как получать статистику (правильный способ)

**Единственный правильный способ** — через MCP-инструмент `mcp__aidacamp-tools__stats`. Не stats.sh напрямую, не raw API.

```
stats(command: "summary", period: "week")
stats(command: "metrika-daily", period: "2026-04-23:2026-04-25")
stats(command: "utm", period: "month")
stats(command: "placements", period: "week")
stats(command: "goals", period: "week")
```

Данные в PostgreSQL синхронизируются **через API** (ETL-скрипты архивированы с 22.04.2026):
- **Яндекс.Директ** — real-time (Direct API v5)
- **Яндекс.Метрика** — real-time (Metrika API)
- **VK Ads** — real-time (VK API)
- **Clarity** — раз в сутки (Clarity API)

## Наши боты в Метрике — критически важно

### Кто такие наши боты

Claude Code Preview и агентские воркдеревья (agent/*) запускают **headless Chromium** для проверки вёрстки. Эти браузеры:

- User-Agent: `HeadlessChrome/<version>` на платформе `gnu_linux`
- Заходят на `localhost:4180`, `127.0.0.1:4173`, `dev.aidacamp.ru` и напрямую на `aidacamp.ru`
- URL содержат GET-параметры: `FF_MODULAR_RUNTIME`, `type=preview`, `parentMessageId=`
- Яндекс.Метрика записывает эти визиты как реальные

### Что фильтрует Метрика (есть 5 фильтров)

Активные фильтры URL в счётчике 96499295:
- `dev.aidacamp.ru` → заблокировано
- `localhost` → заблокировано
- `127.0.0.1` → заблокировано
- `adacamp-test.pages.dev` → заблокировано
- «Собственные визиты» по IP → заблокировано

**Итог:** боты, которые ходят на `localhost` или `dev.aidacamp.ru`, отфильтровываются. Данные в PostgreSQL (через Reports API) по UTM-источникам **чистые**.

### Что НЕ фильтруется

Боты, которые ходят напрямую на `aidacamp.ru` (production) — при необходимости проверить через Logs API по признаку `ClientInfo_Browser = HeadlessChrome`. Через Метрику Reports API (и PostgreSQL) данные приходят уже с применёнными фильтрами счётчика.

### Масштаб (данные апреля 2026)

По анализу Logs API за 21 день (2026-04-04 — 2026-04-24):
- Всего в логах: **38 696 хитов**
- Наших ботов: **~1 191 визит** за период
- Пик: **24 апреля — 318 ботовых визитов** (97.5% отказов в Direct) → было ошибочно принято за внешнюю атаку

### Как отличить ботов от реального трафика в Метрике

Признаки нашего бота в Logs API:
```
ClientInfo_Browser = HeadlessChrome
ClientInfo_OS = gnu_linux
URL содержит: FF_MODULAR_RUNTIME | type=preview | parentMessageId | localhost | 127.0.0.1
Время визита = 0 секунд
```

### Как исправить (рекомендация)

Добавить в Метрику **фильтр по User-Agent**: `HeadlessChrome` → «Не учитывать»

Путь: Метрика → Счётчик 96499295 → Настройки → Фильтры → Добавить → User-Agent → содержит → `HeadlessChrome`

Это заблокирует и наших ботов, и чужих headless-роботов сразу.

## Best practices из нашего опыта

### 2026-04-25: Ботовый трафик 24 апреля принят за атаку

**Симптом:** 24 апреля в канале «Прямые заходы» — 318 визитов, отказы 97.5%, время 0 сек. Выглядело как внешняя DDoS/бот-атака.

**Причина:** Накануне (23-24 апреля) агенты Claude Code активно работали в воркдеревьях — запускали dev-сервер, делали скриншоты через headless Chromium. Боты обращались к `aidacamp.ru` напрямую (без localhost), Метрика их записывала.

**Решение:** Проверено через Logs API — 94% визитов в этот день имели `ClientInfo_Browser = HeadlessChrome` и `ClientInfo_OS = gnu_linux`. Это не внешняя атака, а наши инструменты.

**Правило:** При аномальном росте отказов в «Прямых заходах» — первым делом смотреть на активность агентов/деплоев в этот день. Если агенты работали → это скорее всего наши боты.

### 2026-04-25: Данные за день отсутствуют в БД

**Симптом:** Запрос за текущую дату возвращает 0 строк.

**Причина:** Все API работают в real-time, но данные за текущий день могут быть неполными — Метрика накапливает их в течение дня.

**Правило:** Если данных за сегодня нет — день ещё не закончился или данные не накопились. Использовать `yesterday` для полных суточных данных.

---

### 2026-04-25: Clarity API — максимум 3 дня

**Симптом:** Запрос Clarity Export API с `numOfDays=4` (и выше) возвращает HTTP 400.

**Причина:** Ограничение API. Максимум `numOfDays=3`.

**Правило:** Clarity через API — только последние 3 дня. Для большего горизонта — использовать PostgreSQL (таблицы `clarity_daily`, `clarity_pages`).

---

### 2026-04-24: Обнуление обучения Direct после изменения корректировок

**Симптом:** 24 апреля — только 6 кликов, 218 показов, расход 0₽ (при стратегии PAY_FOR_CONVERSION).

**Причина:** 24 апреля 14:00-16:00 были применены корректировки ставок по устройствам (планшет -100%). Изменение корректировок сбросило обучение кампаний.

**Решение:** 25 апреля РСЯ частично восстановилась: 47 кликов, 598₽, 21 конверсия.

**Правило:** Любые изменения в кампаниях с PAY_FOR_CONVERSION сбрасывают обучение. Ждать восстановления 3-7 дней. Не паниковать при 0₽ расхода — алгоритм переобучается.
