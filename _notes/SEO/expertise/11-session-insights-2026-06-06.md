# Инсайты сессии — 2026-06-06

> Усиление тонких страниц + стабилизация процесса SEO-автопилота. Уроки про хрупкость shared-репо и про качество генерации.

---

## 1. Усиление тонких страниц зоны удара (выполнено)

**Симптом:** 75 запросов ранжируются на главной, выделенные страницы тонкие (~280 слов) → нельзя переключить ранжирование на них без потери позиции.

**Решение:** 14 тонких целей усилены уникальным контентом.
- v1 (`strengthen-pages.js` старый): `buildExtraSection` выдавал **идентичный** блок на все страницы → дубль-контент, риск Баден-Бадена. ❌
- v2: LLM-генерация (gpt-4o-mini) + RAG-факты, уникально на каждой странице, валидатор отсекает banned-words/восклицания/плейсхолдеры/короткий текст.
- Финал: **14 блоков переписаны вручную Claude** под голос Дарьи — gpt-4o-mini давал суховатый generic-маркетинг. Ручной текст заметно брендовее.

**Правило:** для усиления тонких — НЕ один шаблон на всех (дубль = фильтр). Уникальный per-page контент. Для live-страниц с брендовым голосом ручной текст > gpt-4o-mini; для масштаба — few-shot эталоны или сильная модель через OpenRouter/LiteLLM.

## 2. Хрупкость shared-репо на сервере (главный тормоз)

**Симптом:** скрипты терялись, ночной крон переключал ветку под ручной работой, деплой падал на грязном дереве.

**Причины:**
- Рабочие скрипты жили только в `/opt/seo-factory`, не в git → терялись между сессиями (`/tmp` смывался компактами).
- Крон фабрики делал `git checkout -b agent/seo-factory-DATE` в общем `/opt/aidacamp-site` → угонял ветку.
- Деплой от грязного Mac-чекаута блокировался гардом.

**Решение:**
- Все 10 скриптов фабрики → git (PR #559), git = источник правды.
- Крон фабрики → изолированный worktree `/opt/seo-factory-run` (через `SEO_REPO_DIR`).
- `/opt/seo-factory` деплоится из git через `sync-runtime.sh` (читает `git archive origin/dev`, крон 06:55).
- Прод-деплой — из чистого worktree `.claude/worktrees/deploy-prod`, не от грязного основного чекаута.

**Правило:** на shared-сервере никакой автоматики в общем чекауте. Каждый автономный процесс — свой worktree. Runtime-код деплоится из git, не редактируется на месте.

## 3. Большие stateful-задачи в одной сессии = потери

**Симптом:** 4+ компакта контекста за задачу, половина времени на переориентацию, файлы в `/tmp` терялись, пользователь много раз спрашивал «статус» (не видел прогресса между ресетами).

**Правило:** большую задачу дробить на короткие отгрузки (один PR — один инкремент), не держать в `/tmp`, важное сразу в git. Stateful-марафоны — отдельными сессиями с чистым стартом.

## 4. Фабрика: гейт против масс-генерации уже есть

**Факт:** `seo-factory.js` делает `gh pr create --base dev`, но **не авто-мержит**. Ежедневные ≤15 страниц идут PR'ом на ревью. Риск масс-генерации реализуется только если мержить PR не глядя. `seo_kaizen.py` был отключён (вероятно — мусорные страницы); фабрика не должна повторить → мержить прогоны только после проверки.

**Правило:** перед масштабированием генерации — доказать на уже выкаченных 14 страницах, что подход двигает позиции (2–4 недели, `measure-performance`). Не плодить тонкие страницы вслепую.
