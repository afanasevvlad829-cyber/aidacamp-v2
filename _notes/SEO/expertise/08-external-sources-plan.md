# План набора SEO-экспертизы из открытых источников

> Цель: загрузить в RAG (`knowledge_chunks`) проверенное понимание алгоритмов ранжирования, чтобы SEO-фабрика генерировала страницы на основе реальных факторов, а не догадок.
> Приоритет источников (по решению владельца 2026-06-04): официальные доки → поведенческие факторы Яндекса → практические гайды → патенты/исследования.
> Метод загрузки: каждый источник → текст → `ingest-md.mjs` / `ingest-seo-reports.mjs` → чанки с embeddings → source-префикс `seo:source:<категория>:<имя>`.

## Приоритет 1 — Официальные доки Яндекс + Google (первоисточник, факты)

| Источник | Что берём | source-префикс |
|---|---|---|
| Яндекс.Вебмастер — справка (yandex.ru/support/webmaster) | Требования к сайтам, индексирование, robots, sitemap, региональность, Турбо | `seo:source:yandex-docs` |
| Яндекс — «Что влияет на ранжирование» | Официальный список факторов | `seo:source:yandex-ranking` |

**Почему первым:** факты, а не мнения. Особенно важно для Яндекса — мы там работаем. Spam policies критичны чтобы фабрика не нагенерила то, за что прилетит фильтр.

## Как загружать (процесс)

1. **Сбор:** для каждого источника — WebFetch ключевых страниц (или ручное сохранение в `_notes/SEO/sources/<категория>/`).
2. **Очистка:** HTML → текст (как в `ingest-seo-reports.mjs`).
3. **Чанкинг + embeddings:** `ingest-md.mjs` с правильным source-префиксом.
4. **Проверка:** `kb_search_semantic("Баден-Баден плотность ключей")` должен находить.
5. **Применение в фабрике:** `enrichFromRAG` уже ищет по `source LIKE 'seo:%'` — расширить паттерн чтобы захватывал `seo:source:*`.

## Что это даёт фабрике

| Сейчас | После загрузки источников |
|---|---|
| Кластеризация по 2 словам | Intent-классификация (из Ahrefs/Semrush методик) |
| LSI из одного майского анализа | LSI-методология + порог плотности (Баден-Баден) |
| Жёсткие шаблоны | Структура под реальные ranking factors |
| Риск фильтра неизвестен | Знаем пороги переоптимизации |

## Очерёдность исполнения

1. **Сначала П1 + П2** (официальное + Яндекс ПФ) — это защита от фильтров, критично для масштабной генерации.
2. **Потом П3** — улучшение алгоритма кластеризации фабрики.
3. **П4 по запросу** — когда нужно глубокое понимание конкретного механизма.
