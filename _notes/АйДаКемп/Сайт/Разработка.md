# Разработка сайта

## Стек
- **Astro 6.x** + Tailwind CSS v4 (utility classes only)
- **@astrojs/node** adapter (SSR для /api/, статика для страниц)
- Node 22 (nvm), деплой через rsync
- Sharp для AVIF-конвертации (quality 72)

## Ключевые правила
- Tailwind: динамические классы (`grid-cols-${n}`) НЕ работают — только статические
- Порядок смен: 1→2→2.1→2.2→3→4
- FAQ: Проживание/Питание/Безопасность/Связь/Медицина/Все
- "🔥 Осталось 4 места" — убран, не добавлять
- Все изображения только AVIF (quality 72, resize 1200x800 галерея, 640x960 обложки видео)
- Деплой: всегда dev → проверить → prod

## Git workflow (ОБЯЗАТЕЛЬНО для агентов и людей)
1. **Любая правка кода → отдельная feature-ветка** из `dev`, имя `feature/<короткое-описание>`
2. **Не коммитить в `dev` напрямую.** Только merge из feature-ветки после ревью
3. **Коммит = одна логическая правка.** Не захватывать чужие uncommitted изменения
4. **Push feature-ветки → PR в `dev` через GitHub UI** (не через gh без авторизации)
5. **В `main` ничего не пушим автоматически.** Владелец сначала смотрит `dev` глазами после merge, потом отдельной командой пушит в `main`
6. **Если правил напрямую — откатиться:** `git checkout dev && git checkout -- <file>`, затем переделать через feature-ветку

## Деплой
```bash
./scripts/deploy.sh dev     # dev.aidacamp.ru
./scripts/deploy.sh prod    # aidacamp.ru (с подтверждением + бэкап)
```
После деплоя автоматически запускается site-snapshot (контент + скриншоты изменённых страниц).

## API-эндпоинты (SSR)
| Путь | Назначение |
|---|---|
| `/api/lead` | Приём заявок → Telegram + leads.jsonl. `source=smoke-test` пропускается |
| `/api/clicks` | Dead/rage click трекер → `/var/www/aidacamp-dev/clicks/YYYY-MM-DD.jsonl` |
| `/api/photo` | Прокси фото с Яндекс.Диска (без токена у клиента) |
