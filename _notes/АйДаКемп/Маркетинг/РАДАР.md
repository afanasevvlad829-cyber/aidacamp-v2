> Кодовое слово: **РАДАР**
> Запуск: напиши «РАДАР» → Claude загружает данные и выдаёт отчёт

Обновлено: 17 апреля 2026

---

## Как запускать

1. Выгрузи данные через ETL
2. Напиши: **РАДАР**
3. Claude прогоняет все блоки и выдаёт отчёт

Периодичность: ежедневно — блоки 1–6 / еженедельно — все 11

## Ограничение ETL

| Данные | Обновление |
|---|---|
| Директ: кампании, площадки | Несколько раз в день (точное расписание Яндекс не публикует) |
| Директ: поисковые запросы | 1–2 дня задержка (за сегодня данных нет до следующего дня) |
| Метрика: устройства, гео, демография, UTM | 1 раз в сутки (ночью) |
| Метрика: цели в реальном времени | 30 сек — 5 мин (официально) |
| Clarity | 1 раз в сутки |

**Важно о Reports API Директа:** данные через API обновляются реже чем в личном кабинете. Если отчёт API не показывает новых кликов — проверяй баланс в кабинете вживую. Стабилизация статистики до 3 дней (финальные цифры).

Устройства/возраст/гео — всегда за вчера. Это не баг, это архитектура.

## Блок 1 — Общие показатели (MACRO)

Источник: `direct_campaign_stats`
Метрики: CTR → CPC → CR → CPA по каждой кампании
Сравниваем: вчера / позавчера / неделю назад
Экономика: CPA < 500₽ (маржа ~22 500₽ при чеке 75 000₽)
🔴 CPA вырос > 50% | 🟡 CPA вырос > 20%

Диагностика:
- CTR ↓ → слабый оффер или ключ
- CPC ↑ → конкуренция или падает CTR
- CR ↓ → лендинг или нерелевантный сегмент
- Отказы ↑ → мусорный трафик или скорость сайта

### Паттерн DSP-трафика (как распознать)

DSP-трафик появляется когда алгоритм не может найти достаточно кликов на нормальных площадках. Признаки:
- CPC резко падает до 2–7₽
- CTR растёт до 8–15%
- Bounce 65–85%
- Демография «не определена» > 70% трафика
- Clarity: скролл падает до 15–20%

**Паттерн появления по дням:** нормальные площадки 1–3 дня → алгоритм уходит в DSP на 4–5 день если не хватает кликов. После блокировки DSP алгоритм либо возвращается на нормальные площадки, либо уходит в игровые приложения (com.*, io.*). Игровые приложения — следующий уровень мусора после DSP, блокируем по тем же правилам.

## Блок 6 — Мусорные поисковые запросы (KEYWORDS)

Источник: `direct_search_queries`
Логика: расход > 30₽ + нерелевантная тема
Набор минус-фраз ID: 56105889 "Мусор — поиск АйДаКемп" (обновлён 17.04.2026 — добавлены железнодорожный, балашиха, щёлково, ~50 городов МО и РФ, корпоратив, тимбилдинг, вожатым, педагог лагерь)

**Почему прилетают нецелевые запросы по городам:**
Это НЕ автотаргетинг — это широкое соответствие ключевых слов. Ключ `детский лагерь программирования` без оператора срабатывает на «детский лагерь программирования Железнодорожный». Решение: оператор `+` на гео-слово или минус-слова по городам.

**Правило операторов в ключах:**
- Ключи с гео в запросе (Москва, Подмосковье) — оставить без `+подмосковье`
- Широкие ключи без гео — добавить `+подмосковье`
- Пример: `детский лагерь на лето 2026` → `детский лагерь на лето 2026 +подмосковье`

**Автотаргетинг vs широкое соответствие:**
| | Что это | Как отключить |
|---|---|---|
| Автотаргетинг | Показы по темам без ключей | Удалить `---autotargeting` из группы |
| Широкое соответствие | Вариации ключей | Операторы `+` или минус-слова |

## Блок 8 — РСЯ-группы: анализ объявлений (GROUPS)

Источник: `direct_reports` AD_PERFORMANCE_REPORT + `metrika_utm` + `metrika_demographics`

### Как правильно анализировать группу (протокол 16.04.2026)

**Никогда не останавливаться на уровне площадок.** По каждому объявлению смотреть:

1. **Площадки** — топ по кликам, CPC, bounce, устройство
2. **Динамика по дням** — когда появился DSP, что было до него
3. **Устройства** — мобайл vs десктоп bounce отдельно
4. **Демография** — какой сегмент читает (данные из metrika_demographics за тот же период)
5. **Гео** — какие города дают трафик с этой группы
6. **Clarity** — скролл в дни пика DSP vs нормальные дни

**Правило сравнения:** если два объявления в одной группе — сравнивать bounce мобайл отдельно и десктоп отдельно, а не общий.

### Паттерны офферов (что работает в РСЯ)

**Работает хорошо:**
- Провокационные заголовки с отсечением: «Подойдёт не каждому ребёнку» — алгоритм сам находит думающую аудиторию, DSP не появляется
- Двойной адресат (ребёнок + родитель): «Он без телефона. Вы — без тревоги.» — bounce 58%, RBC bounce 20%
- Трансформация: «Уехал геймером — вернулся разработчиком» — конкретный образ результата
- Эмоция родителя: «После смены ребёнок верит в себя» — bounce 50% на нормальных площадках
- Бытовая боль: «Две недели без «мама, скучно»» — близко и понятно

**Не работает:**
- Абстрактные слоганы: «Не просто лагерь. Среда развития» — алгоритм уходит в игровые приложения
- IT-характеристики в заголовке: «Ребёнок делает IT-проект» — нишевый, не цепляет на баннере
- Широкие общие слова: «Пока дети взрослеют — вы отдыхаете» — bounce 76%, алгоритм не понимает аудиторию

**Принцип:** чем провокационнее и конкретнее заголовок — тем лучше алгоритм таргетирует. Провокация отсекает случайных, привлекает целевых.

## Ключевые инсайты — апрель 2026

### О площадках

1. **DSP vs игровые приложения — два уровня мусора.** Сначала алгоритм уходит в DSP (dsp-*.yandex.ru), после блокировки — в игровые приложения (com.outfit7.*, com.easybrain.*). Блокировать последовательно.

2. **Яндекс-субдомены — скрытый мусор.** `m.pogoda.yandex.ru`, `m.disk.yandex.ru`, `rasp.yandex.ru` и 70+ других — технически нормальные Яндекс-сервисы, но реклама там показывается в контексте нецелевого поведения. Заблокировали 71 субдомен через ExcludedSites. Экономия ~10 000₽/мес.

3. **rbc.ru bounce 20% — золотая площадка.** Деловая аудитория, родители с доходом. CPC 34₽. Мониторить — если появляется в отчёте, это сигнал что оффер правильный.

4. **deti.mail.ru bounce 0%, глубина 5 страниц** — открытие 17.04. Детский раздел mail.ru. Добавлен в whitelist. Приоритетная площадка.

5. **Bounce 100% утром ≠ проблема сайта.** Утренние 07–10 МСК — мобильный скроллинг, люди открывают баннер и закрывают. После отключения этого окна bounce нормализуется. Проверять только данные после 11:00 МСК.

6. **Bounce 100% на премиум площадках (dzen, ya.ru, mail.ru) утром** — не значит что площадки плохие. Это временно́й эффект. Вечером те же площадки дают bounce 40–60%.

7. **CPC упал до 7₽ → немедленная тревога.** Это маркер DSP-волны (15.04). При CPC < 10₽ в РСЯ — срочно смотреть площадки.

### О демографии и гео

8. **Королёв — неожиданная находка.** Bounce 32%, 57 сек. Наукоград, родители с IT-бэкграундом — идеальная аудитория.

9. **«Не определённая» демография = DSP.** Если > 70% трафика без пола/возраста — группа в мусоре.

10. **PC Windows bounce 17.9% — лучший сегмент РСЯ.** Корректировка +25% поставлена.

### О стратегии объявлений

11. **Провокационный заголовок → нет DSP.** Объявление «Подойдёт не каждому ребёнку» за 5 дней без единой DSP-площадки. Чем специфичнее оффер — тем лучше таргетирование.

12. **Новое объявление обучается 5–7 дней.** Первые 3 дня — нормальные площадки с низким CTR. На 4–5 день без кликов алгоритм уходит в DSP. Не трогать первые 5 дней.

13. **rsya_books — проблемная группа.** Тексты «Лето с пользой» и «Лагерь с результатом» слишком широкие — алгоритм не понимает аудиторию, льёт в dzen+gismeteo+приложения. Приостановлена 17.04.

### Об автостратегии и ставках

14. **Ставка автотаргетинга при автостратегии не регулирует показы.** При стратегии «Максимум конверсий» единственные реальные рычаги: блокировка площадок, корректировки ставок, расписание.

15. **Гео-блокировка через API минимум -90% (BidModifier=10).** API не принимает 0 для RegionalAdjustments.

16. **set BidModifier API — плоская структура.** Правильный формат: `{'Id': mod_id, 'BidModifier': value}`. Вложенная структура с типом корректировки не работает для метода `set`.

### О поисковых ключах

17. **Мусорные запросы идут не из автотаргетинга — из широкого соответствия.** «Железнодорожный» прилетел из ключа `детский лагерь программирования` без оператора. Решение: `+подмосковье` к широким ключам.

18. **Стратегия операторов — гибрид.** Ключи с Москвой/Подмосковьем в запросе — без оператора. Ключи без гео — добавить `+подмосковье`. Потеря трафика ~30% но +40–60% качества.

19. **Обновлено 17.04:** 8 ключей в Поиске добавлен оператор `+подмосковье` или `+it`. Группы `search_camp2026`, `search_prices`, `rsya_addiction` — новые, добавлены 17.04.

### О данных и обновлениях

20. **Метрика обновляется почти в реальном времени** — 30 сек–5 мин (официальная документация Яндекса).

21. **Директ личный кабинет** — «в течение нескольких часов» (официальная справка). Быстрее чем Reports API.

22. **Директ Reports API** — обновляется реже чем интерфейс кабинета. Если API не показывает новых кликов — проверять баланс в кабинете вживую, не делать вывод что кампании стоят.

23. **Стабилизация статистики Директа** — до 3 дней. Финальные цифры за сегодня могут измениться. Для РАДАР смотреть данные за вчера и позавчера как более надёжные.
