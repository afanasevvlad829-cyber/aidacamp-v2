# РАДАР 2.1 — Протокол оценки Директа с глубокой детализацией

> Развитие РАДАР 1.0 (см. `РАДАР.md`). Не заменяет, а дополняет.
> Версия 2.1 — 18 апреля 2026
> Принцип: идём до (день × группа × объявление × площадка × устройство × демо × гео × час), не останавливаемся на уровне площадок.

---

## Условные обозначения

- **факт** — подтверждено официальной справкой Яндекса или эмпирически
- **гипотеза** — не подтверждено документацией, требует проверки на наших данных
- 🟢 норма · 🟡 внимание · 🔴 критично

---

## Часть I. База знаний об алгоритмах Директа

Всё ниже — из официальной справки Яндекса (2025-2026). Источники в конце документа.

### 1. Автостратегии

| Стратегия | В ЕПК | Оптимизирует | Мин. для обучения |
|---|---|---|---|
| Максимум кликов | ✅ | Клики в бюджете | Нет порога по конверсиям |
| Максимум кликов + ручные ставки (только Поиск) | ✅ | Клики | — |
| Максимум конверсий | ✅ | Конверсии по цели | **≥10 конверсий/неделя** |
| Максимум конверсий с оплатой за конверсии (CPA) | ✅ | Плата только за цель | **≥10 конверсий/неделя** |
| Максимум прибыли (бета) | ✅ | Прибыль | ≥10 конверсий с ценностью |
| Целевая ДРР | — | ROAS | ≥10 конверсий + выручка |
| Пакетные стратегии | ✅ | Общий пул нескольких ЕПК | — |

**Обучение — факт:**
- 1-2 недели технологического периода
- Окно атрибуции оплаты за конверсии = **21 день** после клика
- При <10 конв/нед стратегия не останавливается, но «колеблется»
- Микро-конверсии допустимы при корреляции с макро ≥0.7 (иначе алгоритм учится привлекать нецелевых)

**CPC в автостратегии — факт:** прямого ограничения нет. Рычаги: недельный бюджет, CPA-цель, корректировки, расписание, площадки.

### 2. Автотаргетинг

Пять категорий запросов:
1. **Целевые** — точно соответствуют объявлению. **Отключить нельзя** (факт).
2. Узкие — объявление шире запроса.
3. Широкие — объявление ýже запроса.
4. Альтернативные — другой способ решить ту же задачу.
5. Сопутствующие — смежный интерес.

Флаг брендов — отдельно: свой / конкурентов / без брендов.

**Автотаргетинг работает параллельно с ключами**, не заменяя.

### 3. Корректировки ставок — 10 типов (факт, справка)

| Тип | Диапазон |
|---|---|
| Целевая аудитория (сегменты Метрики/Аудиторий) | -100% .. +1200% |
| Пол + возраст | -100% .. +1200% |
| Видео | **-50%** .. +1200% |
| Регион | **-90%** .. +1200% (0% нельзя) |
| Устройства (iOS/Android/планшет/desktop/CTV) | -100% .. +1200% — **-100% сразу на все устройства запрещено** |
| Погода | -100% .. +1200% |
| Эксклюзивное размещение | **0** .. +1200% (только повышение) |
| Платёжеспособность (топ 1% / 2-5% / 6-10%) | -100% .. +1200% |
| Уровень трат в категории (магазины) | -100% .. +1200% |
| Цена в группе ЕПК | -99% .. +1200% |

**Правила сочетания — факт:**
- Корректировки **перемножаются**, не суммируются
- Пример справки: 15₽ × мужчина 18-24 (-40%) × мобильный (+30%) × Москва (+200%) = **35.1₽**
- При конфликте внутри одной категории (два сегмента ЦА) — **выигрывает максимально повышающая**
- **Группа > Кампания** по приоритету
- -100% обрабатывается до 180 мин — возможны остаточные показы
- Корректировки **работают и в автостратегии**: CPA-цель выдерживается с учётом корректировок

### 4. Атрибуция Метрики

| Модель | Что делает |
|---|---|
| Последний | Источник последнего визита |
| **Последний значимый** (дефолт 2024+) | Незначимые (прямые/внутренние/закладки) передают кредит предыдущему значимому |
| Последний из Директа | Всё приписывается последнему клику в Директе (применяется при переходе из Директа в отчёты) |
| Первый | Самый первый визит |
| Кросс-девайс | По технологии Крипта через устройства пользователя |
| Автоматическая | ML + кросс-девайс + домохозяйства |

**Окно — факт:** у всех моделей одинаково. Все визиты посетителя без перерыва ≥90 дней.

**"Yandex.Direct: Undetermined" — факт:** Метрика поймала yclid, но не сматчила с кликом. Нормально 5-15% трафика.

### 5. Сегменты и Look-alike — факт

- Минимум **100 уникальных** пользователей для таргетинга
- Источники: Метрика-сегменты, Аудитории (CSV email/phone/device-id), Директ, AppMetrica
- Look-alike создаётся из существующего сегмента
- Используется как **таргетинг** (группа) или **корректировка** (группа/кампания)

### 6. Форматы кампаний

- **ЕПК** — стандарт 2024-2026, совмещает Поиск+Сети+Карты, до 50 групп
- **Мастер кампаний** — упрощённый для малого бизнеса
- **Классические кампании** — legacy, постепенно выводится

### 7. Расширенный гео — факт

По умолчанию включён. Показы могут идти вне целевого региона если в запросе есть его упоминание. **Для АйДаКемп — выключать** (не хотим трафик из других регионов).

### 8. Расписание в автостратегии — факт

Работает, но алгоритм может временно превышать бюджет часа при высокой CR-возможности. Расписание — приоритеты, не жёсткие лимиты.

## Часть II. Диагностические блоки РАДАР 2.1

### 📊 Блок M. MACRO (ежедневно, 30 сек)

| Показатель | Источник | Норма | 🔴 |
|---|---|---|---|
| Расход/день | direct_campaign_stats | ~5 000₽ | +30% за сутки |
| Общая CPA | conv / spend | < 500₽ (маржа ~22 500₽ при чеке 75 000₽) | > 500₽ |
| Клики Директ vs визиты Метрика | API + метрика | Метрика +10..40% | разрыв >30% |
| Баланс | Кабинет | >2 дней | <2 дней |

Если M = 🔴 → погружаемся в блоки ниже.

---

### 🎯 Блок S. STRATEGY — состояние стратегии (ежедневно)

Для каждой кампании:

```
Кампания X
  стратегия: «Максимум конверсий с оплатой за конверсии»
  целевая цена: 200₽
  priced_goal: micro_age_select
  недельный бюджет: 35 000₽
  состояние: ОБУЧАЕТСЯ (осталось N дней) / ОБУЧЕНА / ПЕРЕОБУЧАЕТСЯ
  конверсий за 7 дней: X  (норма ≥10)
  CPA-факт vs CPA-цель: отклонение Z%
```

🔴 <7 конв/нед → стратегия голодает, бросает трафик в случайные сегменты
🔴 CPA-факт >2× CPA-цели → алгоритм не справляется, пересмотреть микро-цель
🟡 перезапуск <48 ч назад → данные переходные, выводов не делать

**Правило — факт:** не менять CPA-цель/бюджет/стратегию чаще чем раз в 7 дней, каждое изменение = переобучение.

---

### 🔗 Блок A. ATTRIBUTION (ежедневно)

```
Клики Direct API:       N
Визиты с yclid-матч:    N (норма ~95-100% от кликов)
Undetermined:           % (норма 5-15%)
utm_source=yandex:      N
```

🔴 Undetermined >30% → проверить: скорость сайта (yclid не успевает), `<meta name="referrer">`, HTTPS-referer
🔴 клики > визиты+20% → трафик до сайта не доходит (404, медленная загрузка, baddomain)

---

### 🛒 Блок G. GROUPS × ADS (ежедневно)

Для каждого объявления с расходом >200₽/день:

| Параметр | 🔴 Флаг |
|---|---|
| CTR Поиск | < 3% |
| CTR РСЯ | < 0.4% |
| CR → micro_age_select | < 3% |
| CR → phone_click/messenger | < 0.3% |
| Bounce общий | > 65% РСЯ / > 40% Поиск |
| Bounce iOS | > 75% |
| Bounce Android | > 70% |
| Bounce PC | > 35% |
| Avg time | < 25 сек |
| Доля «пол/возраст не определён» | > 70% → DSP-маркер (гипотеза, подтверждена эмпирически 15.04) |

### 🧩 Блок D. DRILLDOWN — глубокий разбор аномалии

Срабатывает когда G дал 🔴.

#### D.1 Устройства

Не «мобайл vs десктоп», а полная матрица:

| Сегмент | visits | bounce | time | CR micro | CR macro | CPA |
|---|---|---|---|---|---|---|
| iOS + моб.сеть | | | | | | |
| iOS + WiFi | | | | | | |
| Android + моб | | | | | | |
| Android + WiFi | | | | | | |
| PC Windows | | | | | | |
| PC Mac | | | | | | |
| Планшет | | | | | | |
| CTV | | | | | | |

Dimensions: `ym:s:mobilePhone`, `ym:s:operatingSystem`, `ym:s:browser`, `ym:s:deviceCategory`.

Действие: по худшему устройству -30..-70% корректировка на уровне группы. Помнить правило перемножения.

#### D.2 Демография × Устройство × Гео

Не «женщины 35-44», а «женщины 35-44 на iPhone в Москве».

Искомые топ-сегменты АйДаКемп (гипотеза, проверяем каждый месяц):
- Женщины 35-44 × PC × Москва — работающие мамы
- Женщины 45-54 × PC × Красногорск/Подольск/Королёв — наукограды
- Мужчины 25-34 × PC × Москва — IT-папы

Действие: корректировка +20..+50% по топ-сегментам, -50..-100% по худшим. **Сегмент должен быть ≥100 уникальных**, иначе система корректировку не применит (факт).

#### D.3 Гео-drill

`ym:s:regionCity` → при аномалии в город сразу -90% (минимум API гео).

Текущий whitelist (апрель 2026): Москва, Красногорск, Подольск, Королёв, Раменское. Одинцово пограничный. Балашиха -50%. СПб/Тверь/Химки/Люберцы/Домодедово -90%.

#### D.4 Час × День × Устройство

`ym:s:hour × ym:s:dayOfWeek × ym:s:deviceCategory`.

**Нельзя смотреть «час» отдельно** — bounce 22:00 на PC и на моб — разные истории.

Формула решения (гипотеза):
```
score(час, день, устройство) = visits × (1 - bounce) × (CR_micro + 3×CR_macro)
отключать срезы где score < 5% от максимума
```

#### D.5 Площадки × Устройство × Время

```
dzen.ru → 11:00 × PC Windows = bounce 18%   ✅ держать
dzen.ru → 22:00 × iOS        = bounce 89%   🔴 блок или расписание
com.outfit7.*                                🔴 сразу бан
```

Сама Метрика площадку даёт через `ym:s:<attribution>DirectPlatform` (гипотеза — нужно проверить точность).

#### D.6 Keywords × Match-type × Автотаргетинг

`direct_search_queries` + разбивка:
- Точное (`"..."`) — релевантность ~95%
- Фразовое (`[...]`) — ~85%
- Широкое — основной источник мусора
- Автотаргетинг **по категориям отдельно** (целевые / узкие / широкие / альтернативные / сопутствующие)

Действие: если категория автотаргетинга (не «целевые») даёт CR <1% и >5% расхода → отключить. Целевые отключить нельзя.

#### D.7 Объявление × Устройство × Час (микро-анализ креативов)

Когда в группе 2+ объявлений — сравнение **попарно на одинаковом срезе**:
```
A vs B на срезе: Москва × Ж 35-44 × PC × 14-16 МСК
  CTR A=0.8% B=0.5%    → A лучше
  bounce A=48% B=63%
  CPA A=180₽ B=340₽
```

**Не усреднять по всему трафику** — алгоритм показывает разные объявления разной аудитории.

---

### ⚙️ Блок B. BID ADJUSTMENTS (еженедельно + при аномалии)

Аудит активных корректировок:
- тип, сегмент, значение, уровень (кампания/группа)
- суммарный множитель на топ-сегменте (перемножение всех активных)
- эффект до/после (сравнение 7 дней до и 7 после)

🔴 Дубль: одна и та же корректировка на кампании и группе → применится только группа (факт). Снять с кампании.
🔴 Гео минимум = -90%, не 0 (факт API). Проверить `BidModifier=10` для «запрещённых» городов.
🔴 Сегмент <100 уникальных — корректировка не применится (факт). Проверить размеры.

---

### 📡 Блок L. LEARNING STATE

| Состояние | Признак | Действие |
|---|---|---|
| 🟢 Обучена | ≥10 конв/нед + CPA стабильна ±20% | Не трогать |
| 🟡 Обучается | <14 дней с запуска | Ждать, настройки не менять |
| 🔴 Голодает | <7 конв/нед, >14 дней | Расширить гео / добавить микро-цель / снизить CPA-цель |
| 🔴 Переобучается | Была смена цели/бюджета/стратегии | 7-14 дней данные мутные |
| 🔴 В DSP | CPC <10₽ + bounce >65% + «пол не определён» >70% | Блок площадок → расписание → провокационный текст |

---

### 🧠 Блок O. OFFER × LANDING

Соответствие обещания объявления и первого экрана лендинга.

- «Уехал геймером — вернулся разработчиком» → landing с формой возраста ✅
- «Цены на смены» → landing без цен первым экраном 🔴

Метрики соответствия:
- Доля визитов, доскроллививших до Age-секции
- Время до первого взаимодействия (<30 сек → плохой match)

---

### 💰 Блок E. ECONOMICS (еженедельно)

| Юнит | Формула | Норма |
|---|---|---|
| Leads / 1000₽ | leads × 1000 / spend | >2 |
| Cost per micro_age | spend / micro_selects | <50₽ |
| Cost per phone_click | spend / phone_clicks | <500₽ |
| Доля Direct в миксе | direct / (direct+vk+organic) | 40-60% |

**О LTV для АйДаКемп (факт, данные клиента):**
- Лагерь — разовая покупка по своей природе
- Типичный путь: 1 смена, максимум 2-3 раза за «карьеру» ребёнка
- Единичные случаи возврата до 6 раз — исключения, не правило
- **LTV для расчёта юнит-экономики можно считать как 1.0-1.3 смены среднего чека**, не применять модели с высокой повторяемостью (SaaS/ритейл)

Это значит: CAC ≤ 1× средний чек = безопасно; CAC ≤ 1.5× = уже рискованно.

---

### 🔍 Блок Q. QUALITY SCORE (еженедельно, гипотеза)

Яндекс формулу не публикует. Индикаторы (гипотеза):
- AvgImpressionPosition хуже 2.5 → мало показов в блоке, низкий QS
- AvgCpc группы в 1.5× выше медианы кампании → вероятно ниже качество

Проверять тренды, не абсолютные значения.

## Часть III. Формат отчёта РАДАР 2.1

```
РАДАР — [дата]
Оценка: 🟢 / 🟡 / 🔴

M   CPA [X]₽ ([±Y]%) | расход [X]₽ | баланс [X] дней
S   РСЯ: [состояние] ([конв/нед], CPA-факт [X]₽ vs цель [Y]₽)
    Поиск: [состояние]
    Ретаргет: [состояние]
A   yclid-матч [X]% | Undetermined [X]%
G   Группы 🔴: [список]
D   [для каждой 🔴 группы — выжимка D.1-D.7]
B   Корректировки — аудит (дубли / гео-минимумы / <100-сегменты)
L   [статусы обучения по всем группам]
O   Офферы vs лендинги: [проблемные пары]
E   [юнит-экономика]
Q   [quality score — гипотетические индикаторы]

ТОП-3 ACTIONS:
1. ...
2. ...
3. ...
```

## Часть IV. Что добавлено vs РАДАР 1.0

| Блок | 1.0 | 2.1 |
|---|---|---|
| Анализ | Площадки + устройства + демо отдельно | Всегда **кросс-таблицы** (устройство × демо × гео × час) |
| Стратегия | Не проверялось | Блок S |
| Атрибуция | Не проверялось | Блок A |
| Корректировки | Список | Блок B: перемножение + приоритет + ≥100 |
| Keywords | По расходу | Разбивка по match-type + категории автотаргетинга |
| ML state | Неявно | Блок L: 5 состояний + действия |
| Офферы | Описательно | Блок O: оффер ↔ landing |
| LTV | — | Блок E с учётом разовой природы покупки АйДаКемп |
| Глубина | До площадки | До `(день × группа × объявление × площадка × устройство × демо × гео × час)` |

## Открытые вопросы (гипотезы — требуют проверки)

- Формула quality score Директа — официально не публикуется (гипотеза: AvgImpressionPosition + AvgCpc как индикаторы)
- `ym:s:<attribution>DirectPlatform` — даёт ли площадку или только «Search/Network» (проверить)
- Точный алгоритм определения DSP-трафика на стороне Яндекса (внешне не документирован)
- Достаточная ли корреляция `micro_age_select ↔ lead` ≥0.7 — проверить на наших данных (гипотеза, пока не измерено)
