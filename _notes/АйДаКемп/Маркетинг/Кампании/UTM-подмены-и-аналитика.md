## 📐 Схема UTM-подмен (как работает сейчас)

### Параметр `utm_h1` — управляет заголовком на сайте

| utm_h1 | Какую аудиторию ведёт | Примеры заголовков на сайте |
|--------|----------------------|----------------------------|
| `it` | Ищут «IT-лагерь» | «IT-лагерь для детей 10–13 лет» |
| `brand` | Ищут «АйДаКемп» напрямую | «АйДаКемп — IT-лагерь 2026» |
| `age` | Ищут «лагерь 10-13 лет» | «IT-лагерь 10–13 лет — Подмосковье» |
| `camp` | Ищут «детский лагерь» | «Детский лагерь Подмосковье 2026» |
| `nophone` | Ищут «лагерь без телефонов» | «Детский лагерь без гаджетов» |
| `price` | Ищут «цена лагеря» | «IT-лагерь — от 48 000 ₽» |

### Параметр `utm_campaign` — откуда идёт трафик

| utm_campaign | Тип | Площадка |
|-------------|-----|---------|
| `search_it_core_msk_mo` | Поиск | Яндекс |
| `search_brand_msk_mo` | Поиск (бренд) | Яндекс |
| `search_age_10_13_msk_mo` | Поиск (возраст) | Яндекс |
| `search_camp_msk_mo` | Поиск (лагерь) | Яндекс |
| `search_nophone_msk_mo` | Поиск (без телефонов) | Яндекс |
| `search_price_msk_mo` | Поиск (цена) | Яндекс |
| `rsya_2026` | РСЯ | Яндекс сеть |
| `retarget_hot` | Ретаргет горячий | Яндекс |
| `retarget_warm` | Ретаргет тёплый | Яндекс |
| `retarget_crm_leads` | Ретаргет по CRM | Яндекс |
| `retarget_content` | Ретаргет по контенту | Яндекс |
| `codims` | Школа (ретаргет) | Яндекс |

### Параметр `utm_content` — конкретный оффер/сегмент (для РСЯ)

| utm_content | Аудитория / боль |
|------------|-----------------|
| `parents` | Родители — доверие, безопасность |
| `edu` | Образование — проекты, Python |
| `keys` | По ключевым словам |
| `result` | Результат за смену |
| `books` | Осознанный формат |
| `competitors` | Сравнение с конкурентами |
| `addiction` | Зависимость от телефона |

## 🚨 Проблема: нет данных о конверсиях по UTM в PostgreSQL

**Что есть:**
- ✅ UTM-параметры в объявлениях (ads_snapshot)
- ✅ Данные по кликам и затратам (direct_placements)
- ❌ Нет таблицы metrika_utm (конверсии по UTM из Метрики)
- ❌ Нет таблицы metrika_goals (достижение целей)

**Что это означает:**
Мы знаем сколько потратили на каждую кампанию, но **не знаем** сколько конверсий (выбор возраста, заявки) дал каждый utm_h1 / utm_campaign.

Без этого невозможно понять: какой заголовок конвертит лучше.

## ✅ Как настроить аналитику за ~1 час (план для Даны)

### Что нужно получить

```
utm_campaign | utm_h1 | utm_content | визиты | выбор возраста | заявки | CR%
```

### Шаг 1: Получить данные из Яндекс.Метрики (15 мин)

Через интерфейс Метрики → Отчёты → UTM-метки:

1. Зайти в Метрику → **Стандартные отчёты → Источники → UTM-метки**
2. Выбрать период: последние 30 дней
3. Группировка: `utm_campaign`, затем `utm_content` (или `utm_term`)
4. Добавить столбцы целей:
   - ✅ Цель 541048270 «Выбор возраста»
   - ✅ Цель 541048197 «Отправка заявки»
5. Экспортировать в CSV

**Или через API** (если уже подключён MCP для Метрики):
```
GET https://api-metrika.yandex.net/stat/v1/data
?id=COUNTER_ID
&metrics=ym:s:visits,ym:s:goal541048270reaches,ym:s:goal541048197reaches
&dimensions=ym:s:UTMCampaign,ym:s:UTMContent
&date1=30daysAgo&date2=today
```

### Шаг 2: Создать таблицу в PostgreSQL (5 мин)

```sql
CREATE TABLE IF NOT EXISTS metrika_utm (
  id SERIAL PRIMARY KEY,
  date_from DATE,
  date_to DATE,
  utm_source TEXT,
  utm_medium TEXT,
  utm_campaign TEXT,
  utm_content TEXT,
  utm_h1 TEXT,
  visits INTEGER DEFAULT 0,
  goal_age_select INTEGER DEFAULT 0,   -- 541048270 Выбор возраста
  goal_form_submit INTEGER DEFAULT 0,  -- 541048197 Отправка заявки
  cr_age_select NUMERIC(5,2),          -- конверсия в выбор возраста
  cr_form_submit NUMERIC(5,2),         -- конверсия в заявку
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Шаг 3: Залить данные (5 мин)

Либо вручную из CSV, либо через Python-скрипт на сервере.

### Шаг 4: Готовый SQL-отчёт (сразу работает)

```sql
-- Конверсия по типу заголовка (utm_h1)
SELECT 
  utm_h1,
  SUM(visits) as визиты,
  SUM(goal_age_select) as выбор_возраста,
  ROUND(100.0 * SUM(goal_age_select) / NULLIF(SUM(visits), 0), 2) as CR_возраст,
  SUM(goal_form_submit) as заявки,
  ROUND(100.0 * SUM(goal_form_submit) / NULLIF(SUM(visits), 0), 2) as CR_заявка
FROM metrika_utm
WHERE date_from >= CURRENT_DATE - 30
GROUP BY utm_h1
ORDER BY CR_возраст DESC;
```

```sql
-- Конверсия по кампании
SELECT 
  utm_campaign,
  SUM(visits) as визиты,
  SUM(goal_age_select) as выбор_возраста,
  ROUND(100.0 * SUM(goal_age_select) / NULLIF(SUM(visits), 0), 2) as CR_возраст,
  SUM(goal_form_submit) as заявки
FROM metrika_utm
WHERE date_from >= CURRENT_DATE - 30
GROUP BY utm_campaign
ORDER BY CR_возраст DESC;
```

```sql
-- Оффер (utm_content) для РСЯ — что лучше конвертит
SELECT 
  utm_content,
  SUM(visits) as визиты,
  SUM(goal_age_select) as выбор_возраста,
  ROUND(100.0 * SUM(goal_age_select) / NULLIF(SUM(visits), 0), 2) as CR_возраст
FROM metrika_utm
WHERE utm_medium = 'cpc' AND utm_campaign LIKE 'rsya%'
GROUP BY utm_content
ORDER BY CR_возраст DESC;
```

## 📊 Что ожидаем увидеть (гипотезы)

### По utm_h1 (заголовки):

| utm_h1 | Гипотеза CR | Почему |
|--------|------------|--------|
| `age` | Высокий | Точный возраст — аудитория сразу видит «это про нас» |
| `nophone` | Средний | Боль актуальная, но более широкая |
| `it` | Средний | IT-родители — думающая аудитория |
| `price` | Низкий | Ценовые запросы часто сравнивают |
| `brand` | Высокий | Уже знают нас — тёплые |
| `camp` | Низкий | Самый широкий запрос — много нецелевых |

### По utm_content для РСЯ:

| utm_content | Гипотеза |
|------------|---------|
| `addiction` | Высокий — боль с телефоном резонирует |
| `result` | Высокий — конкретный результат убеждает |
| `parents` | Средний — доверие, но менее острое |
| `competitors` | Может быть высокий — провокативный заголовок |
| `books` | Низкий — слишком мягко |
