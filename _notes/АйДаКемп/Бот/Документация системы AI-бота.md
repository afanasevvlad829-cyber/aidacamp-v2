## Обзор системы

AI-чат-ассистент на странице `/ask/` сайта `aidacamp.ru`. Цель — помочь маме получить ответы на вопросы о лагере и довести до бронирования, не звоня менеджеру. Бот общается как «подруга которая уже отправляла своего ребёнка», не продавец.

**Технологический стек:**
- Astro 6.x (`prerender: true` для `/ask/`, SSR для `/api/*`)
- @astrojs/node adapter
- Anthropic Claude Haiku (claude-haiku-4-5-20251001)
- Zod (валидация схемы ответа)
- PostgreSQL (логирование галлюцинаций)
- Bootstrap Icons (через кастомный CSS-манифест)

## Поток запроса (Request Flow)

```
Пользователь вводит текст
        ↓
[ask.astro] go(txt)
  - Добавляет сообщение в историю (max 10 последних)
  - POST /api/ask { message, history[] }
        ↓
[ask.ts] POST handler
  1. Валидирует: message не пустой
  2. Берёт последние 10 сообщений из history
  3. Вызывает claude.messages.create()
     - model: claude-haiku-4-5-20251001
     - max_tokens: 1024
     - system: systemPrompt (с cache_control: ephemeral)
     - messages: [...history, { role:'user', content:message }]
  4. Парсит ответ: ищет JSON через regex /\{[\s\S]*\}/
  5. ResponseSchema.safeParse() — Zod-валидация
  6. Если валидация провалилась → fallback (берёт rawParsed.text)
  7. Запускает validateBotResponse() асинхронно (не блокирует)
  8. Возвращает { state, text, block_type, block_data, chips }
        ↓
[ask.astro] обрабатывает ответ
  - addMsg('ai', data.text) — typewriter эффект
  - renderBlock(data.block_type, data.block_data) — рендер визуального блока
  - addChips(data.chips) — кнопки-подсказки
```

campData.shifts[]          // Массив смен

## Файл: `src/lib/ai/systemPrompt.ts`

Экспортирует строку `systemPrompt` — большой текстовый документ для Claude.

### Разделы промпта (в порядке следования):

| Раздел | Что содержит |
|---|---|
| КТО ЧИТАЕТ | Портрет мамы: 35–45 лет, Москва, смартфон |
| ОБРАЩЕНИЕ | Всегда «Вы», гендер ребёнка из текста |
| ТОНАЛЬНОСТЬ | Подруга, не продавец. Что запрещено (педагогика, эмодзи) |
| ФОРМАТ ОТВЕТА | JSON-схема: text, block_type, block_data, chips |
| ПРАВИЛА БЛОКОВ | Когда показывать визуальные блоки, а когда block_type: null |
| ОБЪЯСНЕНИЕ НАПРАВЛЕНИЙ | Что такое Scratch / Python / Unity / Minecraft / Кибербез / AI |
| ХАКАТОН | Отдельное соревнование, 2 последних дня, 10 часов, команды 5–7 |
| ЗАКРЫТИЕ ВОЗРАЖЕНИЙ | ~15 типичных вопросов мам с ответами |
| КАРТА ССЫЛОК | Якорные ссылки на разделы сайта |
| БАЗА ЗНАНИЙ | Смены (из campData), курсы, все факты |

### ⚠️ Критическое правило блоков:

Блок показывается **только** когда мама явно просит список/обзор:
- `"какие смены есть"` → `block_type: "smeny"`
- `"какие курсы"` → `block_type: "courses"`
- `"расскажи про Python"` → `block_type: null` (текстовый ответ)
- Блок уже был в диалоге → `block_type: null` (не повторять)

## Файл: `src/lib/ai/responseSchema.ts`

Zod-схема валидации ответа Claude.

```typescript
ResponseSchema = z.object({
  text: z.string(),                          // HTML-текст ответа
  block_type: z.enum([
    'smeny', 'courses', 'day_schedule',
    'conditions', 'prices', 'location',
  ]).nullable(),
  block_data: z.record(z.string(), z.any()).nullable(),
  chips: z.array(ChipSchema).max(4),
})

ChipSchema = z.object({
  label: z.string(),
  query: z.string().optional(),              // текст отправляется в чат при клике
  action: z.enum(['book', 'contact_request', 'link']).optional(),
  url: z.string().optional(),               // для action: 'link'
})
```

**Три типа чипов:**
- `query` → клик отправляет текст как новый вопрос
- `action: 'book'` → открывает попап бронирования (оранжевый CTA)
- `action: 'contact_request'` → показывает карточку WhatsApp/Telegram
- `action: 'link'` + `url` → открывает ссылку в новой вкладке

## Файл: `src/lib/ai/validator.ts`

Асинхронный пост-обработчик. Запускается **после** отправки ответа пользователю, не блокирует.

### `validateBotResponse(userMessage, botResponse): Promise<ValidationResult>`

- Вызывает Claude Haiku с системным промптом-контролёром
- Проверяет ТОЛЬКО числовые факты (цены, даты, проценты, условия)
- Не проверяет стиль и формулировки
- При ошибке — возвращает `{valid: true}` (fail-safe, не ломает основной флоу)

### `logGuardFlag(userMessage, botResponse, issue, correction, wasCorrected)`

- Записывает в таблицу `ai_guard_flags` в PostgreSQL
- Создаёт новый `pg.Pool` на каждый вызов (не оптимально, TODO)
- Ошибки подключения игнорируются (`.catch(() => {})`)

### Факты в FACTS-константе validator.ts

**⚠️ Проблема дублирования:** факты продублированы в `campData.ts` и в `validator.ts`. При изменении данных нужно обновить ОБА файла. Это технический долг.

## Файл: `src/pages/api/ask.ts`

SSR-эндпоинт. Принимает POST, возвращает JSON.

### Входные данные:
```typescript
{
  message: string,     // текст пользователя
  history: Array<{     // история диалога
    role: 'user' | 'assistant',
    content: string
  }>,
  sessionId?: string   // не используется в текущей реализации
}
```

### Выходные данные (успех):
```json
{
  "state": "ok",
  "text": "HTML строка с <strong>акцентами</strong>",
  "block_type": "smeny" | "courses" | ... | null,
  "block_data": { "age": 10 } | null,
  "chips": [...]
}
```

### Выходные данные (ошибка):
```json
{
  "state": "error",
  "text": "Что-то пошло не так...",
  "block_type": null,
  "block_data": null,
  "chips": [{ "label": "Написать в WhatsApp", "query": "..." }]
}
```

### Fallback логика (ResponseSchema не прошла):
1. Если `rawParsed.text` — строка → вернуть его как text
2. Иначе → вырезать ```json блоки из raw, взять остаток
3. Если пусто → «Уточните вопрос.»
4. `block_type`, `block_data`, `chips` берутся из rawParsed напрямую

## Файл: `src/pages/ask.astro`

Статическая страница (`prerender: true`). Весь JS — в `<script is:inline>` теге.

### Глобальные переменные:

| Переменная | Тип | Описание |
|---|---|---|
| `busy` | boolean | Запрос в процессе, блокирует повторную отправку |
| `active` | boolean | Был ли хоть один обмен (скрывает intro-экран) |
| `history` | Array | Последние сообщения для контекста (max 20, обрезается до 10 для API) |
| `aiState` | string | `'idle'` / `'think'` / `'speak'` (используется для микрофона) |
| `contactOffered` | boolean | Предложили ли уже написать менеджеру |

### Константы данных:

| Константа | Что содержит |
|---|---|
| `SMENY` | Массив смен с полями `occupied`, `total` для анимированного бара |
| `COURSES` | Массив курсов (дублирует `campData.ts` для клиентского JS — намеренно) |
| `DAY` | Расписание дня (8:30–22:00) |
| `COND` | Условия проживания (6 блоков) |
| `COURSE_PALETTE` | Цветовая схема для каждого курса (6 цветов: синий/зелёный/розовый/фиолетовый/красный/жёлтый) |

### Ключевые функции:

#### `mkEl(tag, css, html)`
Хелпер создания DOM-элементов с inline-стилями. Используется во всех block-рендерерах.
```javascript
// Зачем inline-стили?
// Astro скопирует CSS-классы из <style> тегов (добавит hash data-astro-xxx).
// Динамически создаваемые через JS элементы этот hash НЕ получают.
// Поэтому CSS классы на них не работают.
// Решение: всё через style.cssText напрямую.
```

#### `blockSmeny()`
Рендерит карточки смен с анимированными барами заполнения.
- Каждая карточка: название / даты / цена / бар (занято/свободно)
- Анимация бара: `setTimeout(120 + idx*60ms)` — каскадный старт
- Клик по доступной смене → `openPopup()`

#### `blockCourses(blockData)`
Рендерит сетку курсов (2 колонки).
- Фильтрует по возрасту если `blockData.age` задан
- Клик по тайлу → `go('Расскажи подробнее про ' + course.name)`

#### `blockDay()`, `blockCond()`, `blockLocation()`, `blockPrices()`
Используют `innerHTML` с CSS-классами. **⚠️ Могут не работать корректно** из-за Astro scoping — если что-то отображается без стилей, нужно переписать на `mkEl()` как blockSmeny/blockCourses.

#### `addMsg(role, html)`
- `role: 'user'` → мгновенно
- `role: 'ai'` → typewriter эффект (18ms/символ)
- HTML-теги проходят мгновенно, символы — посимвольно
- Во время печати — мигающий курсор `▋`

#### `addChips(items)`
Кнопки-подсказки под ответом. Полностью на inline-стилях (по той же причине что mkEl).
- Три визуальных стиля: CTA (оранжевый) / soft (зелёный) / default (стекло)
- Hover-эффекты через `onmouseenter`/`onmouseleave`

#### `go(txt)`
Главная функция отправки. Алгоритм:
1. `busy = true`, дизейблим кнопку
2. Добавляем сообщение в историю и в чат
3. Показываем typing indicator
4. POST /api/ask
5. Прячем typing, рендерим ответ + блок + чипсы
6. `busy = false`

#### `send()`
Читает `#inp`, очищает поле, вызывает `go()`.

#### `trackSession(data)`
Пишет данные в `localStorage` ключ `ask_session`. Отправляет в GTM через `dataLayer.push()`.
Трекируемые поля: `age`, `booked`, `contact_requested`, `blocks_shown`, `topics`.

#### `openPopup()` / `closePopup()`
Попап бронирования. При открытии → Metrika goal `ai_chat_complete`.

#### `submitBooking()`
POST `/api/lead` с данными: `phone`, `shift`, `age`, `source: 'ask-chat'`.
После успеха → кнопка «Заявка принята ✓».

## CSS-архитектура

**Проблема:** `<style>` в Astro автоматически добавляет хэш-атрибут (`data-astro-xxx`). Элементы созданные через JS не получают этот атрибут → CSS классы не применяются.

**Решение:** все динамические блоки используют `mkEl()` с `style.cssText` напрямую. CSS-классы (`.chip`, `.vblock`, `.block-*`) описаны в `<style>` но применяются только к статическому HTML.

**CSS-переменные:**
```css
--or: #ec7c00      /* оранжевый бренд */
--ord: #c45f00     /* тёмный оранжевый (для текста поверх!) */
--orl: rgba(236,124,0,.12)
--nv: #060e1a      /* основной фон */
--nv2: #0a1628
--nv3: #0f2040
--sans: 'Manrope', sans-serif
--mono: 'JetBrains Mono', monospace
```

**Шрифты (по стандарту дизайна):**
- Body текст: min 16px, line-height: 1.65–1.70
- Secondary: min 14px
- Micro-labels (бейджи): min 12px

**Контраст (по стандарту):**
- ⚠️ Белый текст на `#ec7c00` = 2.9:1 — ПРОВАЛ WCAG
- ✓ Белый текст на `#c45f00` = 4.6:1 — проходит AA
- CTA кнопки используют `linear-gradient(135deg, #c45f00, #a34e00)` — OK

## Текущие проблемы (технический долг)

### P0 — Критические

1. **Дублирование данных в validator.ts**
   - Факты продублированы в `campData.ts` и в `FACTS`-константе `validator.ts`
   - При изменении цен/условий — надо менять в обоих файлах
   - Решение: импортировать из campData в validator, генерировать FACTS динамически

2. **blockDay/blockCond/blockLocation/blockPrices на CSS-классах**
   - Четыре рендерера используют `innerHTML` с CSS-классами вместо `mkEl()`
   - Могут не стилизоваться корректно (Astro scoping)
   - Решение: переписать на `mkEl()` как blockSmeny/blockCourses

### P1 — Важные

3. **pg.Pool создаётся на каждый вызов logGuardFlag**
   - `new pg.Pool()` → `query()` → `pool.end()` на каждый запрос
   - При высокой нагрузке — утечка соединений
   - Решение: вынести Pool в модульную переменную с переиспользованием

4. **sessionId не используется**
   - В `AskRequest` есть `sessionId?: string` но не передаётся в Anthropic и не логируется
   - Если нужна аналитика сессий — нужно реализовать

5. **Нет rate limiting на /api/ask**
   - Любой может слать запросы в цикле за счёт API
   - Решение: Redis counter по IP или Cloudflare Rate Limiting

6. **История в browser memory, не персистируется**
   - Перезагрузка страницы → история теряется
   - При бронировании менеджер не видит о чём спрашивали
   - Решение: localStorage + передавать sessionId при отправке заявки

### P2 — Желательные

7. **Нет retry логики при ошибке API**
   - Один неудачный запрос → пользователь видит ошибку
   - Решение: 1 автоматический retry с задержкой 1s

8. **Микрофон (Web Speech API) не реализован**
   - Иконка микрофона в UI есть, `toggleMic()` написан, но реально не работает
   - Решение: доделать или убрать кнопку

9. **Попап бронирования с hardcoded сменами**
   - Смены в `<select>` прописаны хардкодом в HTML
   - При обновлении смен — нужно менять вручную в двух местах
   - Решение: рендерить select из `SMENY` данных через JS
