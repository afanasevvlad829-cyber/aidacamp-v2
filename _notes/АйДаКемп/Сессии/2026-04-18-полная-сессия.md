## 🎯 Новый принцип для CM v3 (Decision Engine)

**Пользователь отверг модель "broadcast + список задач человеку"**. Вместо этого:

```
Каждая аномалия → классификатор:
  ├─ AUTO-FIX        → агент ВЫПОЛНИЛ сам, строка в отчёте "✔ Заблокировал X, -8К расхода"
  ├─ ALREADY-HANDLED → не упоминать
  └─ NEEDS-HUMAN     → 1 короткий вопрос + 2-3 кнопки "Вариант A / B / C"
                        клик → агент ВЫПОЛНЯЕТ выбранный вариант
```

**Примеры auto-fix правил:**
- DSP-плейсмент >80₽ расход + не в whitelist → `campaigns.update` ExcludedSites
- Цель Метрики 24ч = 0 при visits > 50 → playwright smoke test + alert
- CPC РСЯ <10₽ → добавить `mytarget_partners` в pads exclude

**Примеры needs-human (кнопки = готовые варианты, не feedback):**
- WSL исчерпан → `[25К / 50К / 75К]` на следующую неделю
- 0 конверсий 2 дня → `[Снизить CPA / Сменить цель / Пауза]`
- Новая кампания → `[Packet PAY_FOR / Individual AVG_CPA / Individual MAX_CONV]`

Клик по кнопке не "рейтингует" действие, а **триггерит Executor node** через callback_data c точным параметром (например `fb:<fp>:raise_wsl:75000` → HTTP request → Direct API update).

**CM v3 компоненты (план):**
1. Collect anomalies (Postgres) — как сейчас
2. **NEW: Fact Gathering** — по каждой аномалии сходить в Direct/VK/Metrika API, собрать actual state
3. **NEW: Classifier** (JS rules + таблица правил) — auto-fix vs needs-human
4. **NEW: Executor** (switch → HTTP Request nodes) — для auto-fix
5. LLM (только для needs-human) — формулирует 1 вопрос + 2-3 варианта
6. Format Telegram — сообщение с inline-кнопками, где callback_data = выполнимое действие
7. Callback Handler (уже есть tg-callback-handler-1d0c6229) — при клике вызывает Executor с выбранным вариантом
