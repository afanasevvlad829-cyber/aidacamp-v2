# Политика обработки ПД, cookies, согласия — инструкция для владельца сайта

> Документ для тех, кто делает сайт с формами обратной связи. Покажет что обязательно по 152-ФЗ + автоматизированным проверкам РКН-2026, как мы это реализовали на aidacamp.ru, и как любой владелец может скопировать схему под себя.

**Источник по требованиям РКН-2026:** [vc.ru/legal/2891844-roskomnadzor-avtomatizirovannye-proverki-saitov](https://vc.ru/legal/2891844-roskomnadzor-avtomatizirovannye-proverki-saitov)

## 1. Что проверяет робот РКН (автоматизированная проверка)

С 2025 года Роскомнадзор использует бота-сканер, который **автоматически** проходит по сайтам и проверяет 5 точек. После находки робот передаёт случай человеку для ручной проверки глубины.

### Чек-лист проверок

| # | Что проверяется | Проверка | Если нет |
|---|---|---|---|
| 1 | **Политика обработки ПД** | Доступна со всех страниц (футер). URL вроде `/privacy-policy/`. Содержит цели, категории данных, сроки хранения, порядок удаления | 100-300 тыс ₽ за неуведомление |
| 2 | **Чекбокс согласия под каждой формой** | Не проставлен по умолчанию. Без него отправка формы невозможна | 100-300 тыс ₽ за сбор без согласия |
| 3 | **Согласие на обработку ПД** (отдельный документ) | Письменный документ-шаблон по `/soglasie-na-obrabotku-personalnyh-dannyh/` | Отсутствие = риск штрафа |
| 4 | **Уведомление о Я.Метрике / Clarity** | В политике явно указано: «используем Я.Метрику для аналитики, она собирает анонимные cookies» | 90 тыс ₽ за исправление |
| 5 | **Уведомление в реестре операторов** | Подача формы на rkn.gov.ru, организация в реестре | Базовое требование |

### Штрафы (актуальные суммы)
- **100-300 тыс ₽** — неуведомление РКН или сбор без согласия
- **1-15 млн ₽** — утечка персданных
- **90 тыс ₽** — несвоевременное исправление нарушений после предписания

## 2. Как реализовано у нас на aidacamp.ru

### Структура: 3 страницы + 2 чекбокса в каждой форме

```
/privacy-policy/                              ← Политика обработки ПД (24 статьи, 152-ФЗ + GDPR-friendly)
/soglasie-na-obrabotku-personalnyh-dannyh/    ← Согласие пользователя (текст которое он принимает)
В каждой форме (LeadForm + ShiftBookModal):
  ☐ Ознакомлен(а) с Политикой обработки ПД      → ссылка на /privacy-policy/
  ☐ Согласен(а) на обработку ПД                  → ссылка на /soglasie-na-obrabotku-personalnyh-dannyh/
  Кнопка submit заблокирована пока оба не отмечены
```

### Где живёт код (для повторения)

| Файл | Что делает |
|---|---|
| `src/pages/privacy-policy.astro` | Главный документ политики 152-ФЗ. ~180 строк юридического текста + контакты ответственного |
| `src/pages/soglasie-na-obrabotku-personalnyh-dannyh.astro` | Текст согласия который пользователь принимает галочкой |
| `src/components/LeadForm.astro` lines 76-90 | Два чекбокса с ссылками на оба документа. JS блокирует submit пока оба не checked |
| `src/components/shifts/ShiftBookModal.astro` lines 46-55 | Те же два чекбокса в модалке заявки на смену |
| `src/layouts/Base.astro` lines 80-90 | Логика opt-out: если в cookie стоит `ym_disable96499295=true` → Метрика и Clarity не запускаются (для админов и спорных регионов) |

### Особенности реализации

**1. Submit-кнопка блокируется через JS**
```js
function bothConsentsChecked() {
  return policyCheckbox.checked && consentCheckbox.checked;
}
submitBtn.disabled = !bothConsentsChecked();
```
Если хоть одна галочка снята — кнопка серая, отправка невозможна.

**2. Чекбоксы НЕ преchecked**
```html
<input type="checkbox" data-book-consent-policy ... />
```
Атрибута `checked` нет — пользователь должен проставить активно.

**3. Текст с inline-ссылками на документы**
```html
<span>Ознакомлен(а) с <a href="/privacy-policy/" class="text-primary underline">Политикой обработки ПД</a></span>
<span>Согласен(а) на <a href="/soglasie-na-obrabotku-personalnyh-dannyh/" class="text-primary underline">обработку ПД</a></span>
```
Ссылки видны и кликабельны — пользователь может прочитать перед галочкой.

**4. Cookie opt-out (для согласных пользователей)**
В Base.astro есть логика: если в URL `?ym_disable=true` или в localStorage стоит флаг — Метрика и Clarity не подгружаются. Это запасной механизм для тех, кто отправил GDPR-запрос.

## 4. Как скопировать схему под СВОЙ сайт (template для владельца)

### Шаг 1: Зарегистрироваться в реестре
Зайти на [rkn.gov.ru](https://rkn.gov.ru/personal-data/register/) → подать форму уведомления → дождаться номера в реестре.
**Время:** ~30 мин на форму, регистрация мгновенная (бесплатно).

### Шаг 2: Создать 2 документа

**`/privacy-policy/`** должна содержать:
1. Кто оператор (название организации, ИНН, юр. адрес)
2. Какие данные собираем (имя, телефон, email, cookies)
3. С какой целью (обработка заявок, аналитика, контакт)
4. На каком основании (152-ФЗ, согласие пользователя)
5. Сколько храним (например: «до отзыва согласия + 3 года для бухгалтерии»)
6. Кому передаём (например: CRM-провайдер, аналитика — указать названия)
7. **Явно перечислить системы аналитики**: Яндекс.Метрика, Google Analytics, Microsoft Clarity, etc.
8. Права субъекта (доступ, удаление, отзыв согласия)
9. Контакты ответственного за обработку ПД (email: например, dpo@example.com)
10. Дата актуальной редакции

**`/soglasie-na-obrabotku-personalnyh-dannyh/`** должна содержать:
1. «Я даю согласие оператору [название] на обработку моих ПД»
2. Перечень данных (ФИО, телефон, email, IP, cookies)
3. Цели обработки
4. Срок действия согласия
5. Право отзыва (как отозвать)

### Шаг 3: 2 чекбокса в каждой форме

Любая форма (заявка, обратная связь, подписка) должна иметь:

```html
<label>
  <input type="checkbox" id="consent-policy" required>
  Я ознакомлен(а) с <a href="/privacy-policy/">Политикой обработки ПД</a>
</label>

<label>
  <input type="checkbox" id="consent-data" required>
  Я даю <a href="/soglasie-na-obrabotku-personalnyh-dannyh/">согласие на обработку ПД</a>
</label>

<button type="submit" disabled id="submit-btn">Отправить</button>

<script>
  const policy = document.getElementById('consent-policy');
  const data = document.getElementById('consent-data');
  const btn = document.getElementById('submit-btn');
  function check() { btn.disabled = !(policy.checked && data.checked); }
  policy.addEventListener('change', check);
  data.addEventListener('change', check);
</script>
```

**Критично:**
- Оба чекбокса не должны быть pre-checked
- Submit заблокирован JS пока оба не отмечены
- Ссылки внутри label видны и кликабельны
- Чекбоксы — отдельные (не один общий «согласен со всем»)

### Шаг 4: Ссылка на политику в футере

В подвале на каждой странице:
```html
<footer>
  <a href="/privacy-policy/">Политика конфиденциальности</a>
</footer>
```

### Шаг 5: Cookie-opt-out (для запросов GDPR-style)

Добавить в `<head>` логику:
```js
// Если в URL есть ?disable_metrika=true → проставить cookie
// Если cookie стоит → не загружать аналитику
if (location.search.includes('disable_metrika=true')) {
  document.cookie = 'ym_disabled=true; expires=...';
}
if (document.cookie.includes('ym_disabled=true')) {
  // НЕ загружать Метрику
}
```

## 5. Cookie-баннер (если хочешь сделать как у крупных)

**Шаблон HTML:**
```html
<div id="cookie-banner" class="fixed bottom-0 left-0 right-0 bg-white border-t border-slate-200 shadow-lg p-4 z-[100]" role="dialog" aria-label="Уведомление о cookies">
  <div class="mx-auto max-w-[1200px] flex flex-col md:flex-row items-center gap-4">
    <p class="text-[14px] text-body-muted flex-1">
      Мы используем cookies для улучшения сайта и аналитики (Яндекс.Метрика).
      Продолжая просмотр, вы соглашаетесь с
      <a href="/privacy-policy/" class="text-primary underline">Политикой</a>.
    </p>
    <div class="flex gap-2 shrink-0">
      <button type="button" data-cookie-decline class="px-4 py-2 text-[14px] text-body-muted hover:text-body">Только необходимые</button>
      <button type="button" data-cookie-accept class="px-5 py-2 rounded-lg bg-primary text-white text-[14px] font-semibold">Принять</button>
    </div>
  </div>
</div>

<script>
  const banner = document.getElementById('cookie-banner');
  if (localStorage.getItem('cookie-decision')) banner.style.display = 'none';
  banner?.querySelector('[data-cookie-accept]').addEventListener('click', () => {
    localStorage.setItem('cookie-decision', 'accepted');
    banner.style.display = 'none';
  });
  banner?.querySelector('[data-cookie-decline]').addEventListener('click', () => {
    localStorage.setItem('cookie-decision', 'declined');
    document.cookie = 'ym_disabled=true; max-age=31536000; path=/';
    banner.style.display = 'none';
  });
</script>
```

**Логика:** показ при первом визите → выбор «принять / только необходимые» → решение в localStorage → НЕ показывать снова.

## 7. Опасные ошибки (НЕ делать)

❌ **Pre-checked чекбоксы** — РКН считает это «навязанным согласием»
❌ **Один чекбокс «Согласен со всем»** — должно быть два отдельных (политика + согласие)
❌ **Submit активна без согласия** — должна быть disabled пока галочки не отмечены
❌ **Политика без упоминания Метрики** — это №1 нарушение, которое ловит автоматический бот
❌ **Без указания юридического лица** в политике — РКН не сможет идентифицировать оператора
❌ **Просрочена дата редакции** — должна быть дата не старше 1 года
