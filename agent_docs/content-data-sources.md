## 🎯 Единый источник смен, дат и цен — НЕ дублировать

**Один источник ДАННЫХ + одно правило роста.** Всё остальное (компоненты, бот, SEO) **выводится** — никаких хардкодов.

| Что | Источник правды | Как брать |
|---|---|---|
| **База цены, даты (start/end), длительность** | `src/data/shifts.ts` → `SHIFT_META` (+ строки `price:`/`startDate:` каждой смены) | импорт |
| **Какие смены открыты к брони** | `src/data/shifts.ts` → `mainShifts` / `shortShifts` | импорт массива |
| **Текущая цена (с ростом)** | `src/data/dynamicPrices.ts` (правило поверх `SHIFT_META`) | `getCurrentPrice(shiftId)` |
| **Цена трансфера от м. Солнцево** | `src/data/shifts.ts` → `TRANSFER_PRICE` | `TRANSFER_PRICE_FMT` / `TRANSFER_INFO` / `TRANSFER_PRICE_ROUNDTRIP_FMT` |

**📈 ЕДИНОЕ ПРАВИЛО РОСТА ЦЕНЫ (для всех смен одинаковое, в `dynamicPrices.ts`):**
1. До «старт − 30 дней» — цена = базовой.
2. За 30 дней до старта — разовый шаг **+5 %** к базе.
3. Далее каждый день **+500 ₽**.
4. На дату старта рост **останавливается** (цена фиксируется).
- Параметры: `RAMP_DAYS=30`, `STEP_PCT=0.05`, `DAILY_INC=500`. Менять правило → только эти константы.

**Правила:**
- Дату/базовую цену/длительность смены менять ТОЛЬКО в `shifts.ts`. `dynamicPrices.ts` берёт их из `SHIFT_META` и применяет правило роста — дублировать дату/цену в нём НЕЛЬЗЯ.
- Цену смены НИКОГДА не хардкодить в компонентах/боте/SEO — только `getCurrentPrice()`.
- Завершить/открыть смену = добавить/убрать её в `mainShifts`/`shortShifts` — **в одном месте**. Бот (`campData.ts`) и SEO (`SchemaOrg.astro`) фильтруются по этому списку автоматически.
- Бот не ведёт свой список смен: `campData.ts` берёт цены через `getCurrentPrice()` и фильтрует смены по `mainShifts`/`shortShifts`.
- Стражи `npm run check:prices` и `check:dates` роняют билд при литерале цены/даты смены вне `shifts.ts`.
- Цену трансфера (2000₽) НИКОГДА не хардкодить строкой в лендингах/промптах бота — только `TRANSFER_PRICE_FMT`/`TRANSFER_INFO`. Страж `npm run check:transfer` роняет билд при хардкоде «2 000 ₽» вне `shifts.ts` (инцидент: на 5+ лендингах цена трансфера разошлась на «бесплатно» vs «2000₽», т.к. хардкодилась в каждом файле отдельно).

## 🧱 Новые гео/возрастные SEO-лендинги — через `[slug]`, не копипастой

В `src/pages/` уже 180+ отдельных `.astro`-файлов под гео/возрастные ключи
(`lager-klin.astro`, `lager-11-let.astro` и т.п.) — это не забытый рефакторинг,
а результат сознательной SEO-политики: разная формулировка на каждой странице
защищает от того, что Google посчитает комбинаторные лендинги шаблонным
дублирующимся контентом (см. `src/data/seasons.ts`: «Тексты сезонов сознательно
НЕ клонируются — привет, Яндекс»). Массово переносить существующие страницы в
единый `[slug].astro`-шаблон **не нужно** — риск (просадка позиций у
проиндексированных страниц) больше выгоды (меньше файлов кода).

Правило — только для **новых** страниц:
- Если новая страница реально шаблонная (тот же гео/возрастной паттерн, без
  уникального смыслового угла) — заводи через `src/data/landings/` +
  `[slug].astro` (уже 17 записей), не копируй существующий `.astro`-файл.
- Если у страницы есть собственный смысловой угол (не просто «замени город») —
  обычный `.astro`-файл, как раньше.

> ⚠️ Инцидент 2026-06-20: бот предлагал завершённую Смену 2 (свой хардкод-список) и тянул цены из мёртвого `/var/www/aidacamp-data/shifts.json` (cron генерации исчез ~4 мая). Исправлено: бот фильтрует по `mainShifts`, SEO читает `getCurrentPrice()`, мёртвый файл убран, цены/даты единообразны через `SHIFT_META` + единое правило роста.

## 💰 Налоговый вычет — НЕЛЬЗЯ хардкодить одну цифру

Перед любым упоминанием — читай [`_notes/Библиотека знаний/Налоговый вычет — правила и данные.md`](../_notes/Библиотека%20знаний/Налоговый%20вычет%20—%20правила%20и%20данные.md).

Суммы по сменам 2026 (ориентир; реальная цена — из `dynamicPrices.ts`, см. секцию выше):
> ⚠️ Суммы вычета ниже зависят от образовательной части путёвки и текущей (растущей) цены — сверять при изменении цен, не хардкодить.

- Смена 2.1 (7 дн., 48 000 ₽) → **~2 800 ₽**
- Смена 4 (10 дн., 74 900 ₽) → **~4 800 ₽**
- Смена 2.2 (8 дн., 75 000 ₽) → **~5 800 ₽**
- Смена 3 (13 дн., 89 400 ₽) → **~5 200 ₽**
- Смена 2 (14 дн., 99 000 ₽) → **~6 000 ₽**
- Смена 1 (10 дн., 85 900 ₽) → **~6 200 ₽** ← максимум

> Формула: 13% × (цена − 3 800 ₽/день). `EDU_RESID_PER_DAY=3800` в `shifts.ts` (НЕ путать с `BYT_PER_DAY=6100` — это для возвратов по ФЗ №2300-1).

❌ ЗАПРЕЩЕНО: писать "до 5 434 ₽" или "до 5 200 ₽" — устаревшие цифры.
✅ Если нужна одна цифра: "до 6 200 ₽ (максимум, Смена 1)".
