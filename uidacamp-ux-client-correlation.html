🚨 Критическое расхождение: «Срочность» vs. реальный клиент

В PR #112 (закрыт) были реализованы scarcity-сигналы — «Осталось N мест», оранжевая граница карточки при ≥85% заполненности. Это прямое противоречие профилю клиента.

Портрет прямо говорит: «Что НЕ покупает Дарья: «Успейте — осталось 3 места» — она не из страха покупает». Наоборот, давление срочностью вызывает тревогу и снижает доверие у этой аудитории.

Рекомендация: Scarcity-сигналы в текущем виде (urgency border + «Осталось N мест» badge) — НЕ внедрять. Вместо этого — социальное доказательство: «Уже едет 47 детей», «60% возвращаются в следующую смену».

UX-рекомендация

Финансовые выгоды должны быть рядом с ценой. Налоговый вычет — конкретная экономия, снижает психологический барьер.

Реальный клиент

  • Налоговый вычет 13% — триггер #3 по важности
  • Конкретная экономия (≈5 000₽ с путёвки) — рациональный аргумент
  • «Умная мама нашла лучший вариант» — образ подходит
✅ Внедрять. Вычет 13% — один из трёх главных триггеров. Должен быть рядом с ценой: «39 900₽ — или 34 700₽ с вычетом». Конкретная сумма, не «возможен налоговый вычет».

Почему этого не было в первом отчёте

Причина 1 — Инструмент: browser_agent делает скриншоты, но не может автоматически вычислить CSS-контраст по коду. Для анализа контраста нужно либо инспектировать CSS вручную, либо использовать специализированные инструменты (axe-core, Lighthouse accessibility audit).

Причина 2 — Приоритизация: UI/UX Pro Max framework фокусируется на паттернах взаимодействия и информационной архитектуре. Типографика и цвет — техническая часть, которая требует отдельного color-audit шага.

Исправление: Для будущих аудитов запускать Lighthouse → Accessibility (автоматически выдаёт contrast ratio по всем элементам) + ручной просмотр CSS для нестандартных значений opacity.

🎯 Приоритетный план действий

✅ Внедрять в первую очередь (максимальный ROI × профиль)

  1. WA как главный CTA на мобиле — заменить «Записаться» (форма) на «Написать в WhatsApp». Данные: 606 клиентов пришли через WA. Это самый прямой путь к деньгам.
  2. Соцдоказательства в hero — рейтинг Яндекс.Карты + «N родителей уже выбрали». Триггер #1 для аудитории.
  3. Расписание дня/программа — убрать 239 повторяющихся WA-вопросов. Страница «Что делает ребёнок» или timeline на главной.
  4. Налоговый вычет рядом с ценой — «39 900₽ → 34 700₽ с вычетом 13%». Конкретная сумма экономии.
  5. text-slate-500 вместо text-slate-400 — 30 секунд исправления, убирает WCAG fail на всём сайте.
  6. text-[8px] удалить или поднять до 12px — критический баг читаемости, 1 строка в коде.

⚠️ Адаптировать перед внедрением

  1. AgeBar нудж — переформулировать: убрать срочность, оставить пользу. «Попадёт в группу с 12 ровесниками» вместо «Идеально подойдёт Смена 1».
  2. Форма заявки — сократить до 2 полей (имя + телефон), но переосмыслить: форма не для «холодных», она для уже готовых. Сделать её вторичной, WA — первичной.
  3. Сравнение смен — сделать, но спрятать за ссылку. Для мужа-технаря, не для мамы.
  4. Hero white/50 → white/80+ — добавить text-shadow или darker overlay под текст в hero.

❌ НЕ внедрять (противоречит аудитории)

  1. Scarcity-сигналы (urgency border, «Осталось N мест» badge) — клиентка покупает из образа, не из страха. Давление = потеря доверия.
  2. Таймеры обратного отсчёта — паттерн для e-commerce дешёвых товаров. Здесь — токсично для бренда.
  3. «Позвонить» как основной CTA — клиентка боится навязчивых звонков. WA — её канал, телефон — её мужа.
  4. Нижняя мобильная навигация (tabbar) — она листает как ленту, не переключается между разделами как в приложении.
  5. Любые механики давления времени/мест — «Успейте», «Только до X», countdown — всё это в красной зоне для данной аудитории.
