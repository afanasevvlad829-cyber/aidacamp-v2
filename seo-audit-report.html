Сайт хорошо оптимизирован технически, отличная Schema.org разметка, сильные Lighthouse-показатели. Основная проблема — критические 404 на страницах с внешними ссылками (/o-lagere, /otzyvy) и отсутствие og:image на лендингах. Оценка может стать A после трёх фиксов.

Executive Summary
Критично
/o-lagere и /otzyvy — 404
Обе страницы возвращают HTTP 404. На них активно ссылаются внутренние страницы (найдено в исходниках), и они выбывают из индекса. Sitemap их не содержит.
Критично
www.aidacamp.ru не редиректит (200 вместо 301)
https://www.aidacamp.ru/ возвращает 200 с тем же контентом что и apex-домен. Дублирование контента + размывание ссылочного веса. Нужен 301 → https://aidacamp.ru/
Критично
og:image отсутствует на лендингах
Все страницы в LandingLayout (/lager-na-iyun, /detskiy-lager, /kompyuternyy-lager и ~25 других) не имеют og:image. При шаринге в соцсетях — пустые превью. Только главная передаёт og:image.
Важно
H1 дублируется на главной
На главной два тега <h1> — "Летний лагерь в Подмосковье, 7–15" выводится дважды (в Hero и в LandingHero). Google берёт первый, но это сигнал некачественной разметки.
Важно
Best Practices Lighthouse 77/100
На всех проверенных страницах Best Practices = 77. Причина — устаревшие API или insecure requests из сторонних скриптов (Metrika, Mail.ru). Также TBT = 270ms на главной (mobile).
Важно
SEO = 92 на лендингах (не 100)
Страницы /lager-na-iyun и /detskiy-lager получают SEO 92 вместо 100 как главная. Lighthouse указывает на отсутствие мета-тегов или проблемы с tap targets на мобиле.
Хорошо
Schema.org — отлично проработана
Главная имеет полный @graph: Organization, SummerCamp, EducationEvent (ItemList), FAQPage, BreadcrumbList, Person (E-E-A-T), WebSite. Страница /otzyvy — Review + AggregateRating.
Хорошо
Производительность desktop 100/100
LCP 0.8s, FCP 0.4s, CLS 0 на desktop. Preload AVIF, локальные шрифты, нет CDN-зависимостей. Технический стек Astro + SSR работает отлично.

Sitemap.xml

  • Sitemap существует: /sitemap.xml (HTTP 200)
  • Корректный XML-формат, 48 URL
  • Указан в robots.txt
  • Отсутствуют: /o-lagere, /otzyvy, /partners (дубль /dlya-kompaniy)
  • Нет <lastmod> ни в одном URL — поисковики не знают когда обновлялись страницы
  • Нет <priority> и <changefreq> (опционально, но полезно для главной)

Robots.txt

  • robots.txt существует и корректен
  • User-agent: * Allow: /
  • Clean-param для UTM и рекламных меток — отлично
  • Ссылка на Sitemap
  • Не закрыты /admin/ страницы от индексации (рекомендуется Disallow: /admin/)

Редиректы HTTP→HTTPS и www→non-www

  • http://aidacamp.ru/ → 301 → https://aidacamp.ru/ ✓
  • https://www.aidacamp.ru/ → 200 OK (дублирует контент) — нужен 301 → https://aidacamp.ru/

Дублирование на www = два индексируемых варианта сайта. Ссылочный вес размывается. Это классическая ошибка nginx-конфига.

Best Practices 73–77 — почему?

Характерная причина для этого диапазона — deprecated API или mixed content от сторонних скриптов:

  • Yandex.Metrika и Top.Mail.Ru используют устаревшие API (document.write, sync XHR)
  • Clarity загружается отложенно (+20s), но всё равно влияет на итоговый счёт
  • Insecure requests от аналитических пикселей (http внутри https)
  • Для повышения до 90+ нужно переключить все сторонние скрипты на современные async-варианты

SEO 92 на лендингах — причины

Lighthouse SEO 92 vs 100 на главной означает одну или несколько из:

  • Отсутствие og:image — Lighthouse считает его критичным для SEO-сигналов
  • Tap targets слишком близко на мобиле (кнопки/ссылки)
  • Возможно — canonical без слеша (/lager-na-iyun) при выдаче с слешем (/lager-na-iyun/)
  • title и description — в норме на всех проверенных страницах

Плюсы контентной стратегии

  • Богатая внутренняя перелинковка — почти каждая страница ссылается на 4–8 других
  • RelatedPages компонент на всех лендингах — создаёт семантические кластеры
  • Хорошая длина описаний (130–160 символов)
  • H2-структура логичная, информативная, не сухой список
  • Тексты написаны "живым" языком, не сео-вода
  • Blog /stati/ — 15+ статей по информационным запросам (зависимость от телефона, подросток, лагерь без гаджетов)
  • Breadcrumbs в HTML на /otzyvy и других страницах

Проблемы контента

  • H1 дублируется на главной (Hero + LandingHero оба рендерят H1)
  • /o-lagere недоступна — ключевая страница "О нас" с богатым контентом и ссылками из отзывов
  • /otzyvy недоступна — страница с Review schema, ссылками из о-lagere и главной
  • Лендинги /lager-na-iyul и /lager-na-iyun не имеют FAQPage Schema (есть только на главной)
  • Некоторые Title на лендингах длиннее 65 символов (72–76 симв) — обрезаются в выдаче
  • Нет Breadcrumb Schema на лендингах (только на /otzyvy)

Schema.org разметка

Главная страница — @graph

  • Organization — name, url, logo, telephone, email, sameAs (VK, Telegram)
  • SummerCamp + LocalBusiness — адрес, телефон, priceRange, coordinates (в LandingLayout)
  • AggregateRating — ratingValue, reviewCount, bestRating
  • Review[] — все отзывы с author, datePublished, reviewBody
  • ItemList → EducationEvent[] — все смены с startDate, endDate, Offer (цена, availability)
  • FAQPage — 7 вопросов родителей
  • BreadcrumbList
  • Person (Дарья + команда) — E-E-A-T сигналы
  • WebSite с publisher
  • sameAs содержит только VK и Telegram — нет Instagram, Яндекс.Карты

Страница /otzyvy

  • LocalBusiness + AggregateRating (5.0 / 40 отзывов)
  • Review[] с полями author, datePublished, reviewBody, reviewRating
  • itemReviewed → EducationalOrganization
  • Страница недоступна (404) — вся эта разметка не индексируется

Лендинги (LandingLayout)

  • Базовый EducationalOrganization + LocalBusiness (без Reviews, без FAQ)
  • Нет BreadcrumbList Schema (есть HTML-breadcrumb, но не структурированные данные)
  • Нет FAQPage — хотя блок FAQ присутствует на каждой странице
  • GeoCoordinates заданы (55.265643, 36.724185)
Рекомендация: добавить FAQSchema (уже есть компонент FAQSchema.astro в layouts/LandingLayout) на все лендинги — это даст FAQ-сниппеты в SERP. Компонент уже подключён в LandingLayout, нужно только убедиться что FAQPage schema рендерится с данными из FAQ-компонента.
