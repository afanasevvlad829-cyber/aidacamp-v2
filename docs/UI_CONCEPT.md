# Портал АйДаКэмп — UI/UX концепция и контент-машина

> Дополняет `/docs/PORTAL_CONCEPT.md` (архитектура).
> Состояние: 2026-05-26, утверждено в диалоге.

## 1. Цель

Сделать так, чтобы:
- сотрудник на смене не думал «что мне делать сейчас»;
- контент для родителей собирался сам, а не пересылался по чатам;
- руководитель писал отчёт в виде редактирования, а не сочинения.

## 2. Шесть принципов

1. **Главный экран = «Сейчас»**, не календарь. Сотрудник открыл — видит карточку текущего/следующего события с временем, чек-листом, материалами и кнопкой «+фото».
2. **Событие — центральная сущность**, всё внутри неё. Чек-лист, материалы, фото, регламенты — слои внутри карточки события, не отдельные разделы.
3. **Регламенты — пункты чек-листов**, не отдельный PDF. «Взрослые едят последними», «фото меню», «считать порции» — галочками рядом со своей задачей.
4. **Архив = автотег от события**. Любое фото снимается из карточки события → автоматически попадает в архив с тегом (событие, автор, время). Никто не собирает руками.
5. **Отчёт по дню — авто-черновик**, не «напиши пост». ИИ собирает текст из событий, чек-листов и подписей фото; руководитель редактирует.
6. **Дефолтный вид зависит от роли**. Вожатый, преподаватель и руководитель открывают портал с разными задачами — стартовая страница это отражает.


## 3. Структура связей

Карточка события — центр. Три роли «входят» в неё сверху (через свой главный экран). Из неё «выходят» данные:

- **Архив дня** — все фото/видео/интервью с тегами события и автора;
- **Отчёт по дню** — собирается из событий, чек-листов, подписей к выбранным фото;
- **Публикация в Telegram родителям** — финальное действие.

## 4. Главный экран по ролям

### Вожатый — мобильный

- Большая карточка «Сейчас» с временем, чек-листом (2 из 5), контент-заданием и кнопкой «Снять и загрузить в архив»;
- Карточка «Дальше» с обратным отсчётом («через 7 мин»);
- Свёрнутая лента остальных событий дня, в ленте подсвечены события с контент-задачей (иконка камеры).

### Преподаватель — мобильный/планшет

- Карточка «Сейчас» с привязанной методичкой (по типу события) и чек-листом подготовки;
- Кнопка «+фото с занятия»;
- Расписание своих пар и групп.

### Руководитель — десктоп

- Сводка дня в 4 метрик-карточках: события закрыты, фото в архиве, контент-задачи, незакрытые пункты;
- Большая карточка «Подготовить отчёт за день N → Открыть редактор»;
- Шахматка сбоку миниатюрно, с подсветкой дыр.

## 5. Сущность «контент-задание»

Контент перестаёт быть побочным эффектом и становится **задачей события**. У каждого события может быть **одно** контент-задание, выбранное из пула шаблонов под этот тип события.

### Формат задания

- **Тип контента** — фото / видео 15 сек / интервью / групповое / таймлапс / мем-кадр;
- **Цель** — что должно быть в кадре, или вопрос для интервью;
- **Кто исполняет** — вожатый / преподаватель / руководитель;
- **Куда складывается** — автоматом в архив дня с тегом задания.

### Пул заданий по типам событий

**Завтрак / обед / ужин / полдник:**
- Фото меню крупно + один ребёнок с тарелкой на фоне
- Групповое фото за длинным столом
- Видео 15 сек: как накрывают
- Интервью 2–3 детей: что вкуснее сегодня
- «Чистая тарелка» — кто доел
- Мем-кадр: серьёзные лица за едой

**Занятия:**
- Фото момента «озарения» (ребёнок и экран)
- Интервью 2 детей: что мы делаем и зачем
- Фото готовой работы + автор рядом
- Видео 20 сек: процесс работы крупным планом
- Скриншот лучшей работы дня

**Бассейн:**
- Видео 15 сек: прыжок с бортика
- Групповое фото у борта
- «Чемпион стиля» — крупный план улыбающегося ребёнка

**Свободное время / прогулка:**
- Пейзаж + дети на территории
- Игры на улице, общий план
- Эмоциональный портрет одного ребёнка

**Вечернее мероприятие:**
- Видео-зарисовка: общий план + 2 крупных лица в смехе
- Команда-победитель крупно
- Интервью «что было самое интересное»

### Контент-план смены

Для каждого слота из пула выбирается **одно** задание один раз — до старта смены. Получается матрица «день × слот», авторская работа руководителя на этапе подготовки. В портале живёт как отдельный артефакт (редактор для руководителя).

## 6. Четыре типа дня + хакатон

| Тип дня | Что отличает | Контентный нерв | Когда |
|---|---|---|---|
| **День заезда** | минус-первый (приёмка номеров вожатым), сбор у автобуса, поездка 40 мин, медицина, расселение, первый ужин, знакомство, ранний отбой | первое впечатление: эмоции родителей и детей, селфи у автобуса, видео заселения, групповое «мы доехали» | день 1 |
| **Типовой учебный день** | 4 пары (две группы параллельно: 09:00–10:30, 10:30–12:00, 15:00–16:30, 16:30–18:00), бассейн через день, вечернее мероприятие | разномастный из пула, 6–8 контент-точек в день | дни 2–7 |
| **День хакатона** | сокращённое занятия (или нет), всё подчинено командной работе над проектами, вожатые в роли поддержки | timelapse команд, интервью «над чем работаем», промежуточные кадры идей | день 8 |
| **День защиты проектов + зефирки** | защиты проектов с хакатона + ритуал посвящения с маршмеллоу и сосисками на костре | два смысловых блока: парадные видеозаписи защит + церемония посвящения; идёт в финальный отчёт смены, не только в пост дня | день 9 |
| **День отъезда** | сбор вещей, прощальный завтрак, уборка, прощальный круг, загрузка автобуса, поездка, встреча с родителями | сентиментальный: интервью «что запомнилось», видео последнего объятия, встреча с родителями | день 10 |

## 7. Загрузка фото и видео

### Дефолт — HTML5 input

В карточке события кнопка «Снять и загрузить в архив» = `<input type="file" accept="image/*" capture="environment">`. На телефоне открывается системная камера, на десктопе — обычный file picker. Файл по `<input>.files[0]` отправляется multipart POST на `/api/portal/photo` с полями `event_id`, `content_task_id` (опц.), `file`. Сервер привязывает к telegram_id из HMAC-cookie, делает ресайз через Sharp до 1600px по длинной стороне, пишет запись в таблицу `archive_photo`.

### Что не работает

`navigator.mediaDevices.getUserMedia` в Telegram WebApp на Android не запускается (TMA issue #681, март 2025). Поэтому кастомный UI камеры внутри WebApp — закрыт. Системная камера через `<input>` — открыт и работает одинаково на iOS и Android.

### Видео

Тот же `<input>` с `accept="video/*"`. Ограничение 30 секунд (длиннее не нужно для контента родителям) — проверка длительности на клиенте перед загрузкой. Ограничение размера 30 МБ.

### Fallback: через бота

Кнопка «Отправить фото в бот» вызывает `Telegram.WebApp.close()` → пользователь попадает в чат с `@Aidacamp2026bot` с подсказкой «Пришлите фото к событию N». Бот ловит по chat_id и последнему активному событию для этого пользователя. Используется как запасной путь, не как default.

## 8. Отчёт по дню — авто-собираемый артефакт

Открыл «Подготовить отчёт за день N» → редактор содержит:

1. **Метрики дня** (4 карточки): закрытые события, фото в архиве, выполненные контент-задачи, незакрытые пункты (последняя с оранжевой подсветкой если > 0).
2. **Чек-лист «что должно быть в посте родителям»** (6 пунктов): заголовок и дата, краткое описание дня, 5–7 отобранных фото, цитата ребёнка или преподавателя, видеосообщение (опц.), расписание завтра.
3. **Галерея фото** из архива дня с подписями (событие/тип), руководитель выбирает 5–7 для поста — выбранные обведены и помечены чек-меткой.
4. **Текст ИИ-черновика** в textarea с подписью «собрано из событий, чек-листов и подписей к выбранным фото — отредактируй под себя» и кнопкой «Перегенерировать ИИ-черновик».
5. **Слот видеосообщения руководителя** (15–30 секунд, запись прямо из браузера).
6. **Кнопки «Предпросмотр поста»** и **«Опубликовать в Telegram родителям»** — публикация акцентирована (синяя).

### Генерация черновика

ИИ-черновик генерируется через `claude-haiku-4-5` (или Sonnet 4.6 для более тонкого русского) на бэке. System prompt включает:
- список событий дня с временем и статусом;
- закрытые чек-листы (что прошло хорошо) и незакрытые;
- подписи к 5–7 выбранным фото (event + автор + время);
- голос/стиль АйДаКемп: тёплый, конкретный, без приторности и клише, без морализаторства.

## 9. Масштабируемость

- **Шаблон дня** клонируется одной кнопкой на новую смену;
- **Шаблон события** несёт предзаданные чек-лист и пул контент-заданий;
- **Регламент** редактируется один раз — пункты обновляются во всех связанных чек-листах;
- **Новая роль** добавляется в `portal_staff` без перетряхивания сетки.
