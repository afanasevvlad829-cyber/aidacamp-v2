## Объём

**В этом спеке:**
- Определение ближайшего к моменту черновика события сетки смены (`shift_event`)
- Лёгкая конвенция для «фото меню» без нового бот-флоу — переиспользует уже существующий сборщик черновиков (Фаза 1)

**Не в этом спеке (сознательно вырезано, не гипотеза «потом добавим», а решение):**
- Внешние новости/мемы, которые упоминались в самой первой формулировке задачи — источника таких данных нет, интеграция с внешним поиском/трендами — самостоятельная задача с вопросами бренд-безопасности (см. `_notes/АйДаКемп/Маркетинг/Позиционирование бренда.md` — эмодзи с чужих мемов легко выбивается из тона Дарьи), не проектируем сейчас
- Отдельная структурированная таблица «меню на смену» — камп физически не ведёт цифровое меню (по прецеденту `shift-content-bot`: «Фото меню» — это просто фото-задание, не данные); вместо цифровой структуры используем фото как есть

## Ближайшее событие сетки (`shift_event`)

```sql
SELECT * FROM shift_event
 WHERE shift_id = $1 AND date = $2
   AND start_time <= $3
   AND (end_time IS NULL OR end_time >= $3)
 ORDER BY start_time DESC
 LIMIT 1
```

Если точного совпадения нет (черновик собран чуть позже, событие уже завершилось) — берём ближайшее по времени завершившееся событие в пределах разумного окна (например, последние 60 минут; точное окно — на усмотрение реализации, не критично для дизайна). `$2`/`$3` — дата и время создания `draft_post` (момент `/готово`, а не момент первого сообщения).

Даёт: `title`, `activity_type` — это и есть «что сейчас происходит» (обед, урок, свободное время…).

## Фото меню — конвенция без нового кода

Отдельного бот-режима не заводим. Если вожатый прислал в рамках черновика фото с текстом, где встречается слово «меню» (например «Меню на обед»), это фото становится «фото меню на сегодня». Спек 4 при генерации, если ближайшее событие — приём пищи (`activity_type` соответствующий), ищет:

```sql
SELECT ap.file_url FROM archive_photo ap
  JOIN draft_post dp ON dp.id = ap.entity_id AND ap.entity_type = 'draft_post'
 WHERE dp.shift_id = $1 AND dp.text ILIKE '%меню%'
   AND ap.uploaded_at::date = $2
 ORDER BY ap.uploaded_at DESC
 LIMIT 1
```

Если такого фото за сегодня не найдено — просто нет визуального меню в контексте, генерация (спек 4) работает без него (не блокируется, не выдумывает).

## Обработка ошибок

- Нет `shift_event` вообще на эту дату/время → `event_title = null`, генерация (спек 4) работает без привязки к конкретному событию, только по фото и распознанным именам.
- Меню-фото не нашлось → `menu_photo_url = null`, как описано выше.

## Тестирование

- Юнит-тест резолвинга ближайшего события: точное попадание / попадание в окно после конца / полное отсутствие.
- Юнит-тест поиска меню-фото: есть подходящее сегодня / есть, но не сегодня (не находим) / нет вообще.

## Открытые вопросы для плана реализации (не блокируют дизайн)

1. Точный размер «окна» для события, уже завершившегося к моменту `/готово` — подобрать по факту (сколько обычно вожатые задерживаются с публикацией после события).
2. Список `activity_type`, которые считать «приёмом пищи» (для поиска меню-фото) — сверить с реальными значениями `activity_type` в текущей сетке смены при реализации.
