# Стандартный шаблон жизненного цикла смены

**Дата:** 2026-06-20
**Статус:** утверждён

## Проблема

Карточки смен в `src/components/Shifts.astro`:
- Смена 1 (завершена) и Смена 2 (идёт) — **захардкожены** (даты, цены, статус, прогресс вручную).
- Смены 3, 4 — через шаблон `ShiftCard`.

При смене статуса (старт/завершение) нужно править вёрстку руками. Нет стандарта.

## Цель

Статус смены определяется **датами автоматически**, карточка рендерится единым шаблоном по фазе. Добавил смену в `shifts.ts` с датами — она сама проходит: предстоит → идёт → прошла.

## Фазы (выводятся из дат, единый источник)

`getShiftPhase(shiftId, today)` в `dynamicPrices.ts`:
- `upcoming` — сегодня < `startDate`
- `live` — `startDate` ≤ сегодня ≤ `endDate`
- `done` — сегодня > `endDate`

## Карточка по фазам

| Фаза | Содержимое | Призыв |
|---|---|---|
| `upcoming` | текущая цена (растёт) + места | «Записаться» + «завтра дороже» |
| `live` | бейдж «смена идёт» + прогресс N/всего + первая→последняя цена | «можно было взять за X, к старту Y» |
| `done` | бейдж «завершена» + первая→последняя цена + «Смотреть как прошла» (если есть recap) | доказательство: бери заранее |

Блок «как росла цена» (**первая → последняя цена**) — главный призыв, показывается на `live` и `done`. Не «купи со скидкой», а доказательство выгоды раннего бронирования.

## Источник первой/последней цены

- **Смены по новому правилу** (3, 4 и дальше): авто — первая = база (`SHIFT_META.basePrice`), последняя = `getCurrentPrice(id, startDate)` (цена на старте). Смена 3 → 89 400 → 108 870.
- **Legacy-смены** (1, 2, шли по старому росту): историческая цена не совпадает с правилом — задаётся явно в данных:
  - Смена 1: `priceFrom` 74 900 → `priceTo` 93 900
  - Смена 2: `priceFrom` 95 000 → `priceTo` 108 000

Поля `priceFrom`/`priceTo` в `shifts.ts` опциональны: заданы → факт истории; нет → выводится из правила.

## Recap-ссылка

Поле `recapUrl?` в данных смены. `done` + `recapUrl` → кнопка «Смотреть как прошла». `done` без `recapUrl` → просто «завершена» (без битой ссылки). Смена 1: `/kak-proshla-smena-1/`.

## Изменения в коде

1. `dynamicPrices.ts`: `getShiftPhase(id, today)`.
2. `shifts.ts`: в `Shift` добавить `recapUrl?`, `priceFrom?`, `priceTo?`. Смены 1/2 переезжают из хардкода Shifts.astro в данные. Экспорт `displayShifts = [shift-1, shift-2, ...mainShifts]` (все для показа).
3. `ShiftRetroCard.astro` (новый): рендер `live`/`done` (бейдж + прогресс/история цены + recap). Извлекается из текущего хардкода Смены 1/2.
4. `ShiftCard.astro`: остаётся карточкой `upcoming` (бронируемой).
5. `Shifts.astro`: удалить хардкод Смены 1/2; `displayShifts.map` → по фазе выбирает `ShiftCard` (upcoming) или `ShiftRetroCard` (live/done).

## Вне scope

- Авто-генерация recap-страниц (делаются вручную, ссылка по `recapUrl`).
- Изменение правила роста цены (уже внедрено отдельно).
