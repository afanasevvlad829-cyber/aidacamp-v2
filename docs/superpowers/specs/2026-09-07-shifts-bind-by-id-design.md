# Развязка производных экспортов shifts.ts от позиции в массиве

**Дата:** 2026-09-07 · **Ветка:** `refactor/shifts-bind-by-id` · **База:** `origin/dev` (4a33afc8)
**Решение владельца:** вариант «В» — атомы по id как база миграции + `shiftLine()` для новых страниц.

## Проблема

Девять экспортов выводятся по позиции в `mainShifts`, а не по id смены:

```ts
export const PRICE_S3 = mainShifts[0].price;   // «Смена 3» ≡ «нулевой элемент массива»
export const DATES_S3 = shiftDatesFull(mainShifts[0]);
export const SEASON_RANGE = `${...mainShifts[0]...} — ${...mainShifts[1]...}`;
```

Имя говорит «Смена 3», смысл — «первая смена в массиве». Пока летний сезон шёл, это
совпадало. При выносе завершённых летних смен из `mainShifts` экспорты молча переезжают
на осенние, и страницы печатают «Смена 3: 25–31 октября, 13 дней — 49 900 ₽» —
имя, длительность и цена от трёх разных смен в одной строке.

Вторая половина проблемы: **длительность нигде не производная**. `duration` есть в
объекте смены, но на страницах она зашита текстом («13 дней»), рядом с динамическими
`${DATES_SHORT_S3}` и `${PRICE_S3}`. Меняется привязка — цена и дата едут, длительность
остаётся.

## Замеры (origin/dev, 07.09.2026)

| экспорт | файлов | вхождений |
|---|---|---|
| `VYCHET_MAX` | 107 | 323 |
| `PRICE_S4` | 97 | 256 |
| `PRICE_S3` | 88 | 218 |
| `DATES_SHORT_S4` | 75 | 182 |

| `VYCHET_S4` / `VYCHET_S3` | 32 / 29 | 95 / 64 |
| `DATES_S4` / `DATES_S3` | 3 / 4 | 7 / 9 |
| `SEASON_RANGE` | **0** | 1 (только объявление) |

- Строк, где зашитая длительность стоит вплотную к маркерам S3/S4: **237**.
- Строк, где зашитая длительность стоит рядом с `VYCHET_MAX`: **76**.
- Формулировок не менее 12 видов.

### Находка 1: `SEASON_RANGE` — мёртвый экспорт
Ноль потребителей. Не мигрируется — удаляется.

### Находка 2: живой баг на проде, предшествующий задаче
`PRICE_MIN` = 49 900 ₽ — это **7-дневная** осенняя смена (проверено исполнением
`shifts.ts`). При этом **94 строки в ~70 файлах** пишут «от 49 900 ₽ за 10 дней»
и «от `${PRICE_MIN}` (10 дней) до `${PRICE_MAX}` (13 дней)».

Баг приехал 27.08.2026, когда осенние смены перенесли в `mainShifts`: `PRICE_MIN`
упал с 74 900 (10 дней) на 49 900 (7 дней), зашитая «10 дней» осталась. Это ровно тот
класс ошибки, который описан в задаче, только уже отгруженный в прод. Чинится тем же
приёмом (`DAYS_MIN`) и попадает под тот же страж.

### Находка 3: `VYCHET_MAX` — самая массовая позиция, опаснее `PRICE_S3`
`max(mainShifts[0], mainShifts[1])` в 107 файлах, и в 76 строках рядом зашито
«за 13-дневную смену». После архивации лета максимум уедет на зимнюю (10 дней).

## Решение

### 1. `byId()` — единственный способ адресовать смену

```ts
function byId(id: string): Shift {
  const s = allShiftsIncludingArchived.find(x => x.id === id);
  if (!s) throw new Error(`shifts.ts: смены «${id}» нет в allShiftsIncludingArchived`);
  return s;
}
```

Ищет по `allShiftsIncludingArchived`, поэтому экспорт продолжает работать после выноса
смены из `mainShifts` в архив. Бросает при опечатке в id — молчаливого переезда больше
не будет ни при каких правках массива.

### 2. Атомы: все `*_S3`/`*_S4` перепривязаны + новые `DAYS_*`

```ts
const _s3 = byId('shift-3'), _s4 = byId('shift-4');
export const PRICE_S3  = _s3.price;
export const DAYS_S3   = _s3.duration;          // «13 дней» — НОВОЕ
export const DATES_S3  = shiftDatesFull(_s3);
export const DATES_SHORT_S3 = shiftDatesShort(_s3);
export const VYCHET_S3 = _fmtV(shiftDeduction(_s3));
```

`DAYS_*` заводятся и для S1/S2/S21/S22 (есть проза «Смена 1 длилась 10 дней»).

### 3. Диапазонные экспорты — длительность вместе с ценой

```ts
const _cheapest = _sorted[0], _priciest = _sorted.at(-1);
export const PRICE_MIN = _cheapest.price;
export const DAYS_MIN  = _cheapest.duration;    // НОВОЕ — чинит находку 2

const _maxVychetShift = mainShifts.reduce((a, b) => shiftDeduction(b) > shiftDeduction(a) ? b : a);
export const VYCHET_MAX      = _fmtV(shiftDeduction(_maxVychetShift));
export const VYCHET_MAX_DAYS = _maxVychetShift.duration;  // НОВОЕ — чинит находку 3
```

`VYCHET_MAX` переходит с `max(mainShifts[0], mainShifts[1])` на `reduce` по всему
`mainShifts`. **Сегодняшнее значение не меняется** (5 200 ₽, shift-3 — максимум и так),
меняется только поведение после архивации.

### 4. `shiftLine()` — канон для новых страниц

```ts
/** «Смена 3 — 3–15 августа, 13 дней, 89 400 ₽» */
export function shiftLine(s: Shift, opts?: { vychet?: boolean }): string
```

Существующие 170+ страниц **сохраняют свои формулировки** — переписывать видимый текст
на 50 страницах с FAQ-разметкой ради единообразия это SEO-риск без выгоды. Они
собираются из атомов. `shiftLine()` — для нового.

### 5. Страж `scripts/check-duration-drift.sh`

Правило: строка боевой страницы, содержащая интерполяцию смены
(`${PRICE_S*}`, `${DATES_*_S*}`, `${VYCHET_*}`, `${PRICE_MIN}`, `${PRICE_MAX}`),
не должна содержать литерал `N дней|дня|день` — длительность обязана приходить из
`${DAYS_*}`. По образцу `check-date-drift.sh`: python-эвристика, ALLOW-список для
законных исключений, подключается в `npm run guard` как `check:durations`.

### 6. Усиление `shifts.test.ts`

Проверки привязки **по id**, а не «содержит августа»:

```ts
it('PRICE_S3 — цена смены shift-3, а не первой в массиве', () => {
  expect(PRICE_S3).toBe(allShiftsIncludingArchived.find(s => s.id === 'shift-3').price);
});
it('экспорты S3/S4 переживают вынос смен из mainShifts', () => { /* фильтруем и сверяем */ });
```

Существующие 30 тестов не ослабляются.

### 7. Архивация лета (после миграции)

`_shift3`/`_shift4` выносятся из `mainShifts` в `const`, добавляются в
`displayShifts` и `allShiftsIncludingArchived` — как `_shift1`/`_shift2`.
Заплатка и комментарий «ЗАПЛАТКА, А НЕ РЕШЕНИЕ» из PR #1920 снимаются, если тот
успеет смержиться; если нет — снимать нечего.

## Порядок работ

| Партия | Содержание | Гейт |
|---|---|---|
| 0 | `byId`, `DAYS_*`, `VYCHET_MAX`/`PRICE_MIN` на reduce, `shiftLine()`, удаление `SEASON_RANGE`, усиление теста | тесты + стражи зелены, ни одна страница не изменилась |
| 1 | 10–15 страниц без FAQ-разметки, вручную | **ревью владельца до продолжения** |
| 2 | Остальные не-FAQ страницы | стражи |
| 3 | Страницы с FAQ-разметкой, отдельно | `check:faq` + `check:breadcrumbs` |
| 4 | Страж `check:durations` в `npm run guard` | guard зелен |
| 5 | Архивация лета, снятие заплатки | тесты + стражи + сборка |

Механику партий 2–3 после ревью партии 1 можно отдать Codex
(`~/agent-context/scripts/codex-task.sh`) — формат к тому моменту зафиксирован и
проверен вручную на десятке страниц.

- `check:dates`, `check:prices`, `check:banned`, `check:static`, `check:faq` — зелено
