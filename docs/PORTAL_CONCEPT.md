# Портал АйДаКэмп для сотрудников — концепция и архитектура

> Внутренний документ. Состояние на 2026-05-25. Среда: dev (`dev.aidacamp.ru/portal`).
> Онлайн-версия: Reports Hub → `2026-05-25-portal-concept`.

**Что это.** Единый внутренний портал лагеря: один вход, единый стиль, разделы по роли.
Сводит вместе расписание смены, роли и доступы, процессы и чек-листы, методические и
учебные материалы, танковый полигон (Robocode) — вместо разрозненных ссылок, чатов и docx.

---

## 1. Обзор и цель

До портала всё было разбросано: материалы на `ai.aidacamp.ru`, инструкции в docx,
расписание в отдельном конструкторе, доступ по общим паролям. Портал решает:

- **Единый вход** по ролям вместо общих паролей и пересланных ссылок.
- **Единый источник правды по смене** — одна сетка, из которой растут все представления.
- **Понятность «кто что делает»** — каждый видит свой день и свои чек-листы.

## 2. Архитектура

| Слой | Что |
|---|---|
| Адрес | `aidacamp.ru/portal` (прод — по выкату); сейчас `dev.aidacamp.ru/portal` |
| Приложение | Astro 6 (SSR, `@astrojs/node`), раздел `src/pages/portal/**` |
| Сервер | node SSR `127.0.0.1:4181`; nginx проксирует `/portal/` и `/api/portal/` |
| Гейт доступа | `src/middleware.ts` — подписанная HMAC-cookie с ролью; без сессии → редирект на вход |
| Данные | PostgreSQL (БД `aidacamp`, роль `aidacamp_app`): реестр сотрудников + сетка смены + отметки |
| Telegram | бот `@Aidacamp2026bot` — вход сотрудников (Login Widget + Mini App initData) |

Принцип: **одна модель данных — много представлений**. Гейт, cookie и роли общие для всех
разделов; добавление раздела не меняет авторизацию.

## 3. Роли и доступ

| Роль | Вход | Что видит |
|---|---|---|
| admin | Telegram + аварийный код | всё, управление сотрудниками и сеткой |
| руководитель смены | Telegram | сетка, сотрудники, документы, отчёты |
| вожатый | Telegram | свой день, чек-листы, инструкции, методички |
| преподаватель | Telegram | учебные материалы, свой день, методички активностей |
| ученик | код | полигон, квесты, каталог, онбординг |

**Жизненный цикл доступа:** сотрудник жмёт «Войти через Telegram» → заявка создаётся
автоматически (роль пустая) → «ожидайте подтверждения» → admin в «Управление сотрудниками»
назначает роль → повторный вход → доступ. **Отзыв:** admin деактивирует → доступ
закрывается ≤60 с (без ожидания истечения cookie). Персональная идентичность вместо общего пароля.

## 4. Расписание смены (ядро)

Одна **сетка смены**: смена → дни → события (активности). У события опционально —
**роли-ответственные** и **чек-листы**. Представления — срезы одних данных:

- **Мой день** — события моей роли на дату + мои чек-листы (главный экран сотрудника).
- **Все события дня** — день по времени.
- **По активностям** — группировка по типу через смену.
- **Шахматка** — матрица дни × роли (Учитель / Вожатый / Руководитель).

Сейчас 2 смены: **30 мая – 8 июня** и **10 – 23 июня**. Даты по-русски. Редактирование —
«Управление сеткой» (admin/руководитель). Несколько смен — переключатель. Архив, не удаление.

## 5. Чек-листы

- Чек-лист = шаблон пунктов, привязанный к событию для определённых ролей.
- Галочки **личные**: каждый отмечает за себя (5 вожатых = 5 независимых отметок).
- Хранятся в БД по `(событие, пункт, telegram_id)`; снять = убрать отметку.
- Единый эндпоинт `/api/portal/shift/check` — общий для портала и будущего Telegram-вебапа.

## 6. Процессы

Процессы — это **события сетки с чек-листами** на нужные роли и дни:

| Процесс | Кто | Чек-лист |
|---|---|---|
| Заезд / встреча | руководитель | список детей, документы |
| Расселение, завоз вещей | вожатый | чемоданы, комнаты |
| Приёмка комнат | вожатый/руководитель | проверка (фото/видео) |
| Вечерний отчёт родителям | вожатый/руководитель | фото, текст, отправка |
| Отбой / подъём | распорядок дня | — |
| Выезд | руководитель | сбор, отчёт |

## 7. Документы и методические материалы

- **Методические материалы (А. Ташкин)** — 5 ИИ-активностей: «Охотник на монстров»,
  «AI Secret Agent», «AI Art Battle», «Побег из лаборатории» (финальный хакатон),
  «ИИ видит предметы». У каждой: превью + архив картинок. Планы/чек-листы — **ожидаются
  тексты от методиста**. Плюс **презентация игры**.
- **Сотрудникам смены** — инструкции вожатого/руководителя, самопроверка (`/staff`),
  конструктор смены и расселение (`/staff/plan`).

## 8. Учебные материалы · портал учителей и учеников

- **Танковый полигон (Robocode)** — арена, бой, тренировка, игра.
- **Учителю** — онбординг преподавателя, хендбук, дашборд.
- **Ученику** — онбординг, квесты, каталог.
- **Поиск по материалам** на хабе (по доступным роли разделам).

Контент образовательной части живёт на `ai.aidacamp.ru/docs`; портал даёт единый вход и
навигацию (решение: не переносить, а собрать ссылки под общий вход).

## 9. Данные (PostgreSQL)

| Таблица | Назначение |
|---|---|
| `portal_staff` | реестр сотрудников: telegram_id → роль, активность, заявки |
| `shift` / `shift_day` / `shift_event` | смена, дни (тема), события (время, роли, тип) |
| `checklist` / `event_checklist` | шаблоны чек-листов и их привязка к событиям/ролям |
| `checklist_done` | личные отметки выполнения (по человеку) |

## 10. Эксплуатация

- Ветки: работа в `dev` → PR/мёрдж → деплой dev → прод по явному «выкатываем».
- Сборка с увеличенной памятью; деплой без `--delete` по корню (после инцидента с `.env`;
  есть бэкап env в `/root/env-backups/`).
- Секреты — в окружении сервиса, не в репозитории.
