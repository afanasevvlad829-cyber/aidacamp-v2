# ADR-001. Медиа сайта — в /var/www/aidacamp-media/, репо без бинарей

Дата: 2026-07-17 · Статус: принято
Источник: PR #1027 «chore(media): перенести тяжёлые медиа из репо в /var/www/aidacamp-media (−80 МБ)» (MERGED); CLAUDE.md → «МЕДИА И ФАЙЛЫ — ЕДИНОЕ ХРАНИЛИЩЕ»; `scripts/deploy.sh` (комментарии о симлинках и nginx-alias); сессия ревью 17.07.2026.

## Контекст
Тяжёлые фото/видео жили в git-репо (раздували его на ~80 МБ) и параллельно копировались
между dev и prod, порождая рассинхрон и мёртвые копии, которые nginx не читает.

## Решение
Все фото, видео и документы живут в одном месте на сервере — `/var/www/aidacamp-media/`.
nginx на prod и dev отдаёт `/images/` и `/videos/` напрямую оттуда через alias
(snippet `/etc/nginx/snippets/aidacamp-site-media.conf`). В рабочих копиях сайта
`images/`, `videos/` — симлинки на хранилище. Репо остаётся без бинарей; новые
картинки из `public/images/` доезжают в хранилище на деплое (`rsync --ignore-existing`,
серверная копия авторитетна).

## Следствия
- Залил файл один раз → виден и на dev, и на prod; синхронизация не нужна.
- НЕ копировать медиа в `/var/www/aidacamp/current/client/` или `/var/www/aidacamp-dev/` —
  эти копии nginx не читает (CLAUDE.md).
- Искать существующие фото/видео — сначала в `/var/www/aidacamp-media/`
  (и `aidacamp-gallery/` для галереи смен).
