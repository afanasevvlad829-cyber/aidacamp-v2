# ADR-007. Гео/возрастные SEO-страницы не шаблонизировать массово

Дата: 2026-07-17 · Статус: принято
Источник: CLAUDE.md → секция «Новые гео/возрастные SEO-лендинги — через [slug], не копипастой»; `src/data/seasons.ts` (комментарий «Тексты сезонов сознательно НЕ клонируются — привет, Яндекс»); код: `src/pages/` (180+ .astro-страниц), `src/data/landings/` (17 гео-конфигов) + `src/pages/[slug].astro`.

## Контекст
В `src/pages/` — 180+ отдельных `.astro`-файлов под гео/возрастные ключи
(`lager-klin.astro`, `lager-11-let.astro`…). Выглядит как забытый рефакторинг:
напрашивается массовый перенос в единый `[slug].astro`-шаблон.

## Решение
Это сознательная SEO-политика, не техдолг: разная формулировка на каждой странице
защищает от того, что поисковик посчитает комбинаторные лендинги шаблонным
дублирующимся контентом. Массово переносить существующие страницы в `[slug].astro`
НЕ нужно — риск просадки позиций у проиндексированных страниц больше выгоды.

Правило только для НОВЫХ страниц:
- реально шаблонная (тот же гео/возрастной паттерн без уникального угла) —
  через `src/data/landings/` + `[slug].astro`;
- есть собственный смысловой угол — обычный `.astro`-файл.

## Следствия
- Рефакторинг-аудитам не предлагать «унифицировать 180 лендингов».
- Новые шаблонные гео-страницы — только через `src/data/landings/`.
