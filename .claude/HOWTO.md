# Как мы работаем — для владельца (Влад)

Это **одна страница** про то, кто что делает, в каких ветках и в каком порядке. Читай раз в месяц, чтоб не было путаницы.

---

## Три роли

| Роль | Кто | Что делает | Куда пишет код |
|---|---|---|---|
| **Владелец** | Влад | Ставит задачи, утверждает выкатку в прод | — (ты не пишешь код) |
| **Оркестратор** | Claude в главной сессии (одна, основная) | Пишет код + принимает PR от агентов + ведёт `dev` + деплоит | напрямую в `dev` |
| **Агент** | Claude в отдельной параллельной сессии (Влад открывает в новом окне) | Делает одну конкретную задачу в своей ветке | в `agent/<название>` → PR в `dev` |

**Главное понять:** «агент» — это **другое окно Claude Code**, которое Влад открыл параллельно. Оркестратор и агенты **не связаны между собой** — они общаются только через git (ветки, PR) и через файлы `.claude/*.md`.

**Правило одного оркестратора:** в любой момент времени оркестратор только один. Все остальные Claude — агенты, работают на ветках `agent/*`.

---

## Четыре ветки

```
main         ← прод (aidacamp.ru)         правит: оркестратор после утверждения Владом
  ↑
dev          ← стейджинг (dev.aidacamp.ru) правит: оркестратор напрямую + через мерж PR
  ↑
agent/*      ← рабочие ветки              правят: агенты (каждый свою)

tooling      ← отдельная orphan-ветка     инструменты для CI, скрипты проверки.
                                          НЕ смешивается с кодом сайта.
```

## Как идёт задача (три типа)

### Тип 1: мелочь / хотфикс / срочно
Оркестратор делает сам на `dev`, деплоит, пишет в `LOG.md`. Пример: поправить отступ, починить опечатку, обновить файл памяти.

### Тип 2: нормальная задача — Влад сам даёт её агенту
1. Влад перед запуском агента спрашивает оркестратора: **«агент будет работать с <файлы>, с кем-то конфликтует?»** — оркестратор смотрит `AGENTS.md` и отвечает да/нет
2. Если чисто — Влад открывает новое окно Claude Code, сам пишет агенту бриф (какую ветку завести, что делать, критерий готовности). Заодно говорит агенту прочитать `.claude/WORKER.md`
3. Оркестратор записывает агента в `AGENTS.md` (ветка + зона файлов)
4. Агент работает → пушит → открывает PR в `dev`
5. Оркестратор проверяет PR (зелёный CI, нет конфликтов), мержит в `dev`, деплоит на dev.aidacamp.ru, пишет в `LOG.md`
6. Влад смотрит на dev.aidacamp.ru — «ок» или «переделать»
7. Если «выкатывай» — оркестратор мёржит `dev → main`, деплоит на прод, пишет в `LOG.md`

### Тип 3: несколько агентов параллельно
Влад открывает несколько окон одновременно. Главный риск — **пересечение зон файлов** (двое правят одно). Чтобы этого избежать:
- Перед каждым новым агентом — спросить оркестратора «не пересекается ли с активными?»
- Оркестратор мержит PR **по очереди** (не два сразу)
- Если пересечение неизбежно — оркестратор говорит Владу, какую задачу запустить первой, вторая пойдёт после мержа первой

## Что Влад говорит оркестратору

**Обычный язык — без технических формулировок:**
- «Поправь X сам» → делаю мелочь на dev
- «Запускаю агента на <файлы/задача>, кто-то уже там копает?» → смотрю `AGENTS.md` и отвечаю: **свободно** / **занято <агентом>** / **частично пересекается с <агентом>, подожди до его мержа**
- «Запустил агента `agent/foo` на <зоне>» → записываю в `AGENTS.md`, слежу за его PR
- «Посмотри PR N» → проверяю и докладываю
- «Что у нас в работе?» → сводка из `AGENTS.md` + открытые PR
- **«Выкатывай на прод»** → мержу `dev → main` и деплою. **Без этой фразы — ничего не уходит в прод.**

**Главная задача оркестратора** — чтоб агенты **не толкались локтями в коде**. Поэтому перед каждым новым агентом есть смысл спросить «кто где работает».

Если Влад сам пишет бриф — он просто добавляет агенту в первое сообщение:

> Ты — агент-работник. Прочитай `.claude/WORKER.md` — там правила (ветка, PR, зона ответственности, что НЕ трогать).

## Нерушимые правила

1. **Никто, кроме оркестратора, не пушит в `dev` и `main`.** Агенты — только в свои `agent/*`.
2. **В `main` нельзя без явного «выкатывай на прод» от Влада.**
3. **Мержим по одному PR за раз.** Пока один не закрыт — следующий не трогаем.
4. **Инструменты (`tools/**`) живут в ветке `tooling`, в ветку сайта не попадают.**
5. **Файлы `.claude/*.md` обновляет оркестратор** после каждого действия (не забываем про `TASKS.md` и `LOG.md`).

---

## Если что-то пошло не так

- **Прод сломался:** Влад говорит «откат». Оркестратор делает `git revert` последнего мержа в `main`, деплоит, пишет в `LOG.md`.
- **Путаница с ветками:** Оркестратор делает `git fetch` + `git status` во всех активных ветках, показывает Владу сводку.
- **Агент застрял:** Оркестратор смотрит его ветку, либо помогает, либо закрывает задачу с комментарием в `TASKS.md`, создаёт новую.
