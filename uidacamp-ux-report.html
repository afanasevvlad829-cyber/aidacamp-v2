Проблемы и конкретные доработки
🧱
Конкурирующие sticky-слои
Mobile UX · Z-index conflict
Критично
На мобилке одновременно могут быть видны: StickyCta (z-70, звонок/WA/TG), AgeBar (z-60, выбор возраста) и cookie баннер (z-50). Это съедает 120–140px экрана снизу, перекрывая CTA-кнопки смен. По UI/UX Pro Max rule #47: «only one persistent sticky element at a time».
Доработка AgeBar и StickyCta не должны показываться одновременно. Когда AgeBar видна — StickyCta скрыта (inert). Когда пользователь выбрал возраст и AgeBar исчезла — StickyCta появляется. Cookie баннер — только если оба других нет.
👁
Первый экран мобилки перегружен
Cognitive Load · Mobile First
Высокий
На 375px в first viewport одновременно конкурируют 7–8 визуальных элементов равного веса: H1 + рейтинг + цена + два CTA + trust chips + cookie + sticky. UI/UX Pro Max rule #12: «max 3 competing visual elements above fold». Мама не понимает куда смотреть первой.
Доработка Trust chips «Лицензия / Медсестра / Страховка» убрать из hero на мобилке (показывать только 320px+, desktop). Рейтинг уменьшить визуально (13px вместо 14px, без рамки). Оставить в first viewport: H1 + один primary CTA + цена. Это увеличит фокус.
✍️
Размеры текста — нет ритма
Typography · Type Scale
Средний
В компонентах используется более 20 разных font-size значений: text-[11px], text-[12px], text-[12.5px], text-[13px], text-[14px], text-[15px], text-[16px], text-[18px], text-[20px], text-[22px], text-[24px], text-[26px], text-[28px], text-[30px], text-[32px]... По UI/UX Pro Max: «type scale должен иметь ≤8 ступеней с ratio 1.2–1.25». Случайные промежуточные значения (12.5px, 15px) нарушают ритм.
Предложение — Type Scale 8 ступеней xs: 12px · sm: 14px · base: 16px · md: 18px · lg: 22px · xl: 28px · 2xl: 36px · 3xl: 48px. Убрать 11px, 12.5px, 13px (заменить на 12 или 14px), 15px (→ 14 или 16px), 20px (→ 22px). Освежит восприятие без смены стиля.
💰
Блок смен — визуальная иерархия
Cards · Conversion · Scarcity
Средний
Карточки смен все одинакового визуального веса. «Горящие» смены (мало мест, высокий pct) ничем не выделены кроме цвета прогресс-бара. По UUPM rule #83 (Scarcity Signaling): карточка с ≥85% занятостью должна иметь усиленную visual treatment — рамку, бейдж, фоновый акцент.
Доработка Смены с pct ≥85%: добавить border-2 border-orange-400 и бейдж «Последние места» в левый верхний угол карточки. Смены с pct ≥95%: bg-red-50 + badge «Осталось N мест». Не требует новых компонентов — только условные Tailwind-классы в ShiftCard.
🎯
CTA-кнопки — вариативность стилей
Consistency · Button System
Средний
Primary CTA встречается в 6 вариантах: bg-primary, bg-[#ec7c00], bg-orange-500, bg-[#ec7c00] + rounded-full, bg-primary + rounded-xl, bg-[#c45f00]. UUPM rule #21: «one primary button style, one secondary». Непоследовательность снижает доверие (посетитель подсознательно замечает несоответствие).
Доработка Ввести единый класс .btn-primary: bg-[#ec7c00] text-[#1e2430] font-semibold rounded-xl px-6 py-3 hover:bg-[#d97000] transition-colors. Применить везде где сейчас несогласованные варианты. Это рефакторинг, не редизайн.
🔲
Spacing — непоследовательный
Spatial System · 4px Grid
Средний
Отступы используют значения вне 4px-сетки: py-2.5 (10px), py-3.5 (14px), gap-2.5 (10px), px-4.5 (18px), mb-1.5 (6px). UUPM rule #5: «stick to 4px base grid». 10px и 18px создают визуальный шум при паттерн-матчинге.
Предложение py-2.5 → py-2 или py-3. gap-2.5 → gap-2 или gap-3. Не критично сразу, но при следующем редизайне компонентов использовать только чётные шаги: 4/8/12/16/20/24/32/40/48/64px.
🌑
Контраст текста — граничные случаи
Accessibility · WCAG AA
WCAG риск
  • text-white/45 на тёмном фоне (hero мета) → ~3.8:1, WCAG требует 4.5:1 для нормального текста
  • text-slate-400 (#94a3b8) на белом → 3.0:1, ниже AA
  • text-orange-300 на тёмном hero → 4.1:1, пограничное
  • Бейдж: bg-emerald-100 + text-emerald-700 → ~4.7:1, OK
Доработка text-white/45 → text-white/55 (уже есть такой вариант на странице — унифицировать). text-slate-400 в информационных подписях → text-slate-500 (#64748b, 4.6:1 на белом).
🖱
Hover-состояния — не везде
Interaction Design · Affordance
Средний
Карточки смен на мобилке не имеют hover. На десктопе часть карточек (ShortShiftCard) без transition на hover. Кнопки dot-навигации в карусели без cursor:pointer. UUPM rule #33: «every clickable element must have visible hover state with 150–200ms transition».
Доработка ShortShiftCard: добавить hover:shadow-md transition-shadow duration-150. Dots в карусели: добавить cursor-pointer hover:bg-[#ec7c00]/60. Dots уже имеют transition-all — нужен только cursor.
🧭
Отсутствие прогресс-индикатора в форме
Forms · UX Feedback
Улучшение
Модалка заявки — одностраничная форма без визуального прогресса. Пользователь не понимает сколько шагов осталось. UUPM guideline #72: «для форм с ≥3 полями показывать completion progress». Сейчас: возраст + телефон + согласие = 3 поля.
Предложение Добавить тонкую прогресс-полосу вверху модалки (0→33→66→100% по мере заполнения). CSS-only через transition на width. Это повышает completion rate форм на 8–12% (Nielsen Norman Group data).
🌊
Scroll-анимации отсутствуют
Motion · Delight · Engagement
Улучшение
Все секции появляются мгновенно при скролле. UUPM style «Warm Soft UI» предполагает subtle fade-in (opacity 0→1 + translateY 20→0) для карточек и секций. Это создаёт ощущение «живого» продукта, особенно важно для эмоциональной аудитории.
Предложение (CSS-only, prefers-reduced-motion safe) 
@media (prefers-reduced-motion: no-preference) {
  [data-fade] {
    opacity: 0; transform: translateY(16px);
    transition: opacity .5s ease, transform .5s ease;
  }
  [data-fade].visible {
    opacity: 1; transform: none;
  }
}
IntersectionObserver добавляет класс .visible. Без JS-библиотек.
🖼
Empty state у фото-галереи
Empty States · UX Polish
Полировка
Если сеть медленная и AVIF не загрузился — пользователь видит пустые серые прямоугольники без skeleton-плейсхолдеров. UUPM guideline #58: «all image containers must have background-color skeleton during load».
Доработка Добавить bg-slate-100 animate-pulse к img-обёрткам в Gallery и ShiftCard до загрузки. Уже используется animate-spin для лоадера — паттерн есть в проекте.
📋
Модалка смены — переименовать таб
Microcopy · Navigation
Полировка
В ShiftModal три таба: «Описание» / «Календарь» / «Подробнее». «Подробнее» и «Описание» пересекаются по смыслу — пользователь не понимает разницу без клика. UUPM microcopy rule: «navigation labels must be self-explanatory».
Доработка «Подробнее» → «Программа» или «Что входит». Это 1 строка кода в ShiftModal.astro.

Что не трогать — уже правильно
🎨
Палитра и бренд
Оранжевый + navy + зелёный — сильная, узнаваемая комбинация. Не менять под «современные тренды» (AI-градиенты, неон, тёмный режим).
💬
Тон коммуникации
«Мама к маме», без педагогики и нотаций. Это продаёт. Не вводить корпоративный tone of voice.
📱
Mobile-first подход
Сайт реально оптимизирован под мобилку (не «адаптивен», а именно mobile-first). Не жертвовать мобильным UX ради десктопной красоты.
⚡
Производительность
96/100 Lighthouse mobile — не добавлять тяжёлые библиотеки анимаций (GSAP, Framer Motion). Только CSS + минимальный JS.
🔤
Inter как основной шрифт
Нейтральный, читаемый, кириллица отличная. Не менять на «более дизайнерский» — потеряем производительность и читаемость.
🏗
Структура секций главной
Hero → Trust → Journey → Shifts → Hackathon → Gallery → Reviews → FAQ → Team → Contacts. Соответствует UUPM pattern «Emotion → Proof → Action». Работает.
